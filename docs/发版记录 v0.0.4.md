## 2. v0.0.4-beta.19（本批重点）

tag `v0.0.4-beta.19` → `dc87cf3`（发版前 main @ dc87cf3，含 bf04ee8 / 608f185 / dc87cf3 三片）。

### 2.1 要解决的问题

WorkBuddy（腾讯 CodeBuddy 内核）等第七类客户端不在六端矩阵里，配置了 MCP 连接器也无法获得「贾维斯」入口规则；若每出现一个客户端就追加专属 adapter，契约会不断膨胀。本批提供通用兜底：**custom 伪客户端**——不走 adapter，用户手动指定任意目录，把入口规则与操作手册写成普通 Markdown 文件，并照常进台账与审计。适配规则由用户/客户端按其约定自行加载（如 Codebuddy 系读 `<workspace>/.codebuddy/rules/*.md`）。

### 2.2 交付范围

- **契约**（`contract/client-entry.ts`）：`CUSTOM_CLIENT_ID = 'custom'`、`CLIENT_ENTRY_CLIENTS` 七值枚举、`CUSTOM_CLIENT_LABEL`；plan/install 新增可选 `target_dir`，superRefine 强约束 custom 必传、六端必须未传（违者进 422 details）。
- **迁移 0026**：`client_entries` 整表重建，仅 client CHECK 由 6 值扩为 7 值加 `'custom'`，其余逐列照 0025；fresh 重放与从 0025 增量升级终值一致性均已演练。
- **installer**：`planInstall` 分流 `planCustomInstall`（不查 adapter 表）；落点固定 `<target_dir>/jarvis-workbench.md`（rule，无 frontmatter 通用 Markdown）与 `<target_dir>/jarvis-workbench/SKILL.md`（skill，共用现模板）；目录不存在自动创建；新增 `resolveInstallRoot`——沿父链找最近存在祖先取 realpath 归一，目标到最近存在祖先这一段出现软链即拒绝。
- **service/REST**：overview 追加第 7 张 custom 合成卡（targets 空、detected 恒 false、entries 只按 client 过滤不按 workspace）；scope 恒 project，台账 workspace_path 记所选目录。
- **web**：设置页「客户端入口」新增兜底卡——目录手输 + 桌面壳目录选择器（浏览器态三结局分别提示）、双资产勾选、复用共享条目行；plan/install 透传 `targetDir`。
- **文档**：`docs/STANDARD.md` §9.7 新增「custom 兜底」小节（四条口径 + WorkBuddy 指引：目录选 `<workspace>/.codebuddy/rules`）；README 功能表更新。

## 3. v0.0.4-beta.18

tag `v0.0.4-beta.18` → `d014767`（72 文件，+8236 / −69），CI run `39817886911`。

### 3.1 要解决的问题

MCP `initialize.instructions` 在协议中是可选字段，客户端不保证注入系统提示；`tools/call` 响应末尾的模式提示只有在调用过工具后才可见；Skills 按需加载，无法承担首次唤醒。因此「配置了 MCP 却无法用『贾维斯』唤起」不是连接故障，而是缺少 always-on 的入口规则。

本批在应用内提供「设置 → 客户端入口」：检测、预览、安装、校验、卸载、自测，覆盖六家客户端。规则是触发器，技能是操作手册，两者不互相替代。

### 3.2 交付范围（M1）

| 能力 | 项目级 | 用户级 |
| --- | --- | --- |
| 入口规则 | Qoder / Cursor / Cline / Windsurf / Claude Code / Codex | Qoder / Cline / Windsurf / Claude Code / Codex |
| 操作技能 | Qoder / Cursor / Claude Code / Codex | Qoder / Claude Code / Codex |

- 设置页新增「客户端入口」Tab（深链 `?tab=client-entry`），六张客户端卡片；稳定/实验徽章按客户端与资产类型标注。
- 落点矩阵与写入方式：独立文件（Qoder/Cursor 规则与技能、Cline 目录规则、Windsurf 项目规则）、托管块（`CLAUDE.md`、`AGENTS.md`、Cline 单文件 `.clinerules`、Windsurf 全局规则）。
- 托管块标记：`<!-- jarvis-workbench:managed:begin/end -->`；块外内容逐字保留，CRLF/BOM 归一。
- 卸载边界：整文件仅在哈希仍等于台账 `file_hash` 且 `created_file=1` 时删除；安装前已存在且内容一致的「接管」文件返回 `kept:'unmanaged'`，只清台账不动文件；托管块内哈希不一致时保留并标 `drifted`。
- 写入安全：同目录临时文件 + fsync + rename；已存在文件先备份（每个 entry 保留最近 5 份）；写前按 `expected_prev_hash` 复核，预览后文件被改返回 `CLIENT_ENTRY_PLAN_STALE`；Windows `EBUSY/EPERM/EACCES` 重试 3 次后返回 `CLIENT_ENTRY_FILE_LOCKED`。
- 路径安全：绝对路径、拒绝 NUL/`..`/ADS/`.git`、目标不得是软链或 junction、最近存在祖先的 realpath 必须落在允许根内；workspace 以 `realpath` 落台账。
- 字符上限：Windsurf 全局规则 6000 字，按**合并后的整份文件**（`limitChars`）判定，超限默认阻止，用户显式勾选豁免后以 `allow_over_limit: true` 写入。
- 自测：MCP 新增 `wake_probe`（无业务副作用、不占任务、不建租约），落 `wake_probes` 表（保留最近 50 条）；设置页自测区展示来源客户端、Token 名与时间，`source` 缺失时显示「收到自检（未标注客户端）」。
- 数据：迁移 `0025_client_entries`（`client_entries` + `wake_probes`，含 CHECK 与 4 个索引）；错误码 `CLIENT_ENTRY_*` 8 枚；审计动作 `client_entry_install` / `client_entry_uninstall`，目标类型 `client_entry`。

### 3.3 评审后收紧的 8 项（含并发收口）

| # | 问题 | 修复 |
| --- | --- | --- |
| 1 | 托管块卸载会删掉用户在块内的修改 | 卸载前比对块正文哈希，不一致保留文件并标 `drifted` |
| 2 | Windsurf 上限只算本应用内容 | 新增 `limitChars`，按合并后整份文件字数判定 |
| 3 | 文件已写但台账/审计失败会留下无主文件 | 台账 upsert + 审计放入同一 Prisma 事务，失败回滚文件 |
| 4 | 整文件卸载误删安装前已存在且内容一致的文件 | `created_file=0` 返回 `removed:true, kept:'unmanaged'`，不 unlink |
| 5 | workspace 用 `path.resolve` 导致软链重复台账 | 改 `realpathSync` |
| 6 | 预览后文件被改仍按旧计划写入 | `assertExpectedState` 在锁内、备份/写盘前复核 |
| 7 | `pick_folder` 把「无桌面壳」和「命令报错」吞成同一结果 | 改用 `tryInvoke`，三种结局分别提示 |
| 8 | 同一目标并发安装产生重复台账行 | repository upsert 改按 `client_scope_assetType_assetName_targetPath` 复合唯一键；审计 `targetId` 用 upsert 返回的实际 id |

## 6. 已知限制（不得写进对外承诺）

1. **六端真机未验**：`docs/v0.0.4/beta真机验证清单.md` §15 的六端 checkbox 仍全为 `[ ]`；当前只证明「文件已安装、工具链路可验证」，不证明某客户端一定会注入规则。
2. **Cursor 用户级规则**：无稳定文件落点，本批只提供复制，写入兜底排在 M2；UI 标「实验」。
3. **Cline / Windsurf 无技能**：`assets` 不含 `skill`，UI 不渲染技能行。
4. **模板升级**：校验会返回 `update_available`，但不会自动改写文件；「重新渲染」交互随 M2。
5. **Windows 路径/junction/锁文件矩阵**：仅有单元测试与 CI 门禁，真机安装与首启仍未验证（M3）。
6. **MCP 配置**：本批不改写各客户端 MCP 配置文件，连接片段仍由「设置 → 令牌」复制。
7. **custom 兜底未真机验证**：第七类客户端（如 WorkBuddy/Codebuddy 系）的兜底卡安装、目录选择器与「客户端按 `.codebuddy/rules` 约定加载规则」均未真机走查；兜底只保证文件按计划落盘并进台账，不保证任意客户端一定注入规则。
