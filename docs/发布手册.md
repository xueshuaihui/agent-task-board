# 发布手册（Release SOP）

> 从源码到 GitHub Release 的完整发布流程。每条命令均在 v0.0.1（2026-09-16）发布中实跑验证。
> 配套文档：构建细节见 `README.MD`（路径 A/B/C）；签名口径见 `docs/系统操作使用手册.md` 2.4；
> 产物校验和与修订史见 `docs/发版记录 v0.1.0.md`。

---

## 0. 版本与通道约定

| 通道 | 何时用 | 产物 |
| --- | --- | --- |
| **prerelease（如 v0.0.1）** | 里程碑间需要对外分发可用包时 | GitHub Release + .dmg 附件 |
| **正式版（v0.1.0 起）** | 验收门禁全过后 | GitHub Release + 发版记录文档 + 勾掉 M4 checklist |

- 版本号来源：`apps/desktop/src-tauri/tauri.conf.json` 的 `version`（当前 `0.1.0`）。
  **注意**：prerelease 阶段打 tag（如 v0.0.1）不必改它——tag 是发布批次标识，包内版本跟随 tauri.conf.json。
- tag 一律用 annotated：`git tag -a vX.Y.Z -m "说明"`，说明里写清发布口径与已知限制。
- `v0.1.0` 正式 tag 的门禁：A3 真机验收 7 项 + 四家客户端接入自测全过（见发版记录第 5 节 checklist）。

## 1. 前置条件

| 项 | 要求 | 缺失时 |
| --- | --- | --- |
| Node ≥ 20 / npm | 版本检查 | 安装 |
| Rust 工具链 | `export PATH="$HOME/.cargo/bin:$PATH"` | rustup 安装 |
| node 二进制（目标架构） | `apps/desktop/src-tauri/resources/sidecar/node` | 按 README 路径 C 第 0 步拷入（不入库，每次换机器必做） |
| GitHub 凭据 | `GH_TOKEN` 环境变量 | 见第 5.1 节 token 注意事项 |
| gh CLI | `~/.local/bin/gh`（本机无 brew，用独立二进制） | 见 5.1 安装命令 |

**gh CLI 安装（本机专用，已装可跳过）**：

```bash
mkdir -p ~/.local/bin && cd /tmp
curl -sL -o gh.zip https://github.com/cli/cli/releases/download/v2.62.0/gh_2.62.0_macOS_amd64.zip
unzip -oq gh.zip -d /tmp/gh-extract
cp /tmp/gh-extract/gh_2.62.0_macOS_amd64/bin/gh ~/.local/bin/gh
```

> GitHub 下载在本机网络下较慢（约 10 分钟），建议提前备好；也可以只装一次长期复用。

## 2. 构建产物

完整步骤见 README「路径 C」，速记版：

```bash
npm install                              # 仅首次
npm run build                            # api（tsc）+ web（vite）
npm run build:sidecar -w @atb/api        # 装配 sidecar 打包资源（~135M，不入库）
cd apps/desktop/src-tauri
export PATH="$HOME/.cargo/bin:$PATH"
npx tauri build                          # .app 产出在 target/release/bundle/macos/
cd target/release/bundle
hdiutil create -volname "Agent Task Board" \
  -srcfolder "macos/Agent Task Board.app" -ov -format UDZO \
  "dmg/Agent Task Board_<版本>_x64.dmg"  # DMG 兜底（bundle_dmg.sh 无头必失败）
```

## 3. 发布前验证（不许跳过）

### 3.1 质量门禁

```bash
npm run typecheck && npm run test
```

### 3.2 产物冒烟（模拟 .app 内真实启动）

```bash
APP="apps/desktop/src-tauri/target/release/bundle/macos/Agent Task Board.app"
TMPD=$(mktemp -d)
(ATB_DATA_DIR="$TMPD" ATB_PORT=17994 ATB_UI_TOKEN=abc123def456abc123def456abc123de \
  "$APP/Contents/Resources/sidecar/node" "$APP/Contents/Resources/sidecar/main.js" > /tmp/atb-smoke.log 2>&1 &)
for i in $(seq 1 60); do grep -q ATB_READY /tmp/atb-smoke.log 2>/dev/null && break; sleep 0.5; done
grep ATB_READY /tmp/atb-smoke.log        # 期望：ATB_READY {"port":17994,...,"version":"0.1.0"}
curl -s --noproxy '*' -o /dev/null -w "tasks: HTTP %{http_code}\n" http://127.0.0.1:17994/api/v1/tasks
# 期望：401（鉴权守卫正常）。结束后清理：
pkill -f "Resources/sidecar/main.js"; rm -rf "$TMPD"
```

> 两个历史缺陷都靠这一步抓出来（缺依赖启动失败、既有库水位撞表），冒烟不过不发版。

### 3.3 校验和

```bash
cd apps/desktop/src-tauri/target/release/bundle
shasum -a 256 dmg/*.dmg | tee /tmp/SHA256SUMS.txt
```

> 用 node 校验 bundle 内修复是否在位时，不要用 BSD `grep "a\|b"`（不支持 `\|` 交替，恒 0 误报），
> 用 `node -e "fs.readFileSync(...).includes('...')"`。

## 4. 发布步骤

### 4.1 提交与打 tag

```bash
git add <本次发布包含的变更>
git commit -m "..."
git push origin main
git tag -a vX.Y.Z -m "vX.Y.Z <通道>：<一句话定位>

- 主要变更点
- 已知限制" 
git push origin vX.Y.Z
```

### 4.2 创建 GitHub Release

Release notes 先写到本地文件（含安装指引、变更清单、已知限制三段），然后：

```bash
export GH_TOKEN=<你的 token>
~/.local/bin/gh release create vX.Y.Z \
  --title "vX.Y.Z <通道>：<一句话定位>" \
  --notes-file /tmp/release-notes-vX.Y.Z.md \
  --prerelease        # 正式版去掉此参数
```

### 4.3 上传构建产物

```bash
~/.local/bin/gh release upload vX.Y.Z \
  "apps/desktop/src-tauri/target/release/bundle/dmg/Agent Task Board_<版本>_x64.dmg" \
  /tmp/SHA256SUMS.txt --clobber
```

> 88M .dmg 约 30–60 秒传完。上传后 GitHub 会把文件名空格替换为点号（`Agent.Task.Board_…dmg`），属正常行为。

### 4.4 核验

```bash
~/.local/bin/gh release view vX.Y.Z --json name,tagName,isPrerelease,assets \
  --jq '.name + " | " + .tagName + " | prerelease=" + (.isPrerelease|tostring) + " | assets: " + ([.assets[].name]|join(", "))'
```

### 4.5 回填发版记录

- `docs/发版记录 v0.1.0.md` 产物表更新为**最终构建**的大小与 SHA-256，修订记录加一条；
- `docs/开发计划-*.md` 快照同步；
- 提交并推送。

## 5. 坑与注意事项（v0.0.1 实录）

### 5.1 GitHub Token（Fine-grained）

- 本机 SSH key 只能推代码，**创建 Release 必须用 token 调 API**（`GH_TOKEN` 环境变量注入，不落盘）。
- **Fine-grained token 必须显式授权目标仓库**：Repository access 未包含 `agent-task-board` 时，
  API 一律 404（不是 403，别被误导）；Permissions 需 **Contents: Read and write**。
- 编辑授权后立即生效，无需重新生成。
- **用完撤销**：token 一旦出现在对话/终端历史中，发布完应立即 regenerate/revoke。

### 5.2 构建侧

- `resources/sidecar/` 不入库：换机器/换架构打包前必须重新准备 node 二进制（历史缺陷 #1 根因相关）。
- 无头会话下 `tauri build` 的 DMG 步骤必失败（osascript），用 `hdiutil` 兜底即可，不影响 .app。
- 既有开发库与打包 app 共用 `~/.agent-board/`，发版前用 3.2 冒烟（临时目录）+ 真机双击各验一次。

### 5.3 流程侧

- 产物在发布前可能被重建（如 v0.0.1 的 .dmg 与上一轮记录的 sha 不同）——**以发布时实跑 `shasum` 为准**回填发版记录，不沿用旧值。
