# 一、产品定位

## 1.1 一句话定位

**Jarvis Workbench 是一个云端账号必须、任务本地存储的桌面应用。admin 创建账号，用户多账号切换，任务和技能按账号隔离且不上云。技能从云端市场订阅或本地创作，绑定任务驱动 Agent 执行。支持多项目、多需求同时管理。**

## 1.3 核心决策

| 决策 | 结论 |
|---|---|
| 产品形态 | 桌面应用（Tauri）+ 云端服务 |
| 账号 | 必须，admin 创建制 |
| 多账号 | 支持，任务按账号隔离 |
| 任务存储 | 本地，不上云 |
| 技能存储 | 云端市场 + 本地创作 + 本地缓存 |
| 组织 | 本期不做 |
| 自托管 | 不做 |
| 离线 | 30 天可用，超时只读 |
| Agent 管理 | 不管理，只提供 MCP 接入 |
| MCP 安装 | 用户自行安装配置 |
| 审核 | 仅人工审核 |
| 项目 | 支持多项目 |
| 看板分组 | 支持多维度分组 |

## 1.4 目标

1. **项目管理**：多项目并行，项目隔离与切换。
2. **需求管理**：需求作为父任务，追踪子任务进度。
3. **任务管理**：可视化看板、依赖、审核、归档。
4. **看板分组**：多维度分组，同时开启多个需求和项目。
5. **技能管理**：创建、编辑、测试、版本、绑定、下发。
6. **云端市场**：技能发现、订阅、发布、评分、反馈。
7. **Agent 接入**：通过 MCP HTTP / REST API，零 Agent 管理。
8. **多账号**：账号切换，任务隔离。
9. **MCP 治理**：声明、审核、策略、审计全链路。
10. **离线可用**：30 天离线，超时只读。

## 1.5 非目标

1. 不做开放注册（admin 创建）。
2. 不做组织（本期）。
3. 不做任务上云。
4. 不做换设备迁移。
5. 不做数据加密（本期）。
6. 不做邮箱找回密码。
7. 不做第三方登录。
8. 不做自托管云端。
9. 不做 Agent 生命周期管理。
10. 不做 MCP 代安装。
11. 不做平台侧并发限制。
12. 不做桌面通知。
13. 不做多语言界面。
14. 不做项目级权限（本期个人使用）。

# 二、核心概念

| 概念 | 说明 |
|---|---|
| **Project** | 项目，任务的顶层容器 |
| **Task** | 统一工作项，直接可执行 |
| **Requirement** | 需求，type=requirement 的任务，作为父任务 |
| **Subtask** | 子任务，parent_id 指向父任务 |
| **Run** | 任务的一次执行尝试 |
| **Lease** | 任务租约，防止重复执行 |
| **Artifact** | Agent 产物 |
| **Review** | 人工审核记录 |
| **Dependency** | 任务依赖（blocks / relates） |
| **Grouping** | 看板分组，多维度聚合视图 |
| **Skill** | 可复用、可版本化的能力单元 |
| **Skill Version** | 技能的语义化版本 |
| **Skill Source** | 技能来源 |
| **MCP Dependency** | 技能声明的第三方 MCP 依赖 |
| **MCP Policy** | 随技能下发的 MCP 调用策略 |
| **Account** | 云端账号，任务隔离的依据 |
| **Workspace** | 账号对应的本地工作区 |

## 2.1 任务模型

任务支持多层级：

```text
Project（项目）
  └── Requirement（需求，type=requirement）
        ├── Subtask（子任务）
        ├── Subtask（子任务）
        └── Subtask（依赖其他子任务）
```

| 层级 | 类型 | 说明 |
|---|---|---|
| 项目 | Project | 顶层容器 |
| 需求 | type=requirement | 父任务，聚合子任务 |
| 子任务 | type=task | 可执行任务 |

**约束：**

- 子任务嵌套最多 2 层
- 父任务不直接执行，只作聚合视图
- 父任务进度 = 已完成子任务 / 总子任务

## 2.2 技能的本质

技能是**抽象的能力封装**，可以表现为：

- 单条提示词
- 步骤列表
- 流程图
- 脚本
- 知识包
- 工具编排
- 决策树
- 组合技能
- 多阶段工作流
- 以上任意组合

## 2.3 技能与相关概念

| 概念 | 回答的问题 | 处理方式 |
|---|---|---|
| **Skill** | 怎么做 | 核心抽象 |
| **Rules** | 不能怎么做 | 技能内部的约束段落 |
| **Workflows** | 按什么顺序做 | 技能的一种表达形式 |
| **Prompt Templates** | 怎么问 | 技能的一种表达形式 |
| **MCP** | 怎么连 | 技能声明的外部依赖 |

## 3.2 角色与权限

| 角色 | 能力 |
|---|---|

```text

    ↓

    ↓
```

# 五、项目与任务模型

## 5.1 项目

**项目是任务的顶层容器，用于隔离不同项目的工作。**

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| name | 项目名 |
| description | 描述 |
| color | 标识颜色 |
| icon | 图标 |
| status | 活跃 / 归档 |
| sort_order | 排序 |
| created_at | 创建时间 |

**项目管理：**

- 创建、编辑、归档、删除
- 归档的项目不出现在默认视图
- 删除项目需处理其下任务（迁移或一并删除）

## 5.2 需求

**需求是 `type=requirement` 的任务，作为父任务，聚合子任务。**

| 字段 | 说明 |
|---|---|
| 与普通任务相同 | 标题、描述、优先级、标签等 |
| type | requirement |
| 子任务 | parent_id 指向此需求 |

**需求的能力：**

- 不直接执行
- 不参与 Agent 领取
- 进度由子任务聚合
- 状态由子任务聚合
- 可绑定技能（下发给子任务参考）

## 5.3 子任务

**子任务是可执行的普通任务。**

| 字段 | 说明 |
|---|---|
| parent_id | 指向父任务（需求） |
| 与普通任务相同 | 所有任务字段 |

**子任务的能力：**

- 可被 Agent 领取
- 独立执行、独立审核
- 独立依赖关系

## 5.4 父子关系规则

| 规则 | 说明 |
|---|---|
| 嵌套深度 | 最多 2 层 |
| 环检测 | 禁止形成环 |
| 删除保护 | 有子任务的父任务不能直接删除 |
| 进度聚合 | 父任务进度 = 已完成子任务 / 总数 |
| 状态聚合 | 父任务状态由子任务聚合（见下表） |

**状态聚合规则：**

| 子任务状态 | 父任务状态 |
|---|---|
| 全部 DONE | DONE |
| 全部 BACKLOG | BACKLOG |
| 有 RUNNING | RUNNING |
| 有 REVIEW | REVIEW |
| 有 FAILED | FAILED |
| 混合 | 显示各状态计数 |

## 5.5 任务字段

| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 描述 | Markdown |
| 类型 | 需求/缺陷/子任务/巡检/重构/测试/文档/自定义 |
| 优先级 | P0-P3 |
| 标签 | 多标签 |
| 所需能力 | 供 Agent 筛选 |
| 自定义字段 | 用户定义 |
| 依赖 | blocks / relates |
| 绑定技能 | 0 到多个 |
| 截止时间 | 可选 |
| 置顶 | 支持 |
| **project_id** | **所属项目** |
| **parent_id** | **父任务（需求）** |

# 六、任务管理

## 6.1 状态机

```text
需求池 → 待执行 → 执行中 → 待审核 → 已完成
                              ↘ 异常/失败
```

| 列 | 说明 |
|---|---|
| 需求池 | 新建任务、驳回回退的任务 |
| 待执行 | 可被 Agent 领取（含被阻塞任务） |
| 执行中 | Agent 已认领，正在执行 |
| 待审核 | Agent 执行完，等待人工审核 |
| 已完成 | 审核通过 |
| 异常/失败 | Agent 上报失败，或租约超时 |

**流转：**

```text
需求池 ──► 待执行 ──► 执行中 ──► 待审核 ──► 已完成
  ▲          ▲                      │
  │          │                      │ 驳回
  └──────────┴──────────────────────┘

执行中 ──► 异常/失败 ──► 需求池 / 待执行
```

## 6.2 任务依赖

| 类型 | 语义 | 对抓取的影响 |
|---|---|---|
| blocks | 硬性前置 | Agent 不能领取 |
| relates | 仅标记 | 不影响抓取 |

**抓取顺序：** 置顶 > 优先级 > 创建时间

**循环依赖：** 添加时检测并拒绝。

**依赖图：** DAG 视图，支持缩放、拖拽、点击打开详情。

## 6.3 任务领取与并发

- Agent 通过 MCP HTTP / REST API 领取。
- 原子认领 + 租约，防止重复。
- 不做平台侧并发限制。
- 同一任务在任一时刻只能被一个 Run 持有。
- 不同任务可并行执行。

## 6.4 审核

**仅人工审核，无自动审核。**

审核必填：

| 字段 | 说明 |
|---|---|
| 审核结论 | 通过 / 驳回 |
| 审核建议 | 对该次执行的评价 |
| 原因 | 为什么通过或驳回 |
| 详情 | 具体要求、修改点 |

驳回时选择：

| 字段 | 说明 |
|---|---|
| 退回目标 | 待执行（默认）/ 需求池 |
| 优先级调整 | 可选 |

## 6.5 任务模板

预填：标题前缀、描述、类型、优先级、标签、所需能力、自定义字段、技能、项目。

## 6.6 导入导出

- 格式：JSON / CSV
- 范围：全部 / 当前筛选 / 选中 / 当前分组
- 导入策略：新增 / 覆盖
- 依赖处理：缺失时跳过并提示
- 项目处理：可映射到现有项目

## 6.7 归档

- 手动归档
- 自动归档：已完成超 N 天（可配置）
- 归档任务可在「已归档」中查看、恢复

## 6.8 自定义字段

| 属性 | 说明 |
|---|---|
| 字段名 | 显示名称 |
| 字段 key | 内部标识 |
| 类型 | 文本/多行文本/数字/单选/多选/日期/布尔/链接 |
| 是否必填 | |
| 适用任务类型 | |
| 排序、启用 | |

## 6.9 产物预览

支持：diff、图片、文本、Markdown、JSON、HTML、PDF。

单文件默认上限 10 MB。

## 6.10 审计

记录：任务创建、状态变更、认领、回写、审核、Token 使用、字段定义变更、模板变更、依赖变更、项目变更、分组变更、导入导出、备份、归档。

# 七、看板分组

## 7.1 分组能力概述

看板支持多维度分组，支持同时开启多个需求和项目。

## 7.2 分组维度

| 维度 | 说明 | 典型场景 |
|---|---|---|
| **项目** | 按项目分组 | 同时管理多个项目 |
| **需求** | 按父任务分组 | 追踪多个需求的子任务 |
| **类型** | 按任务类型分组 | 缺陷、需求、巡检分开 |
| **优先级** | 按优先级分组 | 聚焦 P0/P1 |
| **Agent** | 按执行 Agent 分组 | 查看各 Agent 负载 |
| **标签** | 按标签分组 | 按模块/技术栈 |

## 7.3 分组形态

| 形态 | 说明 |
|---|---|
| **泳道** | 横向分组，每个分组一行，横向可滚动 |
| **主分组 + 次分组** | 两级分组，支持嵌套 |
| **列表视图分组** | 列表视图也支持分组 |

# 八、技能管理

## 8.1 技能模型

遵循 Agent Skills 开放标准，以 `SKILL.md` 为核心。

**SKILL.md 格式：**

```markdown
---
name: code-review
display_name: 代码审查
description: 对代码 diff 做风格、安全、逻辑三层审查
version: 1.2.0
category: 质量保障
tags: [review, quality]
compatible_clients: [qoder, claude-code, codex]
inputs:
  - name: diff
    type: text
    required: true
outputs:
  - name: report
    type: markdown
permissions:
  - file:read
mcp_dependencies:
  - name: github
    server_url: "https://api.githubcopilot.com/mcp/"
    transport: http
    required: true
    tools: [get_pull_request]
    auth_type: oauth2
---

# 代码审查

## 步骤

### 1. 代码风格检查
检查 `{{diff}}` 是否符合项目代码风格规范。

### 2. 安全检查
检查 `{{diff}}` 是否存在安全隐患。

### 3. 逻辑审查
检查 `{{diff}}` 的逻辑正确性。

### 4. 生成报告
汇总以上结果，生成审查报告。
```

# 十一、Agent 接入

## 11.1 接入方式

**仅 MCP HTTP / SSE，不用 stdio。**

- 服务常驻，MCP 端点监听 `127.0.0.1:7788/mcp`
- Agent 客户端配置 MCP URL + Token
- 服务独立于 Agent 运行

## 11.2 接入步骤

1. 用户在设置页生成 Agent Token
2. Agent 客户端配置 MCP URL 和 Token
3. Agent 客户端自身配置定时任务，调用 `claim_next_task`
4. 执行中定期 `heartbeat`
5. 完成后 `complete_task`
6. 下次领取时，通过 `get_task` 读取审核意见、技能、自定义字段

## 11.3 并行执行

并行执行由 Agent 客户端自行管理：

- 对每个任务独立维护 `task_id`、`run_id`、`lease_id`
- 对每个 Run 分别 `heartbeat`、`update_progress`、`append_log`
- 对每个 Run 分别 `complete_task` 或 `fail_task`

## 11.4 首批接入

| Agent | 接入方式 |
|---|---|
| Qoder | MCP HTTP + REST |
| Claude Code | MCP HTTP + REST |
| Codex | MCP HTTP + REST |

# 十二、MCP 依赖治理

## 12.1 核心原则

**第三方 MCP 由用户/Agent 客户端自己安装和配置，平台不负责安装。**

| 环节 | 谁负责 |
|---|---|
| 声明 MCP 依赖 | 技能作者 |
| 审核依赖 | 平台 |
| 下发策略 | 平台随技能下发 |
| 安装 MCP | 用户 |
| 配置 MCP | 用户 |
| 认证授权 | 用户 |
| 调用 MCP | Agent 客户端 |
| 记录审计 | 平台接收回传 |

## 12.2 依赖声明

```yaml
mcp_dependencies:
  - name: github
    server_url: "https://api.githubcopilot.com/mcp/"
    transport: http
    required: true
    tools: [get_pull_request, create_review]
    scopes: [repo:read]
    auth_type: oauth2
```

**约束：**

- `tools` 必须精确到工具级
- 一个技能最多声明 8 个 MCP 依赖

## 12.3 四层准入

| 层级 | 检查 |
|---|---|
| 第一层 | 格式与完整性校验 |
| 第二层 | 服务器信誉查询 |
| 第三层 | 工具级安全扫描 |
| 第四层 | 供应链合规评估 |

## 12.4 策略下发

```json
{
  "mcp_policy": {
    "allowed_servers": [
      {
        "name": "github",
        "allowed_tools": ["get_pull_request"],
        "require_auth": true,
        "max_calls_per_run": 20
      }
    ],
    "deny_undeclared": true,
    "deny_transitive": true
  }
}
```

## 12.5 依赖缺失处理

| `required` | 行为 |
|---|---|
| true | 技能中止，任务 `BLOCKED` |
| false | 跳过依赖步骤，产物中标注 |

## 12.6 审计

所有 MCP 调用记录：技能 ID、任务 ID、Run ID、MCP 服务器、工具、结果、策略决策。

审计保留 180 天。

## 12.7 配置引导

- 技能详情页展示 MCP 依赖
- 生成配置片段（按 Agent 客户端类型）
- 配置状态检测（可选）
- 任务执行前依赖检查

## 16.3 关键设计

**任务认领并发控制（SQLite）：**

```sql
BEGIN IMMEDIATE;
UPDATE tasks
SET status = 'RUNNING',
    lease_id = ?,
    lease_expires_at = datetime('now', '+30 minutes'),
    current_run_id = ?
WHERE id = (
  SELECT id FROM tasks
  WHERE status = 'READY'
    AND type != 'requirement'
    AND (lease_expires_at IS NULL OR lease_expires_at < datetime('now'))
    AND NOT EXISTS (
      SELECT 1 FROM task_dependencies d
      JOIN tasks dep ON dep.id = d.depends_on
      WHERE d.task_id = tasks.id
        AND d.type = 'blocks'
        AND dep.status != 'DONE'
    )
  ORDER BY pinned DESC, priority ASC, created_at ASC
  LIMIT 1
)
RETURNING *;
COMMIT;
```

**账号切换：** 切换数据库文件路径，重新初始化 Prisma 客户端。

**分组查询：** 按分组维度聚合，返回泳道数据。

**离线检测：** 定时 ping 云端，记录最后在线时间，超过 30 天转只读。

# 十九、非功能需求

1. 服务常驻：独立于浏览器和 Agent 运行。
2. 固定端口：默认 7788，可配置。
3. 端口占用：启动时检测并提示。
4. 桌面应用：托盘图标、右键菜单。
5. 数据：SQLite 按账号分文件。
6. 实时：状态变更 1 秒内推送。
7. 并发：个人场景，支持数个 Agent 并行领取。
8. 离线：30 天可用，超时只读。
9. 可移植：Windows / macOS / Linux。
10. MCP 模式：仅 HTTP/SSE。
11. 多项目：支持。
12. 看板分组：支持多维度、两级分组。
13. 自定义字段、产物预览、日志保留、备份、依赖、依赖图、模板、导入导出、归档、置顶。
14. 技能编辑器：三种模式。
15. 技能源：内置、目录、Git、HTTP、云端。
16. MCP 治理：声明、审核、策略、审计。
17. 多账号：切换、隔离。
18. 桌面通知：不做。
19. 多语言：仅中文。

# 二十一、验收标准

## 21.1 账号

1. 首次部署初始化 admin 账号
2. admin 可创建用户
3. 用户首次登录强制改密码
4. 用户可修改自己密码
5. admin 可重置用户密码
6. admin 可禁用用户
7. 支持多账号切换
8. 切换账号时任务隔离
9. Token 共享有效期
10. 离线 30 天内可用
11. 离线超 30 天转只读

## 21.2 项目

12. 可创建、编辑、归档、删除项目
13. 项目可设置颜色、图标
14. 归档项目不出现在默认视图
15. 删除项目时可选择迁移或删除任务

## 21.3 需求与子任务

16. 可创建需求（type=requirement）
17. 需求可作为父任务，挂载子任务
18. 需求不参与 Agent 领取
19. 需求进度由子任务聚合
20. 需求状态由子任务聚合
21. 父子嵌套最多 2 层
22. 有子任务的父任务不能直接删除

## 21.4 看板分组

23. 支持按项目、需求、类型、优先级、Agent、标签分组
24. 支持主分组 + 次分组
25. 分组可折叠、展开、全部折叠、全部展开
26. 泳道头显示分组名、任务数、待审核数
27. 需求泳道头显示项目、优先级、进度
28. 支持拖拽卡片跨分组
29. 支持拖拽泳道头调整分组顺序
30. 支持筛选指定分组
31. 支持多项目同时开启
32. 项目切换器支持多选
33. 列表视图也支持分组
34. 分组设置持久化到用户偏好
35. 跨分组拖拽时弹出确认对话框

## 21.5 任务管理

36. 双击桌面应用，服务启动，托盘图标出现
37. 登录后可创建、拖拽、配置任务
38. 生成 Agent Token，Agent 配置 MCP URL 后领取任务
39. 任务自动进入「执行中」，看板实时更新
40. Agent 完成后，任务进入「待审核」
41. 用户审核，必填建议、原因、详情
42. 通过 → 已完成；驳回 → 按选择回到待执行（默认）或需求池
43. Agent 下次领取该任务时，能读到审核意见
44. 两个 Agent 同时领取，只有一个成功
45. 同一 Agent 连续领取两次，可领到两个不同任务
46. 租约超时后任务回到异常/失败
47. 重启服务后，端口不变

## 21.6 依赖

48. A 依赖 B（阻塞），B 未完成时，Agent 不会领到 A
49. B 完成后，A 可被领取
50. 多前置任务全部完成后，后续任务可领取
51. 添加形成环的依赖被拒绝
52. 置顶任务优先于优先级排序
53. 依赖图可打开，节点与连线正确

## 21.7 技能

54. 用户可创建技能，使用三种编辑模式
55. 可视化编辑器支持块编辑和流程图两种视图
56. 技能可保存，可绑定任务
57. 技能随任务下发给 Agent
58. 技能版本可管理，支持回滚
59. 技能可导入导出 `.atskill`
60. 技能测试可运行，结果可查看
61. 技能含人工块时，任务进入 `BLOCKED`，用户处理后恢复

## 21.8 云端市场

62. 可浏览、搜索、分类筛选云端技能
63. 可订阅技能，同步到本地
64. 可发布本地技能到云端
65. 公开技能需审核
66. 私有技能不上云
67. 可评分、评论、收藏
68. 可举报可疑技能
69. 技能被下线后，已订阅用户保留快照

## 21.9 MCP 治理

70. 技能可声明 MCP 依赖
71. MCP 依赖四层准入检查可用
72. MCP 策略随技能下发
73. Agent 调用 MCP 前可校验策略
74. MCP 调用审计可查
75. MCP 依赖缺失时按 `required` 处理
76. 技能详情页展示 MCP 依赖和配置片段

## 21.10 其他

77. 自定义字段可配置
78. 产物预览支持 diff、图片、文本等
79. 日志保留策略可配置
80. 数据库备份可手动和自动
