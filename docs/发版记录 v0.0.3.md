## 3. 本期明确未做（不得写进对外承诺）

1. **MCP 依赖治理整章（PRD §12）除「声明与展示」外未实现**：无四层准入（12.3）、无策略结构与下发通道（12.4）、无执行期依赖判定（12.5）、无 MCP 调用审计与 180 天保留（12.6）。`mcp_dependencies` 只有 `server/tools/required/reason` 四个字段（缺 `server_url/transport/scopes/auth_type`，条数上限 20 而非 PRD 的 8），且只是存储与展示字段，运行时零判断。
2. **离线模式（§13）**：任务/技能/看板天然本地可用，但无联网探测、无超期只读闸门、无离线态标记与降级 UI；服务端市场在离线时直接抛 `CLOUD_ERROR`。
3. **技能推荐（10.2）**：无算法，仅手动绑定。
4. **公网服务端的审核环节（9.3）**：`apps/cloud` 无审核，需与 PRD 对齐或修订 PRD 口径。
5. **账号体系两套并存**：`apps/api` 的 `Account`（ADMIN/MEMBER、禁用、强制改密、用户管理）与 `apps/cloud` 的 `CloudAccount`（仅 register/login/me，开放注册）是**两套独立 schema、独立密钥（`ATB_JWT_SECRET` vs `CLOUD_JWT_SECRET`）、独立 token（30 天 vs 7 天）**，唯一连接点是本地端用云端用户名密码换 token（`market/cloud/cloud.client.ts:86`）。这不是「统一账号体系」。
6. 前端交互（尤其 21.4 看板分组）**无自动化测试**：`apps/web` 没有单测文件，本期靠浏览器实测回归覆盖。
7. 零碎缺口：6.6 CSV 导出与「当前分组」作用域、6.9 md/json/html/PDF 预览、8.5 版本 diff、8.3 AI 辅助、8.8 git/http 技能源、3.6 token 自动续期与密钥链存储。

## 7. 服务端部署：下一步该做什么（本期暂停处）

1. 本地：`npm run bundle:cloud`（默认 `linux/amd64`，ARM 用 `PLATFORM=linux/arm64`）→ 产物 `dist/agent-task-board-cloud-prod.tar.gz`（约 250MB）。
2. 上传：`scp` 到服务器 `/opt/agent-task-board-cloud/`（包名固定，直接覆盖旧包）。
3. 首次部署：`cd /opt/agent-task-board-cloud && ./deploy.sh`。目标机 80/443 已被 1Panel 的 OpenResty 占用时，脚本会探到并问一句「改用 `EDGE_MODE=off`？」——答 Y（默认）即跳过域名/邮箱，起服后由面板 OpenResty 把站点反代到 `http://127.0.0.1:7789`，证书由该边缘签发。**前置条件：需要一个 A 记录指向该机的子域名**（当前 `market/cloud/atb.xuesh.cn` 均无解析记录）。
4. 之后每次发版：上传新包 → `./deploy.sh update`（无交互，自动留 `:prev` 与升级前备份）。
5. 验收：按 `apps/cloud/README.md` §9 清单逐条过（含 `backup` → `restore` 演练一次，以及桌面端 `ATB_CLOUD_URL` 走完「注册 → 发布 → 另一账号订阅 → 评分/评论」）。
