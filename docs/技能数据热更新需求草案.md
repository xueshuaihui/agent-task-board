# 技能数据热更新 需求草案（2026-09-25 讨论稿）

> 状态：方向已拍板，细节待补。本文档只做需求与决策记录，不是实施方案。

## 1. 背景与问题

- 125 条内置技能随安装包发布：数据经 `scripts/gen-builtin-seeds.mjs` 编译进 sidecar
  （`apps/api/src/skills/builtin-skills.data.*.ts` 分片，全量约 1.4MB）。
- 痛点：每收一批技能（如 0925 批 31 条）就要出一整包 dmg + 走一次真机验证清单，发布节奏被数据更新绑架。
- 机制层已具备热更落库能力：`ensureDefaultSkills`（default-skills.ts）每次启动按 id 幂等 upsert，
  只读守卫/source=default 口径/builtin 版本号都不需动。本需求核心 = **种子数据与代码解耦 + 远端拉取通道**。

## 2. 五项拍板（2026-09-25，用户选定）

| # | 分叉 | 裁定 |
|---|------|------|
| D1 | 更新源 | **GitHub Release 附件 + jsDelivr 镜像加速**。manifest 与签名包作为 Release 附件发布（发布脚本加一步上传）；客户端经镜像拉取，零新增基建。 |
| D2 | 拉取时机 | **启动后台异步拉一次（不阻塞首屏）+ 技能库页「检查更新」手动按钮**（显示结果）。无常驻轮询。 |
| D3 | 下架语义 | **全量对齐：manifest 声明全集 id 清单，库内 source=default 且清单外的行删除**。用户自建/导入的技能不动。补掉现管线「只增不删」的残留问题。 |
| D4 | 完整性 | **minisign 内容签名**。发布端私钥签更新包（私钥进 CI secret），验签公钥编进 sidecar，验签失败拒装。理由：技能内容以 prompt 进 Agent 执行，通道/镜像换包 = 远程 prompt 注入面，仅 HTTPS+SHA256（同源可合谋伪造）不够。 |
| D5 | dmg 整包更新 | **本期只做轻档：检查+提示**。启动查一次 GitHub Releases latest tag，比 `tauri.conf.json` 的 `version` 新则在设置页/托盘提示「发现新版本」，点击打开 Release 页，下载安装仍走手动流程（发布手册现行路径）。**应用内自动替换（tauri-plugin-updater）挂起**，待 Apple Developer 签名/公证有定论再议。理由：整包替换有三道坎——①GitHub 直连 60MB 慢道；②ad-hoc 签名下 updater 替换 .app 后的 Gatekeeper/quarantine 行为未验证；③beta 期 identifier 变更导致新旧包互认失败，需公告过渡。轻档一条不踩。 |

## 3. 方案骨架（按 D1–D4 展开）

1. 生成器新增产出 `skills-update.json`（全集种子数组，内容与 `DEFAULT_SKILL_SEEDS` 同源）+ manifest
   （`{ skills_data_version, files: [{name, sha256}], generated_at }`）+ minisign 签名文件。
2. 发布流：`release.sh` / CI 在出 Release 时附带上传上述三件（属文档「发版脚本保持最薄」边界内的显式扩展，需在发布手册写明命令）。
3. 客户端（sidecar）：
   - 拉取：manifest → 比对本地已装 `skills_data_version` → 拉包 → 验签 → SHA256 对账 → 落
     `ATB_DATA_DIR` 下本地缓存文件。
   - 装载：`ensureDefaultSkills` 数据源改为「本地已验签缓存优先，缺缓存退回编译进 sidecar 的随包分片」。
   - 对齐：按 D3 删除清单外的 default 行，删除记日志（列出被删 id）。
4. UI（web）：技能库页「检查更新」按钮 + 结果提示（成功 N 新增 / M 更新 / K 下架；失败原因）；
   启动拉取静默，结果只体现在下次进页或按钮上。
5. dmg 版本提示（D5 轻档）：sidecar 启动时请求 GitHub Releases API 取 latest tag，与本包
   `version` 比对，结果经现有接口透出；web 设置页 + 托盘展示「发现新版本 vX.Y.Z」，点击仅打开
   Release 页（外部浏览器），不提供应用内下载。与 D2 的启动检查合并为同一次异步任务，共用
   「启动后台静默检查」通道。注意 identifier 变更史（beta 期改过 `dev.jarvisworkbench.desktop`）：
   旧包收不到提示属预期外风险低，一次性公告过渡即可。

## 4. 待拍板 / 待细化（下次评审逐条销）

- **Q1 版本回退**：热更版本高于随包版本，之后用户装了更新的 dmg（随包版本又反超缓存）——比较口径取
  `skills_data_version` 整数大者胜、且随包启动时也 upsert 覆盖缓存？还是「远端恒优先」？需定一个。
- **Q2 镜像失败面**：jsDelivr 失败时自动退回 GitHub 直连（慢但可用）还是直接报失败等手动？
- **Q3 首拉与迁移水位**：真库首启迁移（0006→0019）+ 热更同轮发生的先后与失败语义（迁移未过不拉包）。
- **Q4 删除确认**：清单外删除是否需要 UI 确认，还是日志即可（D3 说「需一条删除前确认/日志」，未细分）。
- **Q5 密钥治理**：minisign 私钥存放（GitHub Secrets）、公钥轮换方式、失窃预案。
- **Q6 与「整包自动更新」的关系**：已随 D5 裁定（轻档做、自动替换挂起），此条关闭。
- **Q7 Releases API 限流**：未认证请求 60 次/小时/IP，正常每启动一次不会踩，但共享出口 IP 下可能
  403——失败静默降级（不提示、下次启动再试）是否即可，还是需要镜像端静态 latest 文件兜底。

## 5. 非目标（本期明确排除）

- **dmg 应用内自动替换/下载**（tauri-plugin-updater）——D5 已裁定本期只做检查+提示，自动替换待
  Apple Developer 签名/公证定论后再议；「检查+提示」轻档不属本条。
- 前端资源单独热更（Tauri 架构不支持）、sidecar 后端热更。
- 用户技能（source=user/import）的远端同步——远端通道只服务 source=default。
