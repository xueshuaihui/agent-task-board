# 一、产品定位

## 1.1 一句话定位

**Jarvis Workbench 是一个纯本地的桌面应用，内置完整的任务看板和技能平台。技能来自默认技能、自定义技能、三方导入技能三种来源。任务在本地管理，Agent 通过 MCP 领取任务、按技能执行、回写结果。**

## 1.2 产品形态

```text
┌─────────────────────────────────────────────────────────────┐
│                  Jarvis Workbench（桌面）                    │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  任务层（本地）                                       │   │
│  │  分组 · 需求 · 任务 · 依赖 · 审核 · 看板 · 流程图     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  创建层                                              │   │
│  │  手动创建 · 需求拆解 · 会话直接创建 · Agent 接入      │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  技能层（本地）                                       │   │
│  │  默认技能 · 自定义技能 · 三方导入技能                 │   │
```

## 1.3 核心决策

| 决策 | 结论 |
|---|---|
| 产品形态 | 纯本地桌面应用（Tauri） |
| 服务端 | 不做（既有 `apps/cloud` 服务端市场**彻底下线**，见「廿一、存量处置」） |
| 账号体系 | 不做（既有账号体系**彻底移除**，见「廿一、存量处置」） |
| 登录 | 不需要（移除登录页与多账号切换，首启直达看板） |
| 数据存储 | 本地 SQLite |
| 技能共享 | 不做 |
| 技能订阅 | 不做 |
| 技能源 | 不做 |
| 技能来源 | 默认 / 自定义 / 三方导入 |
| 技能导入 | 支持（唯一外部入口） |
| 审核 | 仅任务审核 |
| Agent 管理 | 不管理，只提供 MCP 接入 |
| MCP 安装 | 用户自行安装配置 |
| 分类维度 | 分组（Group），非项目（含存量 Project 改名迁移，见「廿一、存量处置」） |
| 分组归档 | 组内全部需求/任务完成后手动归档，归档分组不占上限 |
| 技能标识 | 全局唯一 ID，名称允许重复 |
| 需求拆解 | Agent 发起，Board 确认 |
| 会话创建 | Agent 直接创建，轻确认 |
| 看板视图 | 看板 / 列表 / 流程图 |
| 布局 | 左侧导航 + 顶部工具栏 |

## 1.4 目标

1. **任务管理**：可视化看板、依赖、审核、归档。
2. **分组管理**：多分组并行，任务归属清晰。
3. **需求拆解**：Agent 自动拆解，Board 可视化确认。
4. **会话创建**：Agent 通过会话直接创建任务。
5. **多视图**：看板 / 列表 / 流程图三种模式。
6. **技能管理**：默认 / 自定义 / 三方导入三种来源。
7. **Agent 接入**：通过 MCP HTTP / REST API。
8. **完全本地**：无云端依赖，数据在用户手中。

## 1.5 非目标

1. 不做服务端。
2. 不做账号体系。
3. 不做登录。
4. 不做云端同步。
5. 不做技能共享。
6. 不做技能订阅。
7. 不做技能源。
8. 不做组织。
9. 不做多设备迁移。
10. 不做数据加密。
11. 不做 Agent 生命周期管理。
12. 不做 MCP 代安装。
13. 不做平台侧并发限制。
14. 不做多语言界面。

|---|---|

| **Task** | 统一工作项 |
| **Requirement** | 需求，type=requirement 的任务 |

| **Run** | 任务的一次执行尝试 |
| **Lease** | 任务租约 |
| **Artifact** | Agent 产物 |

| **BreakdownSession** | 拆解会话 |

## 2.1 分层结构

```text
分组（Group）
  ├── 任务（Task）
  │     ├── 属于某分组
  │     ├── 可选属于某需求
  │     └── 可绑定技能、依赖、标签
  │
  └── 需求（Requirement，type=requirement）
        ├── 作为父任务
        ├── 聚合子任务
        └── 进度由子任务聚合
```

## 2.2 分组与需求、标签的区别

| | 分组 | 需求 | 标签 |
|---|---|---|---|
| 性质 | 分类维度 | 父任务 | 属性标记 |
| 数量 | 一个任务一个 | 可选一个 | 多个 |
| 层级 | 扁平 | 父子 | 无 |
| 示例 | 电商平台 | 优惠券功能 | 后端、P1 |

> **看板面收口（2026-09-24 拍板，见 §19.14）**：在看板语境中「分组」与「需求」视为同一个概念，看板 UI 不再出现「分组」；上表的区别仍是数据模型层事实（`group_id` 与 `parent_task_id` 两列都在），「分组」一词保留给列表页分节维度与「设置 / 分组」管理页。

## 2.3 技能与相关概念

| 概念 | 回答的问题 | 处理方式 |
|---|---|---|
| **Skill** | 怎么做 | 核心抽象 |
| **Rules** | 不能怎么做 | 技能内部的约束段落 |
| **Workflows** | 按什么顺序做 | 技能的一种表达形式 |
| **Prompt Templates** | 怎么问 | 技能的一种表达形式 |
| **MCP** | 怎么连 | 技能声明的外部依赖 |

## 2.4 技能的本质

技能是**抽象的能力封装**，可以表现为：

- 单条提示词
- 步骤列表
- 流程图
- 脚本
- 知识包
- 工具编排
- 决策树
- 组合技能
- 多阶段工作流
- 以上任意组合

# 四、任务管理

## 4.1 状态机

```text
需求池 → 待执行 → 执行中 → 人工阻塞 → 待审核 → 已完成
                       ↘ 异常/失败（执行中直接上报，或租约超时）
```

| 列 | 说明 |
|---|---|
| 需求池 | 新建任务、驳回回退的任务 |
| 待执行 | 可被 Agent 领取 |
| 执行中 | Agent 已认领 |
| 人工阻塞 | Agent 请求人工输入（`block_task`）、技能人工块、或必需 MCP 依赖缺失；人工处理后回「待执行」重新可领 |
| 待审核 | Agent 执行完，等待人工审核 |
| 已完成 | 审核通过 |
| 异常/失败 | Agent 上报失败，或租约超时 |

**流转：**

```text
需求池 ──► 待执行 ──► 执行中 ──► 待审核 ──► 已完成
  ▲          ▲                      │
  │          │                      │ 驳回
  └──────────┴──────────────────────┘

执行中 ──► 异常/失败 ──► 需求池 / 待执行

执行中 ──► 人工阻塞 ──(人工处理)──► 待执行
```

## 4.2 任务字段

| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 描述 | Markdown |
| 类型 | 需求/缺陷/子任务/巡检/重构/测试/文档/自定义 |
| 优先级 | P0-P3 |
| 标签 | 多标签 |
| 所需能力 | 供 Agent 筛选 |
| 自定义字段 | 用户定义 |
| 依赖 | blocks / relates |
| 绑定技能 | 0 到多个 |
| 截止时间 | 可选 |
| 置顶 | 支持 |
| group_id | 所属分组 |
| parent_id | 父任务（需求） |
| 来源 | 手动 / Agent 直接 / Agent 拆解 / 导入 |

## 4.3 任务依赖

| 类型 | 语义 | 对抓取的影响 |
|---|---|---|
| blocks | 硬性前置 | Agent 不能领取 |
| relates | 仅标记 | 不影响抓取 |

**抓取顺序：** 置顶 > 优先级 > 创建时间

**循环依赖：** 添加时检测并拒绝。

**依赖图：** DAG 视图，支持缩放、拖拽、点击打开详情。

## 4.4 任务领取与并发

- Agent 通过 MCP HTTP / REST API 领取。
- 原子认领 + 租约，防止重复。
- 不做平台侧并发限制。
- 同一任务在任一时刻只能被一个 Run 持有。
- 不同任务可并行执行。

## 4.5 审核

**仅人工审核，无自动审核。**

审核必填：

| 字段 | 说明 |
|---|---|
| 审核结论 | 通过 / 驳回 |
| 审核建议 | 对该次执行的评价 |
| 原因 | 为什么通过或驳回 |
| 详情 | 具体要求、修改点 |

驳回时选择：

| 字段 | 说明 |
|---|---|
| 退回目标 | 待执行（默认）/ 需求池 |
| 优先级调整 | 可选 |

审核意见保留在任务上，Agent 下次可读取。

## 4.6 任务模板

预填：标题前缀、描述、类型、优先级、标签、所需能力、自定义字段、技能、分组。

## 4.7 导入导出

- 格式：JSON / CSV
- 范围：全部 / 当前筛选 / 选中
- 导入策略：新增 / 覆盖
- 分组处理：可映射到现有分组或归入默认分组

## 4.8 归档

- 手动归档
- 自动归档：已完成超 N 天（可配置）
- 归档任务可在「已归档」中查看、恢复

## 4.9 自定义字段

| 属性 | 说明 |
|---|---|
| 字段名 | 显示名称 |
| 字段 key | 内部标识 |
| 类型 | 文本/多行文本/数字/单选/多选/日期/布尔/链接 |
| 是否必填 | |
| 适用任务类型 | |
| 排序、启用 | |

## 4.10 产物预览

支持：diff、图片、文本、Markdown、JSON、HTML、PDF。

单文件默认上限 10 MB。

## 4.11 审计

记录：任务创建、状态变更、认领、回写、审核、Token 使用、字段定义变更、模板变更、依赖变更、分组变更、导入导出、备份、归档。

# 五、分组管理

## 5.1 分组的定义

**分组是任务的顶层分类维度。一个任务归属于一个分组。**

| 属性 | 说明 |
|---|---|
| 名称 | 分组名 |
| 颜色 | 视觉标识 |
| 图标 | 视觉标识 |
| 描述 | 可选 |
| 排序 | 显示顺序 |

## 5.2 默认分组

- 系统预置「默认」分组
- 新任务不指定分组时归入默认分组
- 默认分组不可删除

## 5.3 分组管理位置

**在设置页。**

```text
设置
├── 通用
├── Token
├── 分组
├── 视图
├── 字段定义
├── 模板
├── Agent
├── 数据
├── 日志
├── 备份
└── MCP
```

## 5.4 分组管理页

```text
┌─────────────────────────────────────────────────────────────────────────────┐
```

## 5.5 约束

| 约束 | 说明 |
|---|---|
| 数量上限 | 暂定 50 个（仅计活跃分组，归档分组不占额；后续按实际需要调整） |
| 嵌套 | 不支持，扁平 |
| 删除保护 | 默认分组不可删 |
| 删除处理 | 迁移到默认分组 或 一并删除 |
| 归档 | 组内全部任务完成后可手动归档（见 §5.6） |

## 5.6 分组归档（r2 新增）

- **触发条件**：分组下**所有任务（含需求及其子任务）均已「已完成」或已归档**时，才允许归档；否则入口置灰并提示剩余任务数。
- **操作方式**：仅手动（分组管理页 / 泳道头「更多操作」），不做自动归档。
- **归档效果**：分组从分组切换器、看板泳道与流程图中默认隐藏；任务数据不移动、不删除，分组转为只读（不能再向该组建任务，Agent 不再领取其任务）。
- **查看与恢复**：在「设置 / 分组 —— 已归档」中查看、取消归档；恢复后重新占用 50 上限，上限已满时不允许恢复。
- 默认分组不可归档。
- **闭环（r3）**：归档分组的任务从 `claim_next_task` / `list_ready_tasks` 候选中排除；`GET /api/v1/groups` 支持 `archived=true` 筛选；WS 推 `group.archived` / `group.unarchived`；审计动作 `group.archive` / `group.unarchive`；取消归档后恢复可领取。

# 八、会话直接创建任务

## 8.1 功能定位

**Agent 客户端通过会话直接创建单个任务，不弹窗、不跳转、不打断对话。**

## 8.2 三种模式

| 模式 | 行为 |
|---|---|
| **直接创建** | Agent 调用即创建，无确认 |
| **轻确认** | Board 弹出轻量确认卡片（默认） |
| **静默创建** | 创建后仅通知 |

**模式生效优先级：**请求参数 `confirmation_mode` > 设置「创建模式」> 默认轻确认。「直接创建」不弹卡片，但重复检测命中时升级为轻确认卡片；「静默创建」不弹确认卡片、仅发通知，创建后仍保留 5 秒撤销 Toast。

## 8.3 完整流程（轻确认）

```text
Agent 调用 board.create_task
    ↓
Board 校验（重复检测、权限、分组、技能）
    ↓
右下角弹出轻确认卡片（30 秒超时）
    ↓
用户响应：
  · 创建 → 创建任务
  · 编辑 → 打开编辑对话框
  · 取消 → 不创建
  · 超时 → 不创建
    ↓
返回结果给 Agent
```

## 8.4 轻确认卡片

**位置：** 右下角，不抢占焦点。

```text
┌─────────────────────────────────────────────────────────────┐
│  📋 创建任务？                                        [×]   │
```

**create_task 输入：**

```json

  "agent_name": "qoder-1",
  "confirmation_mode": "light"
```

**闭环语义（r3）：**轻确认卡片经 WS `agent.task_requested` 下发后，用户操作通过 `POST /api/v1/creation-requests/{id}/decision`（create / edit / cancel，edit 带修改后载荷）回传；`board.create_task` 在服务端阻塞等待决策，最长等待时间 = 轻确认超时 30s + 5s 宽限，到期按「超时→不创建」返回。Agent 若不希望阻塞，可改用异步模式：调用立即返回 `request_id`，用 `board.get_creation_status` 轮询。`agent_sessions`（按 `session_id` upsert，刷新 `last_active_at`/`task_count`）与 `task_creation_logs`（每次创建/取消/超时各记一条）均在 `create_task` 处理事务内由服务端写入；「5 秒撤销」= UI 在 5 秒窗口内调用存量 `DELETE /api/v1/tasks/{id}`，且仅允许撤销 `origin_type=agent` 且未领取的任务。

# 九、技能管理

## 9.1 技能来源

**只有三种来源：**

| 来源 | 说明 | 可编辑 | 可删除 |
|---|---|---|---|
| **默认技能** | 应用预置 | ❌ | ❌ |
| **自定义技能** | 用户创建 | ✅ | ✅ |
| **三方技能** | 外部导入 | ✅ | ✅ |

**三方技能没有「来源」概念（r2）：**三方技能统称用户手动导入的技能文件（技能分享包 / `.atskill` / `SKILL.md` / 目录），不区分、不记录、不展示导入来源，`import_origin` 列删除。

**存量来源值收敛：**既有 `skills.source` 枚举（local/market/builtin/git/http/directory）在迁移时收敛为三来源——`builtin`→默认技能、`local`→自定义技能、其余（market/git/http/directory 及未知值）→三方技能，不保留来源记录。市场订阅落地的技能导入时先导出为 JSON 存档再按三方技能归入。详见「廿一、存量处置」。

**不设受众维度（2026-09-24 分类收口）：**技能没有「官方/社区」受众维度——不加 `audience` 列、不并入 `source_type` 取值，出处只由上表三来源（默认/自定义/三方）表达；`tags` 与 `category` 中均不得出现「官方」「社区」。

**分类与标签（2026-09-24 分类收口）：**本条取代 #41 开发期「分类不加 schema 列、由 tags 词表承载」的临时口径（该口径未入正文，只存在于迁移映射表与实现）。两字段两语义，不再共用 `tags`：

| 字段 | 语义 | 取值 |
|---|---|---|
| `category` | 分类，**单值**——一个技能只有一个分类，取值**恒为叶子** | **两级受控词表**（0925 树化，0018 迁移）：**16 个合法叶子 + `''`**（未分类）。7 个一级：编码开发 / 教育学习 / 内容创作 / 方案写作 / 投资理财 / 办公实用 / 研究分析；其中**编码开发、办公实用、研究分析是纯分组一级，不可作为 `category` 值提交（422）**，教育学习/内容创作/方案写作/投资理财一级兼叶子。叶子：编码开发→需求与规划/开发与实现/质量与安全/代码清理/运维与协作/测试自动化/开发编程；办公实用→Office办公/实用工具；研究分析→数据分析/资讯研究/推荐。作废词（`RETIRED_CATEGORY_TERMS`）：「开学季」（0925 删项）、「质量保障」（0925 树化作废，语义续位「编码开发/质量与安全」）——不得进 `category`（越表 422/归 `''`），也不得留在 `tags` |
| `tags` | **自由标签**，不承载分类、不承载受众词 | 自由文本数组；**唯一豁免**：六个产研阶段词（需求与规划/开发与实现/质量与安全/代码清理/运维与协作/测试自动化）是**双角色词**——既是「编码开发」下的分类叶子，也合法保留在 coding 内置的 `tags` 里作阶段标签（0925 拍板接受卡片「分类徽标 + 同名标签」两行呈现的观感特例）；除此之外 `tags` 不得出现任何叶子词或作废词 |

- 词表收在 `skills.category` 的列级 CHECK 里（0018 起为 `''` + 16 叶子，见 §15.1、§21.4、§21.6），词表外值不落库。
- `SKILL.md` frontmatter 的 `category` 与该列**一一对应**：导入时 frontmatter `category` 直落该列；值不在词表内（含历史导出包把 `category` 误写成 `workflow`/`flow` 这类类型枚举值的旧包，**也含作废词「质量保障」——不做 compat 映射，0925 Q5-D 拍板**）→ 归未分类 `''`，**不报错**。
- 上方样例即此口径：`category: 质量与安全`（0925 树化后 code-review 的叶子值，原「质量保障」已作废）、`tags: [review, quality]` 为自由标签。

**分类的展示面收口（2026-09-24，0925 树化跟批）：** `category` 真列的口径同样覆盖展示面——技能卡片（分类徽标：带图标、中性底，与自由标签 chip 视觉分家；双角色阶段词按拍板允许徽标与标签同名两行并存）、详情抽屉（「分类」独立成行，不混进标签堆）、编辑器（结构化表单的**两级 16+1 单选**：纯分组一级只作组头、不可提交，0925 树化前为 11+1 平铺）三处**直读 `skill.category`**，`''` 一律走「未分类」文案，与筛选器的选项和计数同源，**绝不从 `tags` 推导**。真列落地初期只有筛选器读到它、卡片/抽屉/编辑器三处展示面没有任何一处显示分类、卡片照旧渲染「开学季」这类自由标签词且与分类 chip 长得一模一样（「两套分类标准」在展示面的残余）——该状态由本收口废止。

**技能唯一标识（r2）：**每个技能以全局唯一 `id` 标识——创建时生成（ULID），重命名、改版、导出再导入均不变；`name` 允许与其他技能重复，唯一性只由 `id` 保证，任务绑定与随任务下发一律按 `id` 解析。`.atskill` 与 `SKILL.md` 导出时必带 `id` 字段；导入时同 `id` 识别为同一技能，同名不同 `id` 视为不同技能直接共存（列表对同名技能追加 `id` 短后缀消歧）。老存量技能无 `id` 字段的，迁移时生成并回写文件。

## 9.11 技能选择器（统一「选技能」入口）

平台内所有「选技能」入口——任务详情的绑定技能（§10.1）、拆解草案的技能多选（§7.4）、技能编排中子技能块的技能引用（§9.4）、技能库页「新建技能」下拉里的「复制现有技能」（弹窗内联形态，打开即见列表）——**必须是同一个选择器组件与同一套匹配行为**，不允许任何一处再自写一套名称/ID 子串过滤。四处现已全部收口为同一组件：复制技能弹窗是最后收口的一处，其自绘搜索框 + 自绘列表与每按键一次的服务端搜索一并作废。本条口径由 §19.13 第 83 条钉死。

**匹配是纯前端本地的：**技能列表一次性全量在手，搜索过程**不产生任何请求**，`GET /skills` 不因搜索新增查询参数（与 §21.3 分类筛选轴「筛选在前端」同取向）。

**匹配维度（六面）：** 名称、描述、分类（§9.2 的两级词表，**16 叶子**、0925 树化见 §21.6，`''` 按「未分类」文案参与匹配；**0925 树化后分类命中面 = 「叶子 + 所属一级」拼接文本**，搜「编码」可收拢命中编码开发子树全部条目，一级兼叶子的不重复拼接）、类型（中英文两侧皆可命中，如 `workflow` 与「工作流」）、技能 `id`（含 §9.2 r2 用于消歧的 `id` 后 6 位——UI 上看得见就允许照着搜）、标签。`tags` 在此是自由标签检索面（§9.2）：受众词「官方/社区」已作废、出处由 `source_type` 承载（§9.1），「分类从 `tags` 做减法凑出来」的做法不再存在，选择器也不得从 `tags` 推断分类；六个产研阶段词按双角色拍板同时出现在分类与标签两面，命中面**不去重、不特判**。

**切词与匹配：** 查询按空白切词，token 之间取 **AND**（任一 token 六面皆空则该技能出局）；单个 token 在单个字段上依次尝试 **前缀 → 子串 → 子序列** 三档并取最优档。**不引入拼音词典，不加编辑距离。**

**展示：** 空查询按 `category` 分组展示（组头为 `分类（条数）`），未分类恒排最后；有查询时按匹配分平铺并给命中条数提示。结果条数有上限（暂定 20 条），被截断时给「结果过多，请细化查询」提示，不做全量铺满。选择器自身不发请求、不做业务过滤。

**行模型（2026-09-24 真机走查收口口径，取代此前「名称 + 类型中文标签 + 状态 + 版本号」的单一形态）：**

- **分组态（空查询）：名称 + 版本号。** 逐行的类型/状态徽标与分类文本撤下——分类由组头承载，类型与状态对「挑一个技能」的决策帮助有限，真机实测徽标会把名称挤成省略号（320px 弹层）。
- **查询态：名称 +（仅当命中落在分类字段上时追加分类文本，交代命中原因）+ 类型中文标签 + 版本号。** **状态徽标两态都不展示**——排除 `ARCHIVED` 这类候选过滤归调用方（见下文各入口业务规则）。
- **名称的命中窗口化：** 只有当**名称字段本身确有命中**时才做窗口化——以命中位置为中心开窗、两侧与段间以 `…` 标记，保证高亮片段一定落在可视区内（窗口化在数据层做，不留给渲染层省略号截断，否则高亮会被吞在盒外）；名称零命中时恒全名直出、不做任何人为截断——无命中的截断没有要保护的内容，只会把不同技能截成视觉相同的两行。窗口预算不是固定字符数，而是按**该行名称区的实测像素宽**换算成显示宽度单位（拉丁/半角 1、CJK/全角约 2）：按字符数计会系统性低估 CJK 的像素宽，长中文名的高亮整段被 CSS 省略号吞在盒外。
- **重名消歧后缀恒可见：** 重名技能行追加 `id` 后 6 位消歧后缀，命中片段高亮；后缀渲染在截断区之外、不参与窗口预算扣减——永不被省略号吞掉，「原件」与「副本」两行恒可分辨。
- **打开即输的挂载形态：** 复制技能弹窗内面板挂载后焦点落进搜索框，打开直接打字即过滤。

**四处各自的业务规则留在调用方，不下沉进选择器：**

- 任务详情绑定技能：候选必须排除已绑定技能与 `ARCHIVED` 技能；行主点击仍打开技能详情抽屉，「绑定」是行尾的独立动作。
- 拆解草案技能多选：选中后面板不关闭，点击已选项做增删切换。
- 子技能块技能引用：技能库为空（或列表未就绪）时退回手填 `skl_xxx` 的输入框；引用了库外技能时按唯一 `id` 回显并标注「不在技能库」，提供「清除引用」。
- 复制技能弹窗：单选，选中即收弹窗进入复制流程——页面侧按选中 `id` 取全量内容、创建名称加「副本」后缀的新草稿；取数与加载/失败/空库状态留在调用方，原「N 个块」信息经行尾插槽保留。技能库列表页自身的关键词搜索轴属于列表筛选，不在本节「选技能」口径之内。

# 十一、Agent 接入

## 11.1 接入方式

**仅 MCP over Streamable HTTP（现状为无状态模式），不用 stdio、不提供独立 SSE 流。**

- 服务常驻，MCP 端点监听 `127.0.0.1:7788/mcp`
- Agent 客户端配置 MCP URL + Token
- 服务独立于 Agent 运行

## 11.2 接入步骤

1. 用户在设置页生成 Agent Token
2. Agent 客户端配置 MCP URL 和 Token
3. Agent 客户端自身配置定时任务，调用 `claim_next_task`
4. 执行中定期 `heartbeat`
5. 完成后 `complete_task`
6. 下次领取时，通过 `get_task` 读取审核意见、技能、自定义字段

## 11.3 配置示例

```json
{
  "mcpServers": {
    "jarvis": {
      "url": "http://127.0.0.1:7788/mcp",
      "headers": {
        "Authorization": "Bearer <agent-token>"
      }
    }
  }
}
```

## 11.4 并行执行

并行执行由 Agent 客户端自行管理：

- 对每个任务独立维护 `task_id`、`run_id`、`lease_id`
- 对每个 Run 分别 `heartbeat`、`update_progress`、`append_log`
- 对每个 Run 分别 `complete_task` 或 `fail_task`

## 11.5 首批接入

| Agent | 接入方式 |
|---|---|
| Qoder | MCP HTTP + REST |
| Claude Code | MCP HTTP + REST |
| Codex | MCP HTTP + REST |

# 十二、MCP 依赖治理

## 12.1 核心原则

**第三方 MCP 由用户/Agent 客户端自己安装和配置，平台不负责安装。**

| 环节 | 谁负责 |
|---|---|
| 声明 MCP 依赖 | 技能作者 |
| 本地检查 | 应用 |
| 下发策略 | 本地随技能下发 |
| 安装 MCP | 用户 |
| 配置 MCP | 用户 |
| 认证授权 | 用户 |
| 调用 MCP | Agent 客户端 |
| 记录审计 | 本地记录 |

## 12.2 依赖声明

```yaml
mcp_dependencies:
  - name: github
    server_url: "https://api.githubcopilot.com/mcp/"
    transport: http
    required: true
    tools: [get_pull_request, create_review]
    scopes: [repo:read]
    auth_type: oauth2
```

**约束：**

- `tools` 必须精确到工具级
- 一个技能最多声明 8 个 MCP 依赖

## 12.3 本地检查

| 检查项 | 说明 |
|---|---|
| 格式校验 | 结构合法性 |
| 可达性检测 | DNS + TLS 握手 |
| 权限提示 | 展示所需权限 |

## 12.4 策略下发

策略包随技能下发：

```json
{
  "mcp_policy": {
    "allowed_servers": [
      {
        "name": "github",
        "allowed_tools": ["get_pull_request"],
        "require_auth": true,
        "max_calls_per_run": 20
      }
    ],
    "deny_undeclared": true,
    "deny_transitive": true
  }
}
```

## 12.5 依赖缺失处理

| `required` | 行为 |
|---|---|
| true | 技能中止，任务 `BLOCKED` |
| false | 跳过依赖步骤，产物中标注 |

## 12.6 审计

所有 MCP 调用记录到本地：

| 审计项 | 内容 |
|---|---|
| 调用发起 | 技能 ID、任务 ID、Run ID |
| MCP 服务器 | name、url |
| 调用的工具 | tool name |
| 结果 | 成功/失败、耗时 |
| 策略决策 | 允许/拒绝 |

**审计边界（评审补充）：**Agent 对第三方 MCP 的调用不经本地代理，平台无法强制拦截。审计数据来源为「调用前 `check_mcp_policy` 的决策记录 + 调用后 `report_mcp_call` 的结果上报」，属本地信任模型下的尽力记录；未上报的直连调用平台侧不可见，仅在文档与接入示例中声明该约定。

审计保留 180 天。

## 14.3 关键实现

**任务认领并发控制（SQLite）：**

```sql
BEGIN IMMEDIATE;
UPDATE tasks
SET status = 'RUNNING',
    lease_id = ?,
    lease_expires_at = datetime('now', '+30 minutes'),
    current_run_id = ?
WHERE id = (
  SELECT id FROM tasks
  WHERE status = 'READY'
    AND type != 'requirement'
    AND (lease_expires_at IS NULL OR lease_expires_at < datetime('now'))
    AND NOT EXISTS (
      SELECT 1 FROM task_dependencies d
      JOIN tasks dep ON dep.id = d.depends_on
      WHERE d.task_id = tasks.id
        AND d.type = 'blocks'
        AND dep.status != 'DONE'
    )
  ORDER BY pinned DESC, priority ASC, created_at ASC
  LIMIT 1
)
RETURNING *;
COMMIT;
```

**流程图布局：** dagre 算法，Worker 中计算。

**需求拆解：** MCP 事件驱动 + WebSocket 推送。

**轻确认卡片：** 全局浮层组件。

**技能导入：** 解析 SKILL.md / `.atskill`，校验格式，写入本地。

## 21.4 技能分类收口迁移 0015（2026-09-24 已落地）

> **Jarvis Workbench 是一个纯本地的桌面应用，内置完整的任务看板和技能平台。技能来自默认技能、自定义技能、三方导入技能三种来源。任务在本地管理，Agent 通过 MCP 领取任务、按技能执行、回写结果。无服务端、无账号体系、无技能共享、无技能订阅。**
