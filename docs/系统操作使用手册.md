## 1. 概述

### 1.1 产品定位

Jarvis Workbench 是一款**桌面任务看板 + 技能工作台**：人负责建需求、拆任务、写技能；Agent（外部智能体）通过 MCP / REST 认领并执行任务，**执行结果必须经过人工审核**后才算生效。业务数据全部写入本机 SQLite（由桌面壳托管的本地 sidecar 读写），技能可以从**服务端市场**订阅或本地创作。

核心原则：

- **人建任务，Agent 执行**：任务的生命周期由人和 Agent 分工驱动。
- **强制人工审核**：Agent 完成交付后任务进入「待审核」，必须由人通过 / 驳回，结果才会落定。
- **本地优先**：后端仅监听 `127.0.0.1`，任务、项目（分组）、技能、审核与审计都在本机；服务端不可达时市场自动回落本地内置内容（`apps/web/src/features/settings/tabs/cloud.tsx:51`）。
- **按账号隔离**：本地数据按登录账号隔离（PRD §4.2），实现为**单库 `atb.db` 内按 `accountId` 行级过滤**，不是每账号一个库文件（该偏差见发版记录 v0.0.3 §2.1）。

### 1.2 适用对象

| 角色 | 典型操作 |
| --- | --- |
| **ADMIN（本机建号者）** | 创建/停用账号、重置密码、管理分组与项目级设置、审核 Agent 交付 |
| **MEMBER（使用者）** | 登录自己的账号，在看板上建任务、拖拽流转、审核自己可见的任务 |
| **Agent 接入开发者** | 签发 Token、通过 MCP/REST 认领任务、回写进度与产物、读取审核意见 |
| **运维 / 部署** | 安装依赖、启动 sidecar、桌面打包、部署与升级服务端市场（`apps/cloud`） |

### 1.3 系统架构与运行边界

```
┌──────────────┐      ┌───────────────────────────┐      ┌─────────────────┐
│   @atb/web   │      │  @atb/desktop (Tauri 2)   │      │  外部 Agent     │
│ React + Vite │◄─────┤  窗口 / 托盘 / 单实例     │◄─────┤  MCP / REST     │
│  主窗口 UI   │ REST │  Rust 壳（不承载业务数据）│      │  认领并执行任务 │
└──────────────┘      └─────────────┬─────────────┘      └─────────────────┘
                                    │ 托管 sidecar 子进程
                                    ▼
                          ┌───────────────────────────┐
                          │   @atb/api (NestJS 11)    │
                          │  REST + MCP + WebSocket   │
                          │  仅监听 127.0.0.1 : 7788  │
                          │  Prisma 6 + SQLite（本地）│
                          └─────────────┬─────────────┘
                                        │ 可选：设置 →「服务端」配置地址与服务端账号
                                        ▼
                          ┌───────────────────────────┐
                          │  @atb/cloud（独立部署）    │
                          │  账号 + 技能市场 /cloud/v1 │
                          │  只绑 127.0.0.1:7789，     │
                          │  对外 HTTPS 由边缘反代     │
                          └───────────────────────────┘
```

关键边界：

- **本地后端 sidecar 仅绑定 `127.0.0.1`**，任何情况下不监听 `0.0.0.0`（`apps/api/src/main.ts`）。
- 同一端口（默认 **7788**）复用三条通道：**REST**（`/api/v1`）、**MCP**（`/mcp`，无状态 Streamable HTTP）、**WebSocket**（`/ws`）。
- **桌面壳（Rust）不存业务数据**，所有读写走 sidecar 的 REST（边界原则见 `apps/desktop/src-tauri/Cargo.toml` 注释）。
- **服务端只装账号与市场**：任务、分组、审核、审计永不上行（PRD §4.3 的同步方向）。本地账号与服务端账号是**两套独立体系**（各自 JWT 密钥、各自有效期 30 天 / 7 天），登录服务端只是为了拉市场，不代表统一身份（见发版记录 v0.0.3 §3.5）。
- 服务端部署与运维全部走离线镜像包 + `deploy.sh`，详见 `apps/cloud/README.md`。

### 1.4 技术栈

| 应用 | 技术 | 职责 |
| --- | --- | --- |
| `@atb/web` | React 18 + Vite 6 + Tailwind 4 | Tauri 主窗口前端；`@dnd-kit` 拖拽、`@tanstack/react-query` 数据、`zustand` 状态、`@xyflow/react` 流程图与依赖图 |
| `@atb/api` | NestJS 11 + Prisma 6 + SQLite | 本地 sidecar；REST + MCP + WebSocket；`zod` 校验、`winston` 日志审计 |
| `@atb/desktop` | Tauri 2 + Rust | 桌面壳：窗口（1440×900 起、**960×600 最小**）、托盘、单实例、系统对话框、sidecar 进程托管 |
| `@atb/cloud` | NestJS 11 + Prisma 6 + SQLite | 可独立部署的服务端市场：账号注册/登录 + 技能发布、版本、订阅、评分、评论、收藏、举报、反馈 |

## 2. 安装与启动

### 2.1 环境要求

- **Node.js ≥ 20**（根 `package.json` 的 `engines`）
- **Rust 工具链**（仅桌面端构建需要）：`cargo` 加入 `PATH` → `export PATH="$HOME/.cargo/bin:$PATH"`
- **npm**（使用 workspaces，无需 pnpm/yarn）

### 2.2 开发模式启动

```bash
# 1. 安装依赖（根目录，一次性）
npm install

# 2. 初始化本地数据库（Prisma + SQLite，执行 apps/api/scripts/db.mjs）
npm run prisma

# 3. 启动后端 sidecar（监听 127.0.0.1:7788）
npm run dev:api

# 4. 启动前端（Vite 开发服务器 / Tauri 主窗口）
npm run dev:web
```

> 启动成功后，sidecar 向 stdout 输出唯一一行就绪信号：
> `ATB_READY {"port":7788,"pid":...,"version":...}`，桌面主进程据此确认端口已就绪。

**服务端市场（可选）本地起服**：

```bash
npm run build -w @atb/cloud
CLOUD_JWT_SECRET=$(openssl rand -hex 32) npm run start -w @atb/cloud   # 监听 7789，数据在 ~/.agent-board-cloud/cloud.db
npm run dev:cloud                                                       # 或 watch 模式
npm run test  -w @atb/cloud                                             # 真 HTTP + 临时 SQLite
```

桌面端在「设置 → 服务端市场」填服务地址（如 `http://127.0.0.1:7789`）与服务端账号即可联通；
生产部署见 `apps/cloud/README.md`（离线镜像包 + `deploy.sh`），本地打开发包用 `npm run bundle:cloud`。

### 2.3 桌面端打包

```bash
# 仅构建前端 + Rust 二进制（无 .app 外壳）
npm run build            # = nest build (api) && tsc -b && vite build (web)
npm run desktop:build    # cargo build --release，产物 apps/desktop/src-tauri/target/release/atb-desktop

# 打包 macOS .app / .dmg（可选，需 @tauri-apps/cli）
npm run build                        # 先构建 api（tsc）+ web（vite）
npm run build:sidecar -w @atb/api    # 装配 sidecar 打包资源（webpack 单文件 bundle + 最小 Prisma 运行时 + 迁移 + node）
cd apps/desktop
export PATH="$HOME/.cargo/bin:$PATH"
npx tauri build          # 产物在 src-tauri/target/release/bundle/；.dmg 若因 osascript 失败，用 README 的 hdiutil 兜底
```

> 默认未安装 `@tauri-apps/cli`，因此 `desktop:build` 即可产出 Rust 二进制；若要完整安装包需先 `npm install -D @tauri-apps/cli`。

阶段一仍无 Apple Developer 证书/公证，按降级方案交付，不影响功能与验收）。

### 2.5 端口与访问地址

端口三级决定（优先级从高到低）：

1. 环境变量 `ATB_PORT`
2. `config.json` 中的 `port`
3. 默认 `7788`（`apps/api/src/common/paths.ts`）

前端基址解析顺序：`window.__ATB_API_BASE__` → `__ATB_PORT__`（→ `127.0.0.1:port`）→ `VITE_ATB_API_BASE` → 默认 `http://127.0.0.1:7788`。

服务端市场侧（`apps/cloud`）：

| 项 | 值 |
| --- | --- |
| 监听 | `HTTP_BIND:HTTP_PORT`，默认 `127.0.0.1:7789`（生产由边缘反代对外） |
| API 前缀 | `/cloud/v1`；健康检查 `GET /healthz` 回显 `{ok,commit}` |
| 桌面端指向 | 设置 → 服务端 → 服务地址（对应 `ATB_CLOUD_URL`，所有请求以 `<url>/cloud/v1` 为根） |
| 关键环境变量 | `CLOUD_JWT_SECRET`（生产必填、**不可再生**）、`CLOUD_CORS_ORIGINS`、`EDGE_MODE`、`SITE_DOMAIN`/`ACME_EMAIL` |

## 3. 核心概念

### 3.1 任务与七状态

任务固定落在**按状态分列的看板**，每列对应一个状态（`apps/api/src/contract/enums.ts`）。
PRD §6.1 本期新增 `BLOCKED`，状态集从 6 个变 7 个，看板相应为 **7 列**：

| 状态 | 标签 | 含义 |
| --- | --- | --- |
| `BACKLOG` | 需求池 | 新建任务默认落此列，尚未可执行 |
| `READY` | 待执行 | 已具备执行条件，等待 Agent 认领 |
| `RUNNING` | 执行中 | Agent 已认领并正在执行（**只能由 Agent 认领产生**） |
| `BLOCKED` | 人工阻塞 | Agent 执行到技能的「人工块」时上报转人工（PRD 8.4），等人处理后回 `READY` |
| `REVIEW` | 待审核 | Agent 已完成交付，等待人工审核 |
| `DONE` | 已完成 | 审核通过，终态 |
| `FAILED` | 异常/失败 | 被强制停止或执行失败，可重试 |

### 3.2 状态流转规则（谁能动）

流转矩阵是代码化的单一来源（`apps/api/src/contract/transitions.ts`），前后端共用同一份表。
三类结果：**直接生效（direct）**、**需弹表单（form）**、**禁止（forbidden）**。

| 从 \ 到 | BACKLOG | READY | RUNNING | BLOCKED | REVIEW | DONE | FAILED |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **BACKLOG** | — | ✅ direct | ❌ 仅 Agent | ❌ | ❌ | ❌ | ❌ |
| **READY** | ✅ direct(退回) | — | ❌ 仅 Agent | ❌ | ❌ | ❌ | ❌ |
| **RUNNING** | ❌ | ❌ | — | ❌（只由 Agent 端点产生） | ❌ | ❌ | 🔒 强制停止表单 |
| **BLOCKED** | ✅ direct(退回) | ✅ direct(重试) | ❌ 仅 Agent | — | ❌ | ❌ | ❌ |
| **REVIEW** | 🔒 驳回表单 | 🔒 驳回表单 | ❌ | ❌ | — | 🔒 通过表单 | ❌ |
| **DONE** | ❌ 终态 | ❌ 终态 | ❌ | ❌ | ❌ 终态 | — | ❌ 终态 |
| **FAILED** | ✅ direct(退回) | ✅ direct(重试) | ❌ 仅 Agent | ❌ | ❌ | ❌ | — |

要点：

- **RUNNING 只能由 Agent 认领产生**；人直接把卡片拖到「执行中」一律被拒。
- **BLOCKED 只能由 Agent 调 `POST /api/v1/tasks/:id/blocked` 产生**（拖拽与按钮路径一律拒），
  该端点同时把当次 Run 置 `FAILED` 并清租约；人工处理后拖回「待执行」重试，或退回需求池。
- **FAILED 只能由「强制停止」表单或租约过期产生**。
- **REVIEW 的出口（→DONE / BACKLOG / READY）只能走审核接口**，不能靠拖拽直接改。
- **DONE 为终态**，不可再流转；归档后可恢复回 BACKLOG/READY。

### 3.3 产出物（Artifact）与强制人工审核

- **产出物**是 Agent 在执行过程中交付的文件或链接（`apps/api/src/contract/enums.ts` 类型：`diff / image / text / log / markdown / json / html / pdf / link / file`）。
- 产出物挂在「执行记录（Run）」上；**没有独立的审核状态字段**——审核发生在**任务**层面。
- Agent 上传文件经 `POST /api/v1/artifacts`（仅 Agent 可调用），单文件上限 `artifact_max_mb`（默认 20MB，单 Run 累计 ≤200MB）；`link` 类型不通过上传，由完成回写直接插入。
- 完成交付：`POST /api/v1/tasks/:id/complete` → 任务 `RUNNING → REVIEW`，并推送「待审核」通知。
- 人工审核：`POST /api/v1/tasks/:id/review`：
  - **通过（APPROVE）** → `DONE`，并解锁下游依赖任务。
  - **驳回（REJECT）** → 退回 `BACKLOG` 或 `READY`（必填 `return_to`），任务重新可执行。
- 查看交付内容：前端通过 `POST /artifacts/:id/sign` 换取**一次性签名 URL**（60 秒有效）再拉取原始内容；diff 预览走 `GET /artifacts/:id/diff`。

### 3.4 鉴权与作用域（账号会话 / UI Token / Agent Token）

守卫按凭证分三条判定路径（`apps/api/src/auth/auth.guard.ts`），全部走 `Authorization: Bearer <凭证>`：

| 凭证 | 用途 | 如何获得 | 归属 |
| --- | --- | --- | --- |
| **账号会话 JWT**（HS256，30 天） | 登录后的前端全部接口 + WebSocket `/ws` | 登录页用账号密码换（`POST /api/v1/auth/login`） | 映射到具体 `accountId` |
| **UI Token**（兼容路径） | 未登录/开发态、桌面壳注入 | Tauri 主进程注入内存（`ATB_UI_TOKEN`，≥32 字节）；开发态退化为 `dataDir/dev-ui-token` | 固定映射到**内置 ADMIN 账号 `__local__`**（不出现在用户列表、不可登录） |
| **Agent Token** | Agent 经 MCP/REST 接管的接口 | 在「设置 → Token」中签发，格式 `atb_` + 40 位，明文仅返回一次 | 签发时绑定的 `accountId` |

守卫规则：

- **两套接口面互斥**：Agent Token 调用户接口 403；账号会话/UI Token 调 Agent 写回接口 403。
- **账号状态按库行重算**，不信任旧 token：账号被禁用即 401；`mustChangePassword` 期间只放行
  `auth/me`、`auth/change-password`、`auth/logout` 三个端点，其余返回 `MUST_CHANGE_PASSWORD`。
- **WebSocket 握手同样接受账号 JWT**（v0.0.3 修复：此前只认静态 UI Token，登录后实时连接会断）。
- 撤销 Agent Token 为「禁用」而非删除（保留执行归属）；无重新启用接口。
- `last_used_at` 同一 Token 一小时内最多落库一次（避免审计变成轮询日志）。
- Agent Token 可携带 **能力（capabilities）**，命名空间 `language / framework / repo / tool`，格式 `namespace:value`，用于过滤可认领任务。

### 3.5 自定义字段

字段定义（`apps/api/src/field-defs/*` + `contract/custom-fields.ts`）：

- `key` 唯一，正则 `^[a-z][a-z0-9_]{1,31}$`；`type` 枚举：`text / textarea / number / select / multiselect / date / bool / url`。
- `key` 与 `type` 保存后**不可改**；删除仅当无任务引用，否则应「停用」。
- 全表最多 **2 个** `show_on_card` 字段（仅 `text/number/select/bool`），用于看板卡片展示。
- `required` 字段在任务进入「待执行（READY）」前必须填齐，否则流转被拒（422）。
- `applies_to` 为空表示适用所有任务类型。

设置键总表（`apps/api/src/contract/settings.ts`，越界写入返回 422）。**端口不在设置内**。

| 设置键 | 类型/区间 | 默认 | 热生效 |
| --- | --- | --- | --- |
| `lease_ttl_minutes` | int 1–1440 | 30 | ✓ |
| `heartbeat_interval_seconds` | int 30–600 | 300 | ✓ |
| `board_column_limit` | int 10–200 | 50 | ✓ |
| `auto_archive_days` | int 0–365 | 30 | ✓ |
| `artifact_max_mb` | int 1–200 | 20 | ✓ |
| `backup_time` | `off` 或 `HH:MM` | `03:00` | ✓ |
| `backup_keep` | int 1–30 | 7 | ✗ |
| `log_retention_days` | int 1–90 | 14 | ✓ |
| `log_level` | debug/info/warn/error | info | ✓ |
| `task_types` | 数组(1–20) | 需求/缺陷/子任务/巡检/重构 | ✓ |
| `ui_theme` | system/light/dark | system | ✓ |
| `review_reuse_last_opinion` | bool | true | ✓ |
| `cloud_enabled` | bool | false | ✓ |
| `cloud_url` | 字符串 ≤500 | 空 | ✓ |
| `cloud_username` | 字符串 ≤100 | 空 | ✓ |
| `cloud_token` | 字符串 ≤2000（登录换回的 JWT，**不展示**） | 空 | ✓ |

> `cloud_*` 四项由「设置 → 服务端市场」读写（见 §3.9），看板分组偏好不在这里——它走 `PUT /api/v1/prefs/board.grouping`。

### 3.7 账号体系与本地身份（PRD §3、§4.2）

- **本地不开放注册**：首个 ADMIN 账号在初始化页创建（`accounts.service.ts:63`），之后只有 ADMIN 能在
  **顶栏账号下拉 → 用户管理**（`features/auth/user-manage-dialog.tsx`）建号、改号、停用、重置密码
  （重置后该账号下次登录被强制改密）。后端 `/auth/users` 三件套同样校验 ADMIN 角色。
- **角色**：`ADMIN` / `MEMBER`。ADMIN 多出的能力仅限建号三件套与用户管理，业务数据两边同权。
- **多账号切换**：顶栏账号下拉「切换账号」，记住历史账号；切换即换 `accountId`，看板/列表/技能随之换数据视图。
  实现是**同一库文件按 `accountId` 行级隔离**，不是每账号一个 db 文件（与 PRD §3.4 的措辞有偏差）。
- **服务端账号是另一套**：`apps/cloud` 有自己的 `CloudAccount`（开放注册、无 ADMIN、token 7 天），
  与本地账号不互通。桌面端只是拿服务端用户名密码去换 token 存进 `cloud_token`，
  所以「本地身份 ↔ 服务端身份」的映射由你自己维护（PRD §7.4 的对接约定）。
- **不可再生项**：服务端 `CLOUD_JWT_SECRET`（换=全员掉线）；本地 `ATB_JWT_SECRET` 同理。

### 3.8 分组（项目）与看板分组（PRD §5.1、§7）

三个易混概念，一次讲清（UI 一律叫「分组」，代码与接口仍叫 `project`，见 `d7b94af`）：

| 标识 | 语义 | 落在哪 |
| --- | --- | --- |
| `project_id` | 任务的**归属**字段；跨泳道拖拽会改写它（`patchForLane`） | 任务表 |
| `projectIds` | **作用域**多选过滤器，空数组 = 全部；看板与任务列表页共用，多选 >1 时自动把主分组维度切为 project | 看板工具栏的切换器；偏好持久化到 `PUT /prefs/board.grouping` |
| `grouping` | **呈现层**偏好：主/次维度、泳道顺序、折叠、组内筛选 | 同上 |

- 分组维度实际 7 个：项目 / 需求 / 类型 / 优先级 / 负责 Agent / 标签 / 状态（标签可一卡多组）。
- 分组形态支持三种：单级泳道、主+次**两级**、列表分节；列表视图目前只吃主维度。
- 归档的分组不出现在候选里，删除可选「把任务迁走」或「连任务一起删」（§5.1）。
- **偏好持久化是双层**（`grouping/useGroupingState.ts:77`）：写操作先落 localStorage
  （`atb.board.grouping`），再镜像到 `PUT /api/v1/prefs/board.grouping`；服务端不可达时静默留在本地，
  启动时 `hydrateGroupingPrefs()` 用服务端值覆盖本地（读到合法值才覆盖）。

### 3.9 技能与市场（PRD §8、§9）

- **技能**＝可复用的执行说明，7 类（`prompt / steps / workflow / flow / script / knowledge / composite`，
  `apps/web/src/features/skills/meta.ts:25`），正文由 **15 类块**组成（prompt/step/decision/loop/parallel/
  tool/knowledge/script/subskill/human/input/output/constraint/error_handler/comment），
  可视化 / 结构化 / 源码 / 流程图四种视图共用一份 JSON。
- **版本**：语义化版本，发布产生版本快照，可回滚；测试用例随版本快照，可批量运行（`POST /skills/:id/test`）。
- **技能 → 任务**：任务详情「技能」Tab 绑定；Agent 认领时技能正文与 MCP 依赖随任务下发（PRD §10.3）。
  **注意**：卡片上的技能角标是**手动绑定**的结果，当前没有「按任务描述推荐技能」的逻辑（PRD §10.2 未实现）。
- **人工块**（human 块）执行时会把任务从 RUNNING 置为 **BLOCKED**，等人处理后回 READY（见 §3.2）。
- **导入导出**：`.atskill`（本应用格式）、`SKILL.md`、Cursor `.mdc` 三种，导入中心支持多选与逐文件错误。
- **内置技能库**：`apps/api/src/market/market.seed.ts` 种子 **50 个**技能、11 个分类，
  以 `source:'builtin'`、PUBLISHED、发布者「官方」出现在本地市场里；低价值技能走 delist（订阅快照保留）。
- **服务端市场**：在「设置 → 服务端市场」填服务地址 + 服务端账号密码点连接（`tabs/cloud.tsx`）；
  密码不入库，只用它换一次 JWT 存进 `cloud_token`，断开即清空。连接后市场页聚合服务端技能，
  可发布同步、订阅并代理评分/评论/反馈；不可达时自动回落本地内容。本期服务端市场**发布即上架、无审核**
  （个人共享语义），而本地市场模块实现了审核流（PRD §9.3 的语义落在本地层）。

### 4.2 看板操作

- **列 = 状态**，列顺序固定（`需求池 / 待执行 / 执行中 / 人工阻塞 / 待审核 / 已完成 / 异常`，7 列）。
- **分组泳道**：主分组维度（项目/需求/类型/优先级/负责 Agent/标签/状态）把看板切成横向泳道，可再叠一次
  次维度形成两级分组；泳道头有图标、名称、任务数、待审核数与「⋯」更多菜单，可折叠、拖排、只看/隐藏。
  详见 §3.8 与 §4.9（PRD §7）。
- **拖拽流转**：用 @dnd-kit 把卡片拖到目标列。落点由流转矩阵判定：
  - ✅ 合法 → 直接发请求改状态；
  - 🔒 需表单 → 弹出对应表单（审核 / 停止）；
  - ❌ 禁止 → 仅提示，不改状态。
- **键盘操作**（`apps/web/src/features/board/board-card.tsx`）：
  - `← / →`：在合法目标列之间移动卡片；
  - `⌘ / Ctrl + P`：置顶 / 取消置顶；
  - `Space / Enter`：打开任务详情。
- **RUNNING 卡片**额外显示租约倒计时、进度条与百分比；租约过期会变红。

### 4.3 创建任务

入口：看板工具栏「＋ 新建任务 ▾」、列底「新建任务 / 新建并进待执行」、任务列表页「新建」。

快速创建表单字段（`apps/web/src/features/board/quick-create.tsx`）：

| 字段 | 说明 |
| --- | --- |
| 标题 | 必填，≤200 字 |
| 描述 | Markdown |
| 类型 | 来自 `task_types` 词表 |
| 优先级 | 0–3 |
| 标签 | 逗号分隔，单标签 ≤16 字，每任务 ≤10 个 |
| 自定义字段 | 由已启用字段定义驱动；模板可预填 |

> 普通「新建任务」创建后落 `BACKLOG`；「新建并进待执行」= 创建后再 `transition(READY)` 两步。必填自定义字段未填时，任务留在需求池，补全后可补提交。

### 4.4 任务详情与编辑

点卡片 / `Space` 打开右侧抽屉（`apps/web/src/features/task-detail/*`），含七个 Tab：**概览 / 执行 / 审核 / 依赖 / 评论 / 审计 / 技能**（「技能」为 0919 追加，见 §4.10）。

- **标题**：点击即行内编辑，`Enter` 提交。
- **字段编辑**（概览 Tab「编辑」）：描述、类型、优先级、标签、所需能力、截止时间、自定义字段；仅提交变化过的键；**执行中（RUNNING）禁止编辑**。
- **状态动作**：底部按钮由流转矩阵生成（确认可执行 / 重试 / 退回需求池 / 强制停止 / 审核 / 归档 / 删除等）。危险动作（停止、删除）需二次确认。
- **执行 Tab**：当前与历史 Run、按 Run 归组的产出物、可展开日志（实时有新输出提示）。
- **评论**：仅「新增」，人写评论走 `POST /tasks/:id/comments`。

### 4.5 审核流程（核心）

这是「强制人工审核」的人机界面，三种进入方式：看板拖到「待审核」列（弹表单）、任务详情「审核 → / 退回重跑」、审核页行内「审核」。

审核表单（`apps/web/src/features/review/review-form.tsx`，720px 模态）：

1. 上半区展示任务信息、执行摘要、**内嵌 diff 预览**、其他产出物列表、历史审核意见；
2. 必填三项：审核建议 `suggestion` / 原因 `reason` / 详情 `detail`（单字段 ≤2000 字）；
3. 结论单选：**通过（APPROVE）** / **驳回（REJECT）**；
4. 驳回专属：退回目标 `returnTo`（READY / BACKLOG，默认 READY）+ 可选优先级调整；
5. 草稿按任务自动保存；`review_reuse_last_opinion`（默认开）预填上次三项。

提交：`POST /api/v1/tasks/:id/review`。

- 通过 → 任务 `DONE`，解锁下游依赖。
- 驳回 → 任务退回 `BACKLOG` / `READY`，Agent 可重新认领执行。

**审核页（队列）**：仅列出 `REVIEW` 且未归档任务；提交一条后自动跳到下一条未审核任务。

### 4.6 筛选、搜索与排序

- **任务列表页**：
  - 筛选面板：状态 / 优先级 / 类型 / 标签 / 自定义字段 / 归档 / 依赖状态；
  - 搜索框：标题 / 描述 / ID，300ms 防抖，≤120 字；
  - 排序白名单：id / 优先级 / 状态 / 创建时间 / 更新时间（点列头切升降）；
  - 分页：默认 50，上限 200。

### 4.8 登录与账号管理（0919 §3）

代码在 `apps/web/src/features/auth/`（该目录 README 记录了全部次级决策）。

- **首启**：库内无账号时，登录页切到「初始化管理员账号」表单创建首个 ADMIN（`POST /auth/init`）。
  后端没有「是否已初始化」的探测接口，所以靠 `init` 返回 403（「初始化接口已关闭」）自动切回登录表单。
- **登录**：`POST /auth/login` 换账号 JWT，存 localStorage（`atb.auth.token`）；账号信息只留内存，
  进壳用 `GET /auth/me` 换取。任何业务请求 401 → 清会话回登录页；403 `MUST_CHANGE_PASSWORD` → 强制改密页。
- **改密**：表单含当前/新/确认三项（后端必校验 `current_password`）。管理员重置他人密码后，
  该账号下次登录被拉到改密页。
- **切换账号**（顶栏账号下拉）：本机只记住用户名（最多 10 个，`atb.auth.accounts`），**不存密码**；
  「切换」= 登出 → 回登录页预填用户名。
- **用户管理**（仅 ADMIN 可见）：列表 / 创建 / 重置密码 / 禁用启用。
- **免登录兼容路径**：本地无登录态时回落到注入的 `ATB_UI_TOKEN`（内置 `__local__` 账号），
  桌面壳与 e2e 行为不变；一旦登录，JWT 优先于注入值。

### 4.9 分组管理与看板分组操作（0919 §7）

**分组页 `#/projects`**（`features/projects/projects-page.tsx`）：卡片网格（名称色点+图标、描述、创建时间、状态），

- **跨分组拖拽**（`useCrossGroupDrag.ts`）：落点若改变了归属（项目/需求），弹确认框后再提交；纯改状态直接发流转。
- **多项目作用域**：工具栏项目切换器多选，选中 >1 时主维度自动切为 project。

### 4.10 技能库与编辑器（0919 §8）

- **技能库页 `#/skills`**：搜索（名称/描述/标签）+ 类型 + 状态筛选；卡片菜单含
  新建（空白 / 从模板起步）、导入（`.atskill` / `SKILL.md` / Cursor `.mdc`）、复制现有技能、发布到市场、导出。
- **编辑器页**有四个模式 Tab：**可视化 / 结构化 / 源码 / 流程图视图**，共用同一份块 JSON；
  头部是名称·版本·状态 + 保存草稿 + 发布。发布前校验要求描述不为空。
- **块类型** 15 类（清单见 §3.9，注册点 `features/skills/meta.ts:50`）；
  「人工块」（`human`）是 BLOCKED 的来源（见 §3.2），流程图视图用 @xyflow/react 渲染有向图。
- **技能详情抽屉**五个 Tab：概览（内容块预览）/ 版本（回滚到此版）/ 测试（输入→运行→logs/output）/
  MCP 依赖（配置片段复制）/ 绑定任务；头部有「导出 .atskill」。
- **任务侧绑定**：任务详情「技能」Tab 增删绑定（全量 PATCH `{skills}`），候选含草稿与已发布（排除归档），
  按绑定版本下发给 Agent。卡片上的技能角标只反映**手动绑定**，无推荐逻辑（PRD §10.2 未实现）。
- **发布到市场**对话框：可见性（私有=仅记录不上架 / 公开=提交审核）+ 分类 + license + 兼容客户端多选；

### 4.11 市场与订阅（0919 §9）

- **市场首页 `#/market`**：搜索 + 分类 / 类型 / 评分 / 兼容客户端筛选，排序 4 种
  （热门 / 最新 / 评分 / 订阅数）；版式为「🔥 热门大卡（订阅数前 3）+ 🆕 最新 3 条 + 全部列表（每次多 12 条）」。
- **服务端不可达时静默回落本地市场**，页顶给一条 `⚠ 服务端市场不可达，已回落本地市场` 提示（`market.service.ts:177`），
  不打断浏览。
- **详情页 `#/market/detail?id=`**：四个 Tab（说明 / 内容 / 评论 / 使用记录），右上是
  订阅（订阅 / 更新 / 已订阅）、收藏 ☆、`⋯`（提交反馈 / 举报）。`DELISTED` 显示
  「已下线，快照可继续使用」横幅；评分在「使用记录」里点星提交。
- **个人中心 `#/market?tab=personal`**：我的订阅 / 我的收藏 / 我的发布 / 我的反馈四个分区，
  不进主导航。订阅会在本地生成技能快照；取消订阅保留快照但不再同步更新。
- **审核语义只在本地层**：本地发布 `public` → `PENDING_REVIEW`，ADMIN 审核 `approve → PUBLISHED / reject → REJECTED`；
  非 `PUBLISHED` 的 listing 仅发布者本人与 ADMIN 可见。服务端市场则是**发布即上架**，无审核环节。

## 5. Agent 接入指南（MCP / REST）

### 5.1 接入前提：签发 Agent Token

在「设置 → Token」中签发，得到形如 `atb_xxxxxxxx...` 的 Token（明文仅出现一次）。为 Token 指定 **capabilities**（如 `language:go`、`framework:react`、`repo:atb`、`tool:docker`），用于匹配可认领任务。

调用 MCP / Agent REST 时，在请求头携带：`Authorization: Bearer <agent_token>`。

### 5.2 执行闭环（认领 → 执行 → 完成 → 审核）

```
1. list_ready_tasks      → 查可领取任务（按能力/类型过滤，不含租约）
2. claim_next_task       → 原子认领 + 建立租约（RUNNING，租约时长 lease_ttl_minutes）
3. get_task              → 取任务详情（含自定义字段 / 依赖 / 历史审核）
4. update_progress       → 更新进度（需 task_id+run_id+lease_id 三元组）
   append_log            → 追加执行日志
   heartbeat             → 续租（避免租约过期）
5. complete_task         → 完成回写 → 任务进入 REVIEW（幂等）
   fail_task             → 执行失败 → 任务进入 FAILED
   （交付物需在 complete 前经 POST /artifacts 上传，link 类型直接插入）
   技能里有「人工块」时 → REST `POST /tasks/:id/blocked` 上报，任务转 BLOCKED
6. [人审核]              → APPROVE → DONE / REJECT → 退回
   [人处理阻塞]          → BLOCKED → READY（重试，可重新认领）或 → BACKLOG
7. get_review_feedback   → 读取最近审核意见（驳回原因等）
```

> 所有写回工具必须携带 **三元组 `task_id + run_id + lease_id`**（只读工具除外），用于租约校验与防越权。
> BLOCKED 上报**只有 REST 入口、没有 MCP 工具**（`agent.controller.ts:93`）：MCP 会话内如需人工块，
> 由客户端直接 `POST /api/v1/tasks/:id/blocked`，体为 `{task_id, run_id, lease_id, block_id,
> block_title?, instruction}`；同一三元组在上报后即刻失效（再回写 complete/fail 回 410）。

### 5.3 MCP 工具清单

MCP 走无状态 Streamable HTTP，端点 `POST /mcp`（仅 Agent 作用域）。暴露 9 个工具（`apps/api/src/mcp/agent-tools.ts`）：

| 工具名 | 作用 | 等价 REST |
| --- | --- | --- |
| `list_ready_tasks` | 查可领取任务（只读，无租约） | `GET /api/v1/tasks/ready` |
| `claim_next_task` | 原子认领 + 建租约 | `POST /api/v1/tasks/claim` |
| `get_task` | 任务详情（含审核意见/字段/依赖） | `GET /api/v1/tasks/:id`（any 可读） |
| `update_progress` | 更新进度（需三元组） | `POST /api/v1/tasks/:id/progress` |
| `append_log` | 追加日志 | `POST /api/v1/tasks/:id/logs` |
| `complete_task` | 完成回写 → 待审核（幂等） | `POST /api/v1/tasks/:id/complete` |
| `fail_task` | 失败上报 → 异常 | `POST /api/v1/tasks/:id/fail` |
| `heartbeat` | 续租 | `POST /api/v1/tasks/:id/heartbeat` |
| `get_review_feedback` | 最近审核意见 | `GET /api/v1/tasks/:id/review-feedback` |

### 5.4 REST 等价接口（Agent 组）

前缀 `api/v1`，均 `@AuthScope('agent')`（`apps/api/src/agent/agent.controller.ts`）：

- `GET /tasks/ready` 可领取任务
- `POST /tasks/claim` 认领
- `POST /tasks/:id/progress` 进度
- `POST /tasks/:id/logs` 日志
- `POST /tasks/:id/complete` 完成
- `POST /tasks/:id/fail` 失败
- `POST /tasks/:id/blocked` 人工块上报 → BLOCKED（**无对应 MCP 工具**，见 §5.2）
- `POST /tasks/:id/heartbeat` 续租
- `GET /tasks/:id/review-feedback` 审核意见
- `POST /artifacts` 上传产出物（仅 Agent）

### 5.5 租约与心跳

- 认领成功后建立租约，时长 `lease_ttl_minutes`（默认 30 分钟）。
- Agent 须按 `heartbeat_interval_seconds`（默认 300 秒）周期性 `heartbeat` 续租。
- **租约过期**任务自动回到 `FAILED`，Agent 需重新认领；并发认领由 SQLite 事务原子保证（单连接 `connection_limit=1`）。

### 5.6 Cursor 专用：外部调度脚本（`scripts/cursor-agent-poll.mjs`）

Cursor 没有「到点自动调 MCP 工具」的调度器，其 MCP 工具只在一次会话内由模型调用（产品文档十四章）。本仓库提供零依赖调度脚本，由系统级调度周期拉起，走 REST 完成一次完整的**认领 → 执行 → 回写**：

```bash
ATB_URL=http://127.0.0.1:7788 \
ATB_AGENT_TOKEN=atb_xxx \
ATB_CAPABILITIES="language:go,tool:maven" \
ATB_EXEC='cursor-agent -p "{prompt}" --print' \
node scripts/cursor-agent-poll.mjs
```

脚本行为：

- `claim` 认领一个任务（队列空则静默退出 0，等下次调度）；并行执行多任务由调度器并行拉起多个进程实现。
- 自动读取该任务历史审核意见（`review-feedback`），连同标题、描述拼成 `{prompt}` 占位符注入工作命令；也可用 `{title}` `{description}` `{task_id}`。
- 执行期间按服务端建议周期心跳续租、把工作命令输出增量回传为 Run 日志；心跳失败（租约失效或被强制停止）自动终止工作进程。
- 工作命令退出码 0 → `complete` 回写（摘要取输出末尾）；可设 `ATB_ARTIFACTS_DIR` 把目录内文件作为产物一并上传。非 0 或超时（`ATB_TIMEOUT_SECONDS`，默认 1800 秒）→ `fail` 回写。
- 端到端行为由 `apps/api/src/__tests__/cursor-scheduler.e2e.test.ts` 覆盖（空队列 / 成功含产物 / 失败三条路径）。

macOS launchd 示例（`~/Library/LaunchAgents/com.atb.cursor-poll.plist`，每 5 分钟一轮）：

```xml
<key>ProgramArguments</key>
<array>
  <string>/usr/bin/env</string>
  <string>ATB_AGENT_TOKEN=atb_xxx</string>
  <string>ATB_EXEC=cursor-agent -p "{prompt}" --print</string>
  <string>ATB_QUIET=1</string>
  <string>node</string>
  <string>/path/to/agent-task-board/scripts/cursor-agent-poll.mjs</string>
</array>
<key>StartInterval</key>
<integer>300</integer>
```

> 注意：Cursor 的云端 / 后台 Agent 运行在用户机器之外，访问不到 `127.0.0.1:7788`，不在支持范围内（十五章网络边界不为此放宽）。若选择在 `.cursor/rules/*.mdc` 中写会话规则驱动认领，那不是无人值守方案，文案与预期请勿写成「自动执行」。

## 6. 数据安全与管理

### 6.1 本地优先与网络边界

- 后端仅监听 `127.0.0.1`，不暴露到局域网 / 公网。
- UI Token 与 Agent Token 作用域隔离，互不可调。
- 产出物原始内容经**一次性 HMAC 签名 URL**（60 秒）访问；响应强制 `nosniff` + `CSP: sandbox` + `CORP: cross-origin`，防止 Agent 内容被当脚本执行。
- 资源路径做白名单 + `realpath` 前缀校验，防目录穿越。
- CORS 精确匹配（`tauri://localhost` / `http://tauri.localhost`，开发加 `localhost:5173`；允许的Methods含 `PUT`），不回显任意 Origin、拒 `Origin: null`。
- **唯一的对外出站是服务端市场**：本地不监听额外端口，只在 `cloud_enabled` 时由本地后端向
  `cloud_url` 发请求（`/cloud/v1/*`）。未连接或服务端不可达时市场页回落本地内容（§4.11），
  任务/技能/账号数据不会被动上传——上传只发生在「设置 → 服务端市场」连接与「发布到服务端市场」。
- 服务端自身也只绑 `127.0.0.1:7789`，对外一律经边缘层（`EDGE_MODE=caddy` 的 Caddy，或既有边缘反代）。

### 6.2 备份与恢复

- **只有手动备份**：设置 → 备份 →「立即备份」（`POST /settings/backup`），产物是 `VACUUM INTO` 的一致性快照
  （文件名 `atb-YYYYMMDD-HHMMSS.db`，gzip 后落备份目录）。
- **无自动备份**：`backup_time` / `backup_keep` 两个键存在于设置契约，但没有任何调度器读它们，
  设置页也不暴露（见 §4.7）——需要定时备份请自行对备份目录做外部 cron/rsync。
- **恢复**（`POST /settings/backups/:name/restore`）：整库换文件。点确认后服务端先对当前库做一次安全备份，
  失败即中止恢复，再覆盖为所选备份；文件名不匹配 `^atb-\d{8}-\d{6}\.db$` 的条目会被接口拒绝（400 `INVALID_BACKUP_NAME`）。
- **导入也会前置备份**：数据导入确认前服务端先备份当前库，结果页给出该文件名。

### 6.3 数据导入导出

- 导出：`POST /data/export` → JSON 文件下载（`Content-Disposition` 带文件名）。
- 导入：`POST /data/import`（multipart）；导入预览确认后应用，成功后清空任务 / 字段 / 模板 / 备份 / 审计 / 标签缓存。

### 6.4 审计日志

- 关键动作（签发 Token、设置变更、审核提交、数据导入等）写入审计流。
- 查看：设置 → 日志与审计，`GET /audit`，每页固定 50 条。

## 7. 故障排查与常见错误码

### 7.1 启动类

| 现象 | 原因 / 处理 |
| --- | --- |
| 端口被占用 | 用 `ATB_PORT` 环境变量或 `config.json` 的 `port` 换端口 |
| 数据库未初始化 | 先执行 `npm run prisma`（运行 `apps/api/scripts/db.mjs`） |
| 桌面端无法打 .app | 需先 `npm install -D @tauri-apps/cli`，再 `npx tauri build` |
| 前端连不上后端 | 确认 sidecar 已输出 `ATB_READY`；检查 `127.0.0.1:7788` 可达 |

### 7.2 接口错误码

| 状态码 | 含义 | 处理 |
| --- | --- | --- |
| 401 UNAUTHORIZED | Token 缺失 / 无效 / 已撤销 | 重新签发 Agent Token；确认 UI Token 已注入 |
| 403 FORBIDDEN | 作用域不匹配（UI Token 调 Agent 接口，或反之） | 用正确作用域的 Token |
| 409 ILLEGAL_TRANSITION | 状态流转非法（服务端兜底） | 检查流转矩阵，勿直接拖到 RUNNING / 拖出 DONE |
| 410 LEASE_EXPIRED | 租约已过期 | Agent 重新认领任务 |
| 413 ARTIFACT_TOO_LARGE | 产出物超过 `artifact_max_mb` 或单 Run 上限 | 调大设置或拆分交付 |
| 422 VALIDATION_FAILED | 必填自定义字段缺失 / 设置键非法 / 值越界 | 补齐必填项或修正设置 |

### 7.3 操作异常

- **拖拽没反应 / 被拒**：目标流转属「禁止」或需「表单」，属正常拦截。
- **执行中任务不能编辑字段**：`RUNNING` 状态锁定编辑，停止或完成后再改。
- **审核页为空**：确认存在 `REVIEW` 且未归档任务；铃铛红点 = 有待审核。
- **WebSocket 断线**：前端自动指数退避重连（1s→30s），重连后全量刷新看板 / 任务 / 通知 / 打开的抽屉。
- **数据库锁（SQLITE_BUSY）**：并发由单连接 + 事务保证；避免在外部工具直接写同一 db 文件。
