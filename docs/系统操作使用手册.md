## 1. 概述

### 1.1 产品定位

Jarvis Workbench 是一款**纯本地的桌面任务看板 + 技能工作台**：人负责建需求、拆任务、写技能；Agent（外部智能体）通过 MCP / REST 认领并执行任务，**执行结果必须经过人工审核**后才算生效。业务数据全部写入本机 SQLite（由桌面壳托管的本地 sidecar 读写）。技能有三个来源（需求.md §9.1，v0.0.4 W2）：**默认技能**（随安装包预置、只读，当前 94 条）、**自定义技能**（本地创作）与**三方技能**（导入 `.atskill` / `SKILL.md` / Cursor `.mdc` 文件）。

核心原则：

- **人建任务，Agent 执行**：任务的生命周期由人和 Agent 分工驱动（会话直建与需求拆解链路见 §4.11、§4.12）。
- **强制人工审核**：Agent 完成交付后任务进入「待审核」，必须由人通过 / 驳回，结果才会落定。
- **本地优先、纯单机**：后端仅监听 `127.0.0.1`，任务、分组、技能、审核与审计全部在本机；sidecar 没有任何对外出站请求。
- **本机单用户**：v0.0.4（W1a）起没有账号体系——无注册/登录/角色/多账号隔离，全部数据归本机唯一使用者，鉴权只用于区分「人用的 UI」与「Agent 用的接口面」（见 §3.4）。

### 1.2 适用对象

| 角色 | 典型操作 |
| --- | --- |
| **本机使用者（人）** | 在看板上建任务、拖拽流转、管理分组与设置、审核 Agent 交付、创作与导入技能（v0.0.4 起无账号/角色概念，本机使用者即唯一管理员） |
| **Agent 接入开发者** | 签发 Token、通过 MCP/REST 认领任务、回写进度与产物、读取审核意见、发起需求拆解与会话直建 |
| **运维 / 部署** | 安装依赖、启动 sidecar、桌面打包与分发（纯本地，无服务端部署） |

### 1.3 系统架构与运行边界

```
┌──────────────┐      ┌───────────────────────────┐      ┌─────────────────┐
│   @atb/web   │      │  @atb/desktop (Tauri 2)   │      │  外部 Agent     │
│ React + Vite │◄─────┤  窗口 / 托盘 / 单实例     │◄─────┤  MCP / REST     │
│ 左导航+顶栏  │ REST │  Rust 壳（不承载业务数据）│      │  认领并执行任务 │
└──────────────┘      └─────────────┬─────────────┘      └─────────────────┘
                                    │ 托管 sidecar 子进程
                                    ▼
                          ┌───────────────────────────┐
                          │   @atb/api (NestJS 11)    │
                          │  REST + MCP + WebSocket   │
                          │  仅监听 127.0.0.1 : 7788  │
                          │  Prisma 6 + SQLite（本地）│
                          │  ~/.jarvis-workbench      │
                          └───────────────────────────┘
```

关键边界：

- **本地后端 sidecar 仅绑定 `127.0.0.1`**，任何情况下不监听 `0.0.0.0`（`apps/api/src/main.ts:17`）。
- 同一端口（默认 **7788**）复用三条通道：**REST**（`/api/v1`）、**MCP**（`/mcp`，Streamable HTTP，`apps/api/src/mcp/mcp.controller.ts`）、**WebSocket**（`/ws`）。
- **桌面壳（Rust）不存业务数据**，所有读写走 sidecar 的 REST（边界原则见 `apps/desktop/src-tauri/Cargo.toml` 注释）。
- **没有任何对外出站请求**：v0.0.4 起服务端（`apps/cloud`）已整体删除，任务、分组、技能、审核与审计全部留在本机——技能只有三来源（§3.8），默认技能随安装包预置。
- 数据目录 v0.0.4（W1b）起为 `~/.jarvis-workbench`（`apps/api/src/common/paths.ts`），旧目录升级首启自动搬迁（§6.5）。

### 1.4 技术栈

| 应用 | 技术 | 职责 |
| --- | --- | --- |
| `@atb/web` | React 18 + Vite 6 + Tailwind 4 | Tauri 主窗口前端；`@dnd-kit` 拖拽、`@tanstack/react-query` 数据、`zustand` 状态、`@xyflow/react` 流程图与依赖图 |
| `@atb/api` | NestJS 11 + Prisma 6 + SQLite | 本地 sidecar；REST + MCP + WebSocket；`zod` 校验、`winston` 日志审计 |
| `@atb/desktop` | Tauri 2 + Rust | 桌面壳：窗口（1440×900 起、**960×600 最小**）、托盘、单实例、系统对话框、sidecar 进程托管 |

## 2. 安装与启动

### 2.1 环境要求

- **Node.js ≥ 20**（根 `package.json` 的 `engines`）
- **Rust 工具链**（仅桌面端构建需要）：`cargo` 加入 `PATH` → `export PATH="$HOME/.cargo/bin:$PATH"`
- **npm**（使用 workspaces，无需 pnpm/yarn）

### 2.2 开发模式启动

```bash
# 1. 安装依赖（根目录，一次性）
npm install

# 2. 初始化本地数据库（Prisma + SQLite，执行 apps/api/scripts/db.mjs）
npm run prisma

# 3. 启动后端 sidecar（监听 127.0.0.1:7788）
npm run dev:api

# 4. 启动前端（Vite 开发服务器 / Tauri 主窗口）
npm run dev:web
```

> 启动成功后，sidecar 向 stdout 输出唯一一行就绪信号：
> `ATB_READY {"port":7788,"pid":...,"version":...}`，桌面主进程据此确认端口已就绪。

真启动冒烟门禁（v0.0.4 起为 api 片提交前必跑）：`npm run boot:smoke -w @atb/api`
（`apps/api/scripts/boot-smoke.sh`）——拉起真实 sidecar，校验 `ATB_READY`、REST 401 与
默认技能预置落库（`GET /skills?source=default` 的 total ≥ 94）。

本项目为纯本地应用，**没有服务端组件需要启动**（`apps/cloud` 已随 v0.0.4 W1c 删除）。

### 2.3 桌面端打包

```bash
# 仅构建前端 + Rust 二进制（无 .app 外壳）
npm run build            # = nest build (api) && tsc -b && vite build (web)
npm run desktop:build    # cargo build --release，产物 apps/desktop/src-tauri/target/release/atb-desktop

# 打包 macOS .app / .dmg（@tauri-apps/cli 已在根 devDependencies）
npm run build                        # 先构建 api（tsc）+ web（vite）
npm run build:sidecar -w @atb/api    # 装配 sidecar 打包资源（webpack 单文件 bundle + 最小 Prisma 运行时 + 迁移 + node）
cd apps/desktop
export PATH="$HOME/.cargo/bin:$PATH"
npx tauri build          # 产物在 src-tauri/target/release/bundle/；.dmg 若因 osascript 失败，用 scripts/package-release.sh 的 hdiutil 兜底
```

> 发布主路径是推 tag 走 CI（`docs/发布手册.md` §1），上述本地打包是附录路径（§6）。
> 本地全流程也可用 `bash scripts/package-release.sh`（门禁→构建→sidecar→.app→ad-hoc 签名→dmg→冒烟→SHA256）。

### 2.4 安装包签名状态与 Gatekeeper 降级说明（macOS）

**当前发布口径（v0.0.4-beta 系列，最新 `v0.0.4-beta.3`）：产物经 ad-hoc 签名、未公证**（`scripts/package-release.sh` 第 4.5 步 `codesign --force --deep --sign -` + 签名后强制重出 dmg + 验签硬门禁，第 6 步含 `hdiutil verify` 与 dmg 挂载验签；
仍无 Apple Developer 证书/公证，按降级方案交付，不影响功能与验收）。
Apple Silicon 双击不再判「已损坏，无法打开」；首次打开仍会拦「无法验证开发者」，按下方二选一解除。

#### 首次打开被拦截的解除方式（二选一）

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 右键打开 | 右键 `.app` →「打开」→ 弹窗中再点「打开」 | 仅需确认一次，之后正常启动 |
| 终端清除隔离属性 | `xattr -cr "/path/Jarvis Workbench.app"` | 适合批量部署或脚本化场景 |

> 拦截只发生在首次运行 `.app` 时；`.dmg` 的下载、挂载、拷贝均不受影响。

#### 架构说明

**发布链路在 CI**：推 `v*` tag → `.github/workflows/release.yml` 在 Intel 与
Apple Silicon 两台 runner 上各出一份原生包。**本地/CI 内的产物名是带空格的
`Jarvis Workbench_0.1.0_x64.dmg` / `Jarvis Workbench_0.1.0_arm64.dmg`；GitHub 上传后会把空格
替换为点号**（Release 页面上显示 `Jarvis.Workbench_0.1.0_x64.dmg` 等，属正常行为），
Release 内附合并 `SHA256SUMS.txt`——**SUMS 条目按本地空格名登记，Release 资产是点号名，
对账时以 SHA-256 哈希为准、别按文件名精确匹配**
（口径详见 `docs/发布手册.md` §1/§5 与 `docs/v0.0.4/beta真机验证清单.md`）。
**按机器架构选包即可，Apple Silicon 不需要 Rosetta。**
本地兜底打包路径见 `docs/发布手册.md` §6 与 `scripts/package-release.sh`。

#### 升级路径（取得证书后）

在 `tauri.conf.json` 配置 `signingIdentity`，构建后依次执行 `codesign` 签名 → `notarytool` 公证 → `stapler staple` 装订，即可移除上述降级说明，用户双击直开无拦截。

> 付费 Apple Developer 证书 + notarytool 公证为**待拍板升级项**（落地后可消除上表「右键→打开」首启步骤）；未拍板前维持 ad-hoc 签名口径。

### 2.5 端口与访问地址

端口三级决定（优先级从高到低）：

1. 环境变量 `ATB_PORT`
2. `config.json` 中的 `port`
3. 默认 `7788`（`apps/api/src/common/paths.ts`）

前端基址解析顺序：`window.__ATB_API_BASE__` → `__ATB_PORT__`（→ `127.0.0.1:port`）→ `VITE_ATB_API_BASE` → 默认 `http://127.0.0.1:7788`（`apps/web/src/api/env.ts`）。

> v0.0.3 及更早的「服务端市场侧」（7789 端口、`/cloud/v1`、`CLOUD_JWT_SECRET` 等）已随
> `apps/cloud` 删除，本应用不再监听 7788 以外的任何端口。

## 3. 核心概念

### 3.1 任务与七状态

任务固定落在**按状态分列的看板**，每列对应一个状态（`apps/api/src/contract/enums.ts`）。
`BLOCKED` 于 v0.0.4 拍板纳入状态机（需求.md §4.1/§6.2.1），全集 7 个状态，看板相应为 **7 列**：

| 状态 | 标签 | 含义 |
| --- | --- | --- |
| `BACKLOG` | 需求池 | 新建任务默认落此列，尚未可执行 |
| `READY` | 待执行 | 已具备执行条件，等待 Agent 认领 |
| `RUNNING` | 执行中 | Agent 已认领并正在执行（**只能由 Agent 认领产生**） |
| `BLOCKED` | 人工阻塞 | Agent 执行到技能的「人工块」时上报转人工（需求.md §8.4），等人处理后回 `READY` |
| `REVIEW` | 待审核 | Agent 已完成交付，等待人工审核 |
| `DONE` | 已完成 | 审核通过，终态 |
| `FAILED` | 异常/失败 | 被强制停止或执行失败，可重试 |

### 3.2 状态流转规则（谁能动）

流转矩阵是代码化的单一来源（`apps/api/src/contract/transitions.ts`），前后端共用同一份表。
三类结果：**直接生效（direct）**、**需弹表单（form）**、**禁止（forbidden）**。

| 从 \ 到 | BACKLOG | READY | RUNNING | BLOCKED | REVIEW | DONE | FAILED |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **BACKLOG** | — | ✅ direct | ❌ 仅 Agent | ❌ | ❌ | ❌ | ❌ |
| **READY** | ✅ direct(退回) | — | ❌ 仅 Agent | ❌ | ❌ | ❌ | ❌ |
| **RUNNING** | ❌ | ❌ | — | ❌（只由 Agent 端点产生） | ❌ | ❌ | 🔒 强制停止表单 |
| **BLOCKED** | ✅ direct(退回) | ✅ direct(重试) | ❌ 仅 Agent | — | ❌ | ❌ | ❌ |
| **REVIEW** | 🔒 驳回表单 | 🔒 驳回表单 | ❌ | ❌ | — | 🔒 通过表单 | ❌ |
| **DONE** | ❌ 终态 | ❌ 终态 | ❌ | ❌ | ❌ 终态 | — | ❌ 终态 |
| **FAILED** | ✅ direct(退回) | ✅ direct(重试) | ❌ 仅 Agent | ❌ | ❌ | ❌ | — |

要点：

- **RUNNING 只能由 Agent 认领产生**；人直接把卡片拖到「执行中」一律被拒。
- **BLOCKED 只能由 Agent 上报产生**：REST `POST /api/v1/tasks/:id/blocked`，或 MCP 工具
  `block_task`（v0.0.4 W6 新增，见 §5.3；拖拽与按钮路径一律拒）。
  上报同时把当次 Run 置 `FAILED` 并清租约；人工处理后拖回「待执行」重试，或退回需求池。
  Agent 侧可用 `wait_for_resume` 阻塞等待人工恢复（§5.3）。
- **FAILED 只能由「强制停止」表单或租约过期产生**。
- **REVIEW 的出口（→DONE / BACKLOG / READY）只能走审核接口**，不能靠拖拽直接改。
- **DONE 为终态**，不可再流转；归档后可恢复回 BACKLOG/READY。

### 3.3 产出物（Artifact）与强制人工审核

- **产出物**是 Agent 在执行过程中交付的文件或链接（`apps/api/src/contract/enums.ts` 类型：`diff / image / text / log / markdown / json / html / pdf / link / file`）。
- 产出物挂在「执行记录（Run）」上；**没有独立的审核状态字段**——审核发生在**任务**层面。
- Agent 上传文件经 `POST /api/v1/artifacts`（仅 Agent 可调用），单文件上限 `artifact_max_mb`（默认 20MB，单 Run 累计 ≤200MB）；`link` 类型不通过上传，由完成回写直接插入。
- 完成交付：`POST /api/v1/tasks/:id/complete` → 任务 `RUNNING → REVIEW`，并推送「待审核」通知。
- 人工审核：`POST /api/v1/tasks/:id/review`：
  - **通过（APPROVE）** → `DONE`，并解锁下游依赖任务。
  - **驳回（REJECT）** → 退回 `BACKLOG` 或 `READY`（必填 `return_to`），任务重新可执行。
- 查看交付内容：前端通过 `POST /artifacts/:id/sign` 换取**一次性签名 URL**（60 秒有效）再拉取原始内容；diff 预览走 `GET /artifacts/:id/diff`。

### 3.4 鉴权与作用域（UI Token / Agent Token）

v0.0.4（W1a）账号体系移除后，鉴权只剩**两面 Token**，全部走 `Authorization: Bearer <凭证>`
（守卫在 `apps/api/src/auth/auth.guard.ts`，只回答「是不是合法 token」，没有 accountId、JWT 会话与角色语义）：

| 凭证 | 用途 | 如何获得 | 说明 |
| --- | --- | --- | --- |
| **UI Token** | 前端全部接口 + WebSocket `/ws` | 生产：Tauri 主进程生成后经环境变量 `ATB_UI_TOKEN` 注入 sidecar 与 WebView（`window.__ATB_UI_TOKEN__`，不落盘）；开发态：退化为 `dataDir/dev-ui-token` 文件（0600），由 `vite.config.ts` 读走注入前端（`apps/api/src/common/ui-token.ts`） | 固定代表「本机的人」，≥32 字节 |
| **Agent Token** | Agent 经 MCP/REST 接管的接口 | 在「设置 → Token」中签发，格式 `atb_` + 40 位 base62，明文仅返回一次（`contract/ids.ts`） | 本机单用户，不再绑定账号；归属按 `api_tokens.id` 记在 Run 上 |

守卫规则：

- **两套接口面互斥**：Agent Token 调用户接口 403；UI Token 调 Agent 写回接口 403（`@AuthScope('agent'|'ui')`，`auth.scope.ts`）。
- 撤销 Agent Token 为「吊销」（置 `enabled = 0`）而非删行（`task_runs.token_id` 要保留执行归属）；无重新启用接口。
- `last_used_at` 同一 Token 一小时内最多落库一次（避免审计变成轮询日志）。
- Agent Token 可携带 **能力（capabilities）**，命名空间 `language / framework / repo / tool`，格式 `namespace:value`，用于过滤可认领任务。
- 401 的三种情形：缺凭证 / Token 已吊销 / 凭证无效。没有「账号被禁用」「强制改密」这类状态。

### 3.5 自定义字段

字段定义（`apps/api/src/field-defs/*` + `contract/custom-fields.ts`）：

- `key` 唯一，正则 `^[a-z][a-z0-9_]{1,31}$`；`type` 枚举：`text / textarea / number / select / multiselect / date / bool / url`。
- `key` 与 `type` 保存后**不可改**；删除仅当无任务引用，否则应「停用」。
- 全表最多 **2 个** `show_on_card` 字段（仅 `text/number/select/bool`），用于看板卡片展示。
- `required` 字段在任务进入「待执行（READY）」前必须填齐，否则流转被拒（422）。
- `applies_to` 为空表示适用所有任务类型。

| `artifact_max_mb` | int 1–200 | 20 | ✓ |
| `backup_time` | `off` 或 `HH:MM` | `03:00` | ✓ |

| `log_retention_days` | int 1–90 | 14 | ✓ |
| `log_level` | debug/info/warn/error | info | ✓ |

### 3.7 分组（Group）与看板分组（需求.md §5、§6）

v0.0.4（W1b）起 **Project 已整体改名 Group**：Prisma 模型 `Group`（表 `groups`）、
`tasks.group_id`（原 `project_id`）、REST 前缀 `/api/v1/groups`（`apps/api/src/groups/*`），
UI 也一律叫「分组」——「数据模型仍叫 project」的旧口径作废。三个易混概念：

| 标识 | 语义 | 落在哪 |
| --- | --- | --- |
| `group_id` | 任务的**归属**字段；跨泳道拖拽会改写它（`patchForLane`） | 任务表 |
| `groupIds` | **作用域**多选过滤器，空数组 = 全部；看板与任务列表页共用 | 看板工具栏的分组切换器；偏好持久化到 `PUT /prefs/board.grouping` |
| `grouping` | **呈现层**偏好：主/次维度、泳道顺序、折叠、组内筛选 | 同上 |

- 分组维度实际 7 个：分组 / 需求（父任务）/ 类型 / 优先级 / 负责 Agent / 标签 / 状态（标签可一卡多组；`features/board/grouping/dimensions.ts`）。
- 分组形态支持三种：单级泳道、主+次**两级**、列表分节；列表视图目前只吃主维度。
- **默认分组**：预置一行 `grp_default`（W1-D1，迁移 0009 植入），不可删除、不可归档；预置组之外上限 **50 个活跃分组**（归档不占额，`groups.service.ts:12`）。
- 归档（W4 §5.6）：`status` ACTIVE/ARCHIVED + `archived_at` 配对，`POST /groups/:id/archive|unarchive`；归档分组不进候选，组内任务不进认领队列；删除可选「把任务迁走」或「连任务一起删」。
- **偏好持久化是双层**（`grouping/useGroupingState.ts`）：写操作先落 localStorage
  （`atb.board.grouping`），再镜像到 `PUT /api/v1/prefs/board.grouping`；sidecar 不可达时静默留在本地，
  启动时 `hydrateGroupingPrefs()` 用库里的值覆盖本地（读到合法值才覆盖）。v0.0.3 遗留的
  旧 localStorage 分组键在首启被一次性改写（W1-D2）。

### 3.8 技能与三来源（需求.md §9）

- **技能**＝可复用的执行说明，7 类（`prompt / steps / workflow / flow / script / knowledge / composite`，
  `apps/web/src/features/skills/meta.ts:25`），正文由 **15 类块**组成（prompt/step/decision/loop/parallel/
  tool/knowledge/script/subskill/human/input/output/constraint/error_handler/comment，注册点 `meta.ts` 的
  `BLOCK_KIND_META`），**可视化 / 结构化 / 源码三种编辑模式 + 流程图画布视图**共用同一份块 JSON（W3，见 §4.10）。
- **三来源**（W2 §9.1，`skills.source_type`，`apps/api/src/skills/skills.dto.ts:23`）：
  - `default` 默认技能：随安装包预置、**只读**（三模式与画布仅供查看，页顶横幅提示可「复制为自定义技能」改造）；
    当前预置 **94 条**（93 条千问工作台迁移 + code-review，种子 `default-skills.ts`，真启动落库由 `boot:smoke` 门禁校验）。
  - `custom` 自定义技能：本地创建/复制/模板起步。
  - `imported` 三方技能：导入 `.atskill` / `SKILL.md` / Cursor `.mdc`（r2：不记录「导入来源」）。
- **唯一 ID、允许重名**（r2 §9.2）：`skills.name` 无唯一约束，身份由主键 `id`（终身不变、随导出/导入持久）决定；导入冲突按「同 ID」判定。
- **版本**：语义化版本，「发布」产生版本快照（纯本地动作，无市场上架/审核语义），可回滚；测试用例随版本快照，可批量运行（`POST /skills/:id/test`）。
- **技能 → 任务**：任务详情「技能」Tab 绑定；Agent 认领时技能正文与 MCP 依赖随任务下发。
  卡片上的技能角标是**手动绑定**的结果，没有「按任务描述推荐技能」的逻辑。
- **人工块**（human 块）执行时会把任务从 RUNNING 置为 **BLOCKED**，等人处理后回 READY（见 §3.2）。

### 4.2 看板操作

| 字段 | 说明 |
| --- | --- |

### 4.4 任务详情与编辑

- **字段编辑**（概览 Tab「编辑」）：描述、类型、优先级、标签、所需能力、截止时间、自定义字段；仅提交变化过的键；**执行中（RUNNING）禁止编辑**。
- **状态动作**：底部按钮由流转矩阵生成（确认可执行 / 重试 / 退回需求池 / 强制停止 / 审核 / 归档 / 删除等）。危险动作（停止、删除）需二次确认。

### 4.5 审核流程（核心）

这是「强制人工审核」的人机界面，三种进入方式：看板拖到「待审核」列（弹表单）、任务详情「审核 → / 退回重跑」、审核页行内「审核」。

审核表单（`apps/web/src/features/review/review-form.tsx`，720px 模态）：

1. 上半区展示任务信息、执行摘要、**内嵌 diff 预览**、其他产出物列表、历史审核意见；
2. 必填三项：审核建议 `suggestion` / 原因 `reason` / 详情 `detail`（单字段 ≤2000 字）；
3. 结论单选：**通过（APPROVE）** / **驳回（REJECT）**；
4. 驳回专属：退回目标 `returnTo`（READY / BACKLOG，默认 READY）+ 可选优先级调整；
5. 草稿按任务自动保存；`review_reuse_last_opinion`（默认开）预填上次三项。

提交：`POST /api/v1/tasks/:id/review`。

- 通过 → 任务 `DONE`，解锁下游依赖。
- 驳回 → 任务退回 `BACKLOG` / `READY`，Agent 可重新认领执行。

**审核页（队列）**：仅列出 `REVIEW` 且未归档任务；提交一条后自动跳到下一条未审核任务。

### 4.11 需求拆解链路（需求.md §7，v0.0.4 W7 新增）

「一段需求 → 一组带依赖的任务草案」的人机确认链路，Agent 侧发起、人侧确认：

1. **Agent 开始拆解**：MCP `board.begin_breakdown`（需求原文 + 拟拆任务数），过程中
   `board.report_progress` 报阶段进度、`board.report_task_draft` 逐条上报任务草案
   （标题/优先级/技能名/验收标准/草案间依赖 ref）、`board.finish_breakdown` 收尾转「待确认」；
   `board.cancel_breakdown` 可撤。技能名解析撞重名时有歧义提示与「用户重选即消歧」规则（r3 §7.5）。
2. **人侧待确认覆盖层**（`features/breakdown/breakdown-overlay.tsx`，覆盖内容区、不是独立路由；
   多会话并发展开时切换器带进行中红点；拆解类通知 kind 后端尚未落库，见 §4.8）：
   进度清单 + 草案卡片流 + **草案依赖流程图**（§7.3），
   多会话并发用会话切换器；草案支持**最小编辑**（增删改、调依赖，检出环后禁确认；
   走服务端写端点 PATCH/DELETE `/api/v1/breakdown/sessions/:id/drafts/:ref`，乐观更新 + 失败回滚，
   单条可「重新生成」）与验收标准编辑。
3. **确认创建 / 取消**：确认后弹 **5 秒撤销窗口**（§7.8：倒计时归零才真正 `POST confirm`，
   期间点「撤销」零副作用）；确认后生成父任务（需求）+ 子任务与依赖边。`reviewing` 超 7 天未确认、
   `receiving` 超 30 分钟无进展由定时任务收敛（`jobs/breakdown-timeout.job.ts`，超时不可再确认）；
   抢先流转后写端点统一 409。
4. REST 读侧：`GET /api/v1/breakdown/sessions[/:id]`；WS 有 `draft_updated` 等事件驱动覆盖层刷新。

### 4.12 会话直接创建任务（需求.md §8，v0.0.4 W8 新增）

Agent 在会话中直接建任务（不等认领队列），闭环含三种确认模式与撤销：

- **入口**：MCP `board.create_task` / `board.create_tasks_batch`（可带 `confirmation_mode` 参数）；
  REST `POST /api/v1/creation-requests` 等创建/读/决策端点为 **UI 作用域**（`@AuthScope('ui')`，供前端卡片
  回传决策与列表展示）；读侧 `GET /creation-requests`、
  决策回传 `POST /creation-requests/:id/decision`（create / edit+改后载荷 / cancel），
  Agent 可用 `board.get_creation_status` 轮询、`board.wait_for_confirmation` 阻塞等待（另有 5 秒宽限）。
- **三模式**（优先级：请求参数 ＞ 设置 `agent_creation_mode` ＞ 默认轻确认；设置入口在「设置 → 通用 →
  Agent 创建任务」，§4.7）：
  - `direct` 直接创建：不弹卡片，但**重复检测命中时升级为轻确认卡片**（§8.5）；
  - `light` 轻确认：右下角浮层卡片（`features/creation/creation-card.tsx`），
    「[取消][编辑][创建]」+ 倒计时条，超时（`light_confirm_timeout_seconds`，默认 30s）按不创建处理；
  - `silent` 静默创建：不弹卡片、仅发通知（kind `creation_request`），保留 5 秒撤销。
- **5 秒撤销浮层**（§8.6，direct/silent）：卡片「✅ 任务已创建 · T-xxxx · [查看任务] [撤销]」，
  观察通道是 WS；撤销即 `DELETE /api/v1/tasks/:id`，服务端守卫「仅 origin=agent 且未领取」可撤，
  窗口内成功则就地转「已撤销」。任务读侧（`/tasks`、`/board`）带 `origin_type` 标识直建来源。
- **留痕**：`agent_sessions` 按 session_id upsert，`task_creation_logs` 记创建/取消/超时各一条（§8.7）。

## 5. Agent 接入指南（MCP / REST）

### 5.1 接入前提：签发 Agent Token

在「设置 → Token」中签发，得到形如 `atb_xxxxxxxx...` 的 Token（明文仅出现一次）。为 Token 指定 **capabilities**（如 `language:go`、`framework:react`、`repo:atb`、`tool:docker`），用于匹配可认领任务。

调用 MCP / Agent REST 时，在请求头携带：`Authorization: Bearer <agent_token>`。

### 5.2 执行闭环（认领 → 执行 → 完成 → 审核）

```
1. list_ready_tasks      → 查可领取任务（按能力/类型过滤，不含租约）
2. claim_next_task       → 原子认领 + 建立租约（RUNNING，租约时长 lease_ttl_minutes）
3. get_task              → 取任务详情（含自定义字段 / 依赖 / 历史审核）
4. update_progress       → 更新进度（需 task_id+run_id+lease_id 三元组）
   append_log            → 追加执行日志
   heartbeat             → 续租（避免租约过期）
5. complete_task         → 完成回写 → 任务进入 REVIEW（幂等）
   fail_task             → 执行失败 → 任务进入 FAILED
   （交付物需在 complete 前经 POST /artifacts 上传，link 类型直接插入）
   技能里有「人工块」时 → MCP `block_task`（或 REST `POST /tasks/:id/blocked`）上报，任务转 BLOCKED；
   需等人处理时可 `wait_for_resume` 阻塞等待恢复
6. [人审核]              → APPROVE → DONE / REJECT → 退回
   [人处理阻塞]          → BLOCKED → READY（重试，可重新认领）或 → BACKLOG
7. get_review_feedback   → 读取最近审核意见（驳回原因等）
```

> 所有写回工具必须携带 **三元组 `task_id + run_id + lease_id`**（只读工具除外），用于租约校验与防越权。
> BLOCKED 上报有 **MCP 与 REST 双入口**（v0.0.4 W6）：REST `POST /api/v1/tasks/:id/blocked`
> （`agent.controller.ts:93`），体为 `{task_id, run_id, lease_id, block_id, block_title?, instruction}`；
> MCP 侧 `block_task` 同一语义（`mcp/agent-tools.ts`）。同一三元组在上报后即刻失效
> （再回写 complete/fail 回 410）。

### 5.3 MCP 工具清单

MCP 走无状态 Streamable HTTP，端点 `/mcp`（仅 Agent 作用域；当前不落会话，`GET`/`DELETE /mcp` 回 405，
不支持独立 SSE 流）。v0.0.4（W6/W7/W8）后共 **25 个工具**（`apps/api/src/mcp/agent-tools.ts`）：

**贾维斯唤醒词（v0.0.4 #46）**：接入本 MCP server 后，不必逐次写提示词驱动工具调用——
在客户端对话里说「贾维斯，…」（如「贾维斯，创建一个任务：明天发布」）即进入 Jarvis Workbench
工作模式，Agent 直接用看板工具完成请求、不反问是否使用工具；与唤醒无关的普通对话不会触发看板工具。
两种语义由设置键 `mcp_wake_mode` 切换（「设置 → Token → 贾维斯唤醒模式」，§3.6、§4.7）：

- **单次对话（single，默认）**：本轮唤醒对应的操作完成即退出工作模式；
- **连续对话（continuous）**：唤醒后保持工作模式，把后续请求继续当作看板操作处理，
  直到说「退出贾维斯」（或同义退出指令）。

协议全文由服务端在 MCP 连接的 `initialize` 响应（instructions）里整段下发，客户端 Agent 自动遵循，
无需手工配置。唤醒模式每次连接现读：改动后在客户端下一次 initialize（重连或新开会话）生效，
不必重启 sidecar。

### 5.4 REST 等价接口（Agent 组）

前缀 `api/v1`，均 `@AuthScope('agent')`（`apps/api/src/agent/agent.controller.ts`）：

- `GET /tasks/ready` 可领取任务
- `POST /tasks/claim` 认领
- `POST /tasks/:id/progress` 进度
- `POST /tasks/:id/logs` 日志
- `POST /tasks/:id/complete` 完成
- `POST /tasks/:id/fail` 失败
- `POST /tasks/:id/blocked` 人工块上报 → BLOCKED（与 MCP `block_task` 双入口，见 §5.2）
- `POST /tasks/:id/heartbeat` 续租
- `GET /tasks/:id/review-feedback` 审核意见
- `POST /artifacts` 上传产出物（仅 Agent）

### 5.5 租约与心跳

- 认领成功后建立租约，时长 `lease_ttl_minutes`（默认 30 分钟）。
- Agent 须按 `heartbeat_interval_seconds`（默认 300 秒）周期性 `heartbeat` 续租。
- **租约过期**任务自动回到 `FAILED`，Agent 需重新认领；并发认领由 SQLite 事务原子保证（单连接 `connection_limit=1`）。

### 5.6 Cursor 专用：外部调度脚本（`scripts/cursor-agent-poll.mjs`）

Cursor 没有「到点自动调 MCP 工具」的调度器，其 MCP 工具只在一次会话内由模型调用（产品文档十四章）。本仓库提供零依赖调度脚本，由系统级调度周期拉起，走 REST 完成一次完整的**认领 → 执行 → 回写**：

```bash
ATB_URL=http://127.0.0.1:7788 \
ATB_AGENT_TOKEN=atb_xxx \
ATB_CAPABILITIES="language:go,tool:maven" \
ATB_EXEC='cursor-agent -p "{prompt}" --print' \
node scripts/cursor-agent-poll.mjs
```

脚本行为：

- `claim` 认领一个任务（队列空则静默退出 0，等下次调度）；并行执行多任务由调度器并行拉起多个进程实现。
- 自动读取该任务历史审核意见（`review-feedback`），连同标题、描述拼成 `{prompt}` 占位符注入工作命令；也可用 `{title}` `{description}` `{task_id}`。
- 执行期间按服务端建议周期心跳续租、把工作命令输出增量回传为 Run 日志；心跳失败（租约失效或被强制停止）自动终止工作进程。
- 工作命令退出码 0 → `complete` 回写（摘要取输出末尾）；可设 `ATB_ARTIFACTS_DIR` 把目录内文件作为产物一并上传。非 0 或超时（`ATB_TIMEOUT_SECONDS`，默认 1800 秒）→ `fail` 回写。
- 端到端行为由 `apps/api/src/__tests__/cursor-scheduler.e2e.test.ts` 覆盖（空队列 / 成功含产物 / 失败三条路径）。

macOS launchd 示例（`~/Library/LaunchAgents/com.atb.cursor-poll.plist`，每 5 分钟一轮）：

```xml
<key>ProgramArguments</key>
<array>
  <string>/usr/bin/env</string>
  <string>ATB_AGENT_TOKEN=atb_xxx</string>
  <string>ATB_EXEC=cursor-agent -p "{prompt}" --print</string>
  <string>ATB_QUIET=1</string>
  <string>node</string>
  <string>/path/to/agent-task-board/scripts/cursor-agent-poll.mjs</string>
</array>
<key>StartInterval</key>
<integer>300</integer>
```

> 注意：Cursor 的云端 / 后台 Agent 运行在用户机器之外，访问不到 `127.0.0.1:7788`，不在支持范围内（十五章网络边界不为此放宽）。若选择在 `.cursor/rules/*.mdc` 中写会话规则驱动认领，那不是无人值守方案，文案与预期请勿写成「自动执行」。

## 6. 数据安全与管理

### 6.1 本地优先与网络边界

- 后端仅监听 `127.0.0.1`，不暴露到局域网 / 公网。
- UI Token 与 Agent Token 作用域隔离，互不可调。
- 产出物原始内容经**一次性 HMAC 签名 URL**（60 秒）访问；响应强制 `nosniff` + `CSP: sandbox` + `CORP: cross-origin`，防止 Agent 内容被当脚本执行。
- 资源路径做白名单 + `realpath` 前缀校验，防目录穿越。
- CORS 精确匹配（`tauri://localhost` / `http://tauri.localhost`，开发加 `localhost:5173` / `127.0.0.1:5173`；
  允许的 Methods 含 `PUT`），不回显任意 Origin、拒 `Origin: null`（`apps/api/src/common/origins.ts`）。
- **没有任何对外出站请求**：v0.0.4 起服务端市场已下线、`apps/cloud` 已删除，本地不监听额外端口、
  也不向任何远端发业务请求；断网时应用功能完整可用。

### 6.2 备份与恢复

- **只有手动备份**：设置 → 备份 →「立即备份」（`POST /settings/backup`），产物是 `VACUUM INTO` 的一致性快照
  （文件名 `atb-YYYYMMDD-HHMMSS.db`，落在 `~/.jarvis-workbench/backups/`；文件名前缀沿用 `atb-` 未随目录改名）。
- **无自动备份**：`backup_time` / `backup_keep` 两个键存在于设置契约，但设置页不暴露（见 §4.7）；
  需要定时备份请自行对备份目录做外部 cron/rsync。
- **恢复**（`POST /settings/backups/:name/restore`）：整库换文件。点确认后服务端先对当前库做一次安全备份，
  失败即中止恢复，再覆盖为所选备份；文件名不匹配 `^atb-\d{8}-\d{6}\.db$` 的条目会被接口拒绝（400 `INVALID_BACKUP_NAME`，`backup/backup-name.ts`）。
- **导入也会前置备份**：数据导入确认前服务端先备份当前库，结果页给出该文件名。

### 6.3 数据导入导出

- 导出：`POST /data/export` → JSON 文件下载（`Content-Disposition` 带文件名，`atb-export-*.json`）。
- 导入：`POST /data/import`（multipart）；导入预览确认后应用，成功后清空任务 / 字段 / 模板 / 备份 / 审计 / 标签缓存。

### 6.4 审计日志

- 关键动作（签发/吊销 Token、设置变更、审核提交、数据导入、分组归档、拆解超时、MCP 调用等）写入审计流。
- 查看：设置 → 日志与审计，`GET /audit`，每页固定 50 条；MCP 动作显示中文标签（需求.md §12.6）。

### 6.5 数据目录与升级迁移（v0.0.4 W1b）

- **数据目录**：默认 `~/.jarvis-workbench`（Windows：`%APPDATA%\jarvis-workbench`；`ATB_DATA_DIR` 可覆盖），
  内含 `jarvis.db`（+WAL）、`artifacts/`、`backups/`、`config.json`（`apps/api/src/common/paths.ts`）。
  日志目录独立：macOS `~/Library/Logs/AgentTaskBoard`（备份不含日志）。
- **首启自动搬迁**：升级后首次启动检测到旧默认目录 `~/.agent-board`（`atb.db`）时，在 api 侧 bootstrap
  一次性搬迁（`infra/data-dir-migration.ts`）：先整库备份 → 复制库（含 -wal/-shm）到新目录并在副本上
  checkpoint → `integrity_check` 校验 → 续跑 schema 迁移 → 写 `settings.migrated_from = 'v0.0.3'` 与
  `migration_completed` 审计 → 旧目录留只读指引 `MIGRATED.md` → 旧库改名 `atb.db.migrated` 封存。
  任一步失败即回滚（删新目录副本、备份保留），旧库分毫未动、旧版仍可启动。**搬迁成功即不可逆**（§21.2-2）。
- **schema 迁移链**：v0.0.3→v0.0.4 依次执行 0007（删 accounts/market_*、全表去 account_id）→
  0008（projects→groups 改名）→ 0009（预置默认分组）→ 0010（技能三来源/去重名约束）→ 0011（分组归档）→
  0012-0014（拆解/会话创建/通知词表），见 `apps/api/prisma/migrations/`。
- 开发库演练惯例：真机数据目录禁写，演练用临时 `ATB_DATA_DIR`（打包/冒烟脚本已如此）。

## 7. 故障排查与常见错误码

### 7.1 启动类

| 现象 | 原因 / 处理 |
| --- | --- |
| 端口被占用 | 用 `ATB_PORT` 环境变量或 `config.json` 的 `port` 换端口 |
| 数据库未初始化 | 先执行 `npm run prisma`（运行 `apps/api/scripts/db.mjs`，建 `~/.jarvis-workbench/jarvis.db`） |
| 桌面端无法打 .app | `@tauri-apps/cli` 已在根 devDependencies，直接 `npx tauri build`；dmg 步骤失败按 §2.3 用脚本的 hdiutil 兜底 |
| 前端连不上后端 | 确认 sidecar 已输出 `ATB_READY`；检查 `127.0.0.1:7788` 可达 |
| 升级后看不到旧数据 | 检查首启搬迁是否完成：新目录应有 `jarvis.db`、旧目录应有 `MIGRATED.md` 与封存的 `atb.db.migrated`（§6.5）；失败回滚时旧库未动，旧版仍可启动 |

### 7.2 接口错误码

| 状态码 | 含义 | 处理 |
| --- | --- | --- |
| 401 UNAUTHORIZED | Token 缺失 / 无效 / 已撤销 | 重新签发 Agent Token；确认 UI Token 已注入 |
| 403 FORBIDDEN | 作用域不匹配（UI Token 调 Agent 接口，或反之） | 用正确作用域的 Token |
| 409 ILLEGAL_TRANSITION | 状态流转非法（服务端兜底） | 检查流转矩阵，勿直接拖到 RUNNING / 拖出 DONE |
| 410 LEASE_EXPIRED | 租约已过期 | Agent 重新认领任务 |
| 413 ARTIFACT_TOO_LARGE | 产出物超过 `artifact_max_mb` 或单 Run 上限 | 调大设置或拆分交付 |
| 422 VALIDATION_FAILED | 必填自定义字段缺失 / 设置键非法 / 值越界 | 补齐必填项或修正设置 |

### 7.3 操作异常

- **拖拽没反应 / 被拒**：目标流转属「禁止」或需「表单」，属正常拦截。
- **执行中任务不能编辑字段**：`RUNNING` 状态锁定编辑，停止或完成后再改。
- **审核页为空**：确认存在 `REVIEW` 且未归档任务；铃铛红点 = 有待审核。
- **WebSocket 断线**：前端自动指数退避重连（1s→30s），重连后全量刷新看板 / 任务 / 通知 / 打开的抽屉。
- **数据库锁（SQLITE_BUSY）**：并发由单连接 + 事务保证；避免在外部工具直接写同一 db 文件。
