```Plain Text
├──────────────────────────────────────────────────────────────────────────┤
│ ① 顶栏 56px                                                               │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│ ② 主内容区（padding 24px）                                                │
│                                                                          │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘

任务详情抽屉从右侧滑入，覆盖主内容区右侧 640px。
```



|项|规格|
|---|---|
|默认尺寸|1440×900|
|最小尺寸|960×600（低于此值列宽不足，见 11\.1）|
|标题栏|**原生**，可拖拽移动窗口；不自绘|

|macOS Dock 图标点击|显示并聚焦主窗口|

|右键菜单|禁用 WebView 默认右键菜单与文本选择（输入框、代码区除外）|

```Plain Text
│                                                                          │
│  [◆] Agent Task Board      看板   审核   任务   设置        🔔 3        │
│  ↑logo + 应用名            ↑顶部导航，当前页加下划线      ↑未读通知角标  │
```

|元素|规格|
|---|---|
|Logo|24×24 图标 \+ 16px 600 字重文本，左边距 24px|
|导航项|14px 500 字重 `--text-secondary`；当前项 `--text-primary` \+ 底部 2px `--primary` 下划线；项间距 24px|
|「审核」导航项|**不带角标**，只作导航|
|通知铃铛|24×24，右上角角标显示**未读通知数**（待审核紫 `#8B5CF6` 底白字，圆角 10px，最小宽 18px，上限「99\+」，`0` 时不渲染徽标本体）。点击**不展开面板**，直接跳任务列表页并带上「待审核」筛选（PRD 6\.7），落地即把对应通知标已读、计数回落；通知面板属阶段二（10\.2）|
|顶栏底边|`1px solid var(--border)`|


**顶栏没有的三项，以及为什么：**


- **依赖图入口**：阶段二功能（PRD 17\.2），阶段一不渲染该按钮，而不是渲染一个点了报错的按钮。
- **全局「筛选」按钮**：筛选是**页面级**状态，看板的筛选在工具栏（3\.4、3\.5），任务列表页的筛选在同一套字段的另一处工具栏。顶栏放第三个筛选器只会产生"两个筛选器谁覆盖谁"的问题。
- **全局搜索框**：搜索即 `GET /api/v1/tasks?keyword=`，结果是一张表格，属于任务列表页（3\.8）。放在顶栏会让人以为能搜审核记录和评论——本期只搜任务 ID 与标题。


全栏只有**一个**角标。若「审核」导航项再挂一个待审核数，就有两个数字描述同一件事，而它们的清零条件不同（通知要标已读，待审核数要等人审完），必然对不上。角标只算未读通知，待审核数量在导航项点进去后的页面里看。


**与原生标题栏的关系：** 采用 `decorations: true` 时，macOS 红绿灯位于标题栏内、不进入内容区，因此顶栏左边距 24px 按原规格生效。若改为 `titleBarStyle: overlay`，Logo 左边距增至 **78px**，且整条顶栏需设为 `-webkit-app-region: drag`（按钮区改 `no-drag`）。



**通知铃铛角标：**

```Plain Text
   ③   ← 紫色 #8B5CF6，白字，12px，圆角 10px
```

|元素|规格|

|图标|16×16，左边距 12px|
|悬停|背景 `--bg-muted`|
|退出项|文本 `#EF4444`|



**菜单项行为：**



|菜单项|行为|
|---|---|
|打开看板|显示并聚焦 Tauri 主窗口（**不打开浏览器**）；窗口已在前台时回到原状态，不重置视图|
|复制 MCP 地址|复制 `http://127.0.0.1:7788/mcp` 到剪贴板，并短暂显示「已复制」|
|查看日志|用系统文件管理器打开日志目录|
|重启服务|仅重启本地服务进程，主窗口保持打开；期间窗口内的请求失败走 Toast（10\.4）|
|退出|结束本地服务后退出应用；若仍有执行中任务，先弹确认（10\.5）|



**托盘图标三态（PRD 6\.7、10\.4）：**



|图标态|触发|表现|
|---|---|---|
|正常|sidecar 存活且 `unread_count = 0`|默认图标，无角标|
|有未读|`GET /api/v1/notifications?unread=true` 的 `unread_count > 0`|图标 \+ 未读数角标（`>99` 显示 `99+`），macOS 用 `set_badge_count`、Windows 用 `overlay_icon`|
|服务已停止|Rust 侧收到 sidecar 子进程退出事件（PRD 10\.4），无需轮询|红色图标，菜单首项变「● 服务已停止」（文本 `#EF4444`），「重启服务」变为唯一可用动作|


角标数据与顶栏铃铛同源（同一 `unread_count`，WS `notification.created` 直接把新计数带上，两处同时更新，无需回查），主窗口隐藏到托盘后仍然更新——这是窗口不可见时唯一的提醒通道。角标只在通知被标已读后回落，不随用户"看了一眼托盘"而清零。



**菜单首项（状态行）：** 「● 运行中 (端口 7788)」／「● 服务已停止」，圆点与文本色随上表变化；端口取 `ATB_PORT`，默认 7788（20\.9）。

```Plain Text
│            │            │            │            │            │   ▸     │
│  [卡片]    │  [卡片]    │  [卡片]    │  [卡片]    │  [卡片]    │  折叠   │

```


对应 PRD 4\.1 与 6\.2 第 5 条的三条布局规则：


- 折叠只有一条规则：**列内无可渲染卡片 → 该列折叠为 40px 竖条**（只留列头色点 \+ 计数），有卡片时自动展开，带 200ms 宽度过渡。默认视图下例外：除「异常/失败」外的五列即使为空也保持 280px 占位，因为默认视图里的空列是信息（"这类没活"）；而视图预设（3\.4）下的空列是噪声，一律折叠。
- 每列只渲染前 50 张卡片（`board_column_limit`，20\.7），列底常驻「查看全部 →」，点击跳顶部导航「任务」列表页并带上该列的状态筛选（PRD 6\.1 第 8 条）。**看板内不做分页、不做无限滚动**。
- 工具栏**没有**视图切换：列表视图不是看板的另一种显示，它是独立的「任务」页（3\.8）。看板内能做的是 3\.4 的视图预设，它过滤卡片、不改变列结构。



## 3\.2 列头



```Plain Text
┌──────────────────────────────┐
│  ● 待执行              (3)   │   ← 44px 高，(3) 为可点计数徽标
└──────────────────────────────┘
```



|元素|规格|
|---|---|
|色点|8×8 圆点，对应状态色（1\.1 状态色表）|
|列名|14px 500 字重 `--text-primary`|
|计数|12px `--text-secondary`，背景 `--bg-muted`，圆角 10px，内边距 2px 6px；是 `<button>`，悬停时背景转 `--border-strong`、光标 pointer|
|列头背景|`transparent`|
|列头下边距|12px|


**列头没有「更多」菜单。** 原先设计的「排序 / 折叠 / 筛选」三项都无处安放：


- 排序：列内顺序由服务端固定（PRD 4\.1 \+ 5\.6 抓取顺序；「已完成」列按 `updated_at DESC`），前端不提供列内重排——否则卡片位置和 Agent 实际领取顺序对不上。
- 折叠：自动触发，任何列无可渲染卡片时都会折叠（3\.1），不是用户手点的开关。
- 筛选：属于工具栏与筛选面板（3\.4、3\.5），不在列头重复。

计数徽标本身可点：点击「待审核」计数跳审核页，点击其他列跳「任务」列表页并带上该状态。

## 3\.7 拖拽交互


 

拖拽的**允许／禁止／需弹表单**由 PRD 4\.5 的拖拽矩阵单一决定，前端不另写一份判断；矩阵改动即交互改动。原型只规定三种反馈形态：

|形态|视觉|松手后|
|---|---|---|
|✅ 直接生效|目标列顶部 2px 主色条 \+ 虚线占位|`POST /tasks/{id}/transition`，成功后 WS `task.moved` 校正位置；失败按 `409 ILLEGAL_TRANSITION` 回弹并 Toast 服务端 `message`|
|🔒 需表单|目标列虚线描边 \+ 列头出现对应动作名（「强制停止」「审核」「驳回」）|松手弹出 720px 模态（1\.5：与审核页右栏是同一组件的两个壳）；取消则卡片回原位，**不发请求**|
|❌ 禁止|目标列整体红描边 \+ 禁止光标|卡片回弹动画，只 Toast 文案，不改状态|


 

**Toast 文案**（与 PRD 4\.5「统一提示文案」逐字一致，前端不自拟）：



- 拖向或拖出「执行中」：「执行中由 Agent 认领产生，请使用卡片上的"强制停止"」

- 从「已完成」拖出：「已完成是终态。需要重做请新建任务并设为其后续」

- 其余 ❌ 组合：「不能从「{源列}」直接拖到「{目标列}」」

    

 

两条容易被忽略的矩阵推论：



- **待审核 → 已完成是 🔒 不是 ❌**：松手即弹审核表单（结论预填「通过」），取消回原列；待审核拖向需求池／待执行同样 🔒，弹驳回表单并把拖放目标写进「退回目标」。

- **被阻塞的 `READY` 卡片可以拖**：阻塞只影响 Agent 可领取性，不限制人工流转（PRD 4\.5 末条）。

- **空态**沿用 3\.6 的插图，但带筛选时空文案为「没有匹配的任务」\+「清除筛选」按钮，不显示「新建任务」。

**产物行规则（与 9 章预览器、PRD 17\.2 一致）：**


|`artifacts.type`|阶段一动作|说明|
|---|---|---|
|`diff` / `text` / `log` / `image`|`[预览]`|走 9\.1–9\.3 预览器|
|`file`|`[下载]`|无预览器|
|`json` / `markdown`|`[下载]`|预览器阶段二；图标仍按类型区分，不伪装成"不支持"|
|`html` / `pdf`|`[下载]`|同上；HTML 需沙箱独立源，成本最高|
|`link`|`[浏览器打开]`|无内容可预览，`uri` 只接受 `http(s)`，交系统默认浏览器（不由 WebView 导航）|


一行一个动作按钮，不在阶段一把按钮置灰——置灰的下载/预览按钮会让人以为是网络问题。`SUCCESS` 与「已驳回」分两行渲染：前者是 `task_runs.status`，后者是 `reviews.conclusion`，合成一个"❌ 已驳回"会让读代码的人去 `task_runs` 里找一个不存在的枚举值。

产物行显示的是 `artifacts[].name`（服务端由 `metadata.name` 或 `uri` 末段推导，PRD 20\.7），**不是磁盘文件名**——磁盘上存的是 `{artifact_id}.{ext}`（20\.6），原名只在 `name` 里。

**Agent 名的取值**：卡片、Run 行、审核列表、审计操作人显示的一律是 `api_tokens.name`（示例里的 `qoder-1` / `claude-ci`），服务端在认领与写日志时取该值（20\.8），Agent 不能自报。客户端产品名（Qoder / Claude Code / Codex / Cursor）只出现在 7\.3 的「客户端配置片段」Tab 上——那是"怎么接入"的语境，不是"谁执行的"。

## 4\.9 底部操作栏



按钮由状态决定，**动作名与 PRD 4\.3 操作表逐字一致**，界面不自造同义词。每态只有一个主按钮（右一，主色底），其余为次级按钮；更少的常用动作收进 `⋯`。



|状态|主按钮|次按钮|`⋯` 内|
|---|---|---|---|
|需求池|确认可执行|—|删除|
|待执行|—|撤回（→ 需求池）|删除|
|执行中|强制停止|—|查看日志（跳 4\.5 日志块）|
|待审核|审核 →|退回重跑|—|
|已完成|归档|—|删除|
|异常/失败|重试（→ 待执行）|退回需求池|删除|



- 「重新执行」「直接完成」这类按钮**不存在**：待审核只有审核与退回重跑两条路，后者等价于填驳回表单（4\.3）。

- 「归档」只出现在「已完成」——非 `DONE` 调归档接口会得到 `409`（6\.13\.1），按钮也就不该在那儿。

- 「删除」进 `⋯` 且需二次确认，文案取 4\.5「将同时删除 {n} 条执行记录及其产物…」。

- 抽屉内改状态成功的反馈是**卡片列位变化 \+ 顶部 Toast**，抽屉不自动关闭（可能还要接着看执行记录）。

|复用上次意见|`↺` 按钮把该任务**上一条 `reviews`** 的三字段填进表单，填后仍可编辑。`review_reuse_last_opinion = false` 时这一行整体不渲染（不是置灰，7\.2）。首次审核（无历史 `reviews`）时按钮旁标注「无历史意见」并禁用|
|diff 区块|超过 200 行折叠 \+ 「展开全部」；解析走 `GET /artifacts/{id}/diff`（13 章），不在前端解析 patch 文本|
|提交|`POST /api/v1/tasks/{id}/review`；成功 Toast \+ 左列**自动跳到下一条未审核**（到末尾则停在最后一条并显示「队列已清空」）；`409 ILLEGAL_TRANSITION`（同一台机器上的并发来源：卡片在看板被拖走、Agent 回写覆盖、租约定时器回收）时不清空表单，改为顶部条幅「该任务状态已变化」\+ 「刷新后重试」|
|校验|前端只做"非空"，枚举与长度校验交服务端（`422 VALIDATION_FAILED`，`details[]` 逐字段回填红字），避免两套规则|
