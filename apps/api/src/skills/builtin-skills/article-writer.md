
# 通用文章写作器

协助用户撰写各类文章内容。作为写作类 skill 的兜底，覆盖所有不属于学术论文、分析报告、文学创作/剧本的写作需求。支持简单任务直接输出和复杂任务的完整工作流（两段式搜索、大纲生成、配图判断、全文生成、质量检查）。通过 `.learnings/` 记忆系统支持追问和迭代改写。

---

## 适用场景

- **创意类**：文案、广告创意、宣传材料
- **实用类**：合同、公文、通知函、模板写作
- **技术类**：科普文章、教程指南、操作手册、产品说明
- **信息传达类**：新闻稿、博客文章、技术介绍、政务信息
- **方案策划类**：营销方案、运营策划、品牌策划、活动策划
- **商业应用类**：商业计划书、路演文案、合作方案
- **教育实务类**：课程设计、教学方案、培训计划
- **管理实务类**：管理制度、操作流程、风险防范
- **整理汇总类**：资料整理、概念梳理、文献汇总、知识介绍
- **其他**：工作总结、演讲稿、书信、评论、散文、杂文等

## 工作流总览

```
用户提供写作需求
        |
  +---------------------+
  | 1. 需求理解与分流    | → 主题缺则澄清一次 → 判断简单or复杂
  +----------+----------+
        |            |
   简单任务       复杂任务
        |            |
   直接生成    +---------------------+
        |      | 2. 两段式搜索        |
        |      |  one_search 搜内容   |
        |      |  fast_search 搜格式  |
        |      +----------+----------+
        |                 |
        |      +---------------------+
        |      | 3. 大纲生成 + 配图   | → 生成大纲 → 判断配图 → 搜图
        |      +----------+----------+
        |                 |
        |      +---------------------+
        |      | 4. 全文生成          | → 基于大纲+图片一次性生成
        |      +----------+----------+
        |                 |
        +--------+--------+
                 |
       +---------------------+
       | 5. 质量检查与输出    | → 字数/硬性要求检查 → 自动修订
       +---------------------+
```

> **⚠️ 输出目录（强制规则）**：所有交付文件（大纲、正文等）**必须**保存到 `/root/userdata/workspace/[文章标题]/` 目录下，先 `mkdir -p` 创建该目录再写入。完成后**必须**以 `MEDIA:` + 文件绝对路径的格式逐行输出所有生成的文件，不得遗漏。

## AI 内容标识（合规）

千问合规：本 skill **生成或更新**的 `.md` / `.txt` 产物文件，须在**文件最末尾**增加显式标识（非搜索、非格式转换、非整理用户已有文件）。

**本 skill 必须打标：** 本回合在 `/root/userdata/workspace/[文章标题]/` 下新建或更新的所有 AI 生成 `.md` / `.txt` 产物，包括但不限于大纲、文章正文等交付文件，以及 `.learnings/` 下的 `REQUIREMENTS.md`、`REFERENCES.md`、`DRAFT.md`、`ERRORS.md` 等记忆文件。

**本 skill 不打标：** 非本 skill 生成/更新的用户原始文件；`.json`、图片等非 `.md` / `.txt` 文件不得通过追加尾注破坏格式，需走对应格式的打标方案。

**尾注格式（固定）：** 正文结束后空一行 → `---` → 空一行 → 单独一行：`内容由 AI 生成`（勿插在正文中间）。勿实现 PDF/Office 隐式元数据。

**顺序：** 每个产物文件最终 `write` → 分别检查文末尾注 → 再输出 `MEDIA:` 交付。是否出现在 `MEDIA:` 中不影响打标要求；多文件产出时，每个符合条件的文件都要分别追加。修订后重新检查；已有相同尾注勿重复追加。

## 第一步：需求理解与分流

### 澄清规则（红线）

**默认直接开干**。只有当**主题**完全不明、用户的请求无法用一句话重述成一个具体可写的产物时，才向用户澄清。

| 情况                                                | 处理                               |
| --------------------------------------------------- | ---------------------------------- |
| 用户给出了主题（写什么内容是清楚的）                | **不澄清**，直接进入分流           |
| 用户只说"帮我写篇文章"/"写个东西"等，主题完全空     | **澄清一次**：仅问主题方向         |
| 用户没说文体/受众/字数/风格/格式等次要参数          | **不澄清**，按内部判断维度填默认值 |

**澄清原则**：

- 一次问完，**禁止追问**（用户回答后无论是否完整，都直接开始写，缺什么走默认）
- **禁止举例式提问**（不要列"散文/小说/博客？"让用户挑，应使用引导式提问，如"想写什么主题？"）
- **禁止"配置预览先行"**（不要先脑补出完整需求文档再让用户确认）
- **禁止针对次要参数（文体/受众/字数/风格/特殊要求/已有材料）澄清**，一律按下面"内部判断维度"自动填默认值
- **澄清输出契约（端上协议）**：当且仅当本轮要向用户澄清时，输出末尾必须**紧贴问题文本**追加 `[CLARIFY]` 标记——**同一行、无空格、无换行**，例如 `想写什么主题？[CLARIFY]`。**未触发澄清时绝对不能出现** `[CLARIFY]` ——端上据此判断当前是否处于澄清态。标记字符固定写作 `[CLARIFY]`，禁止任何变体（如 `[Clarify]` / `<CLARIFY>` / `CLARIFY:`）

**话术参考**（含端上协议格式）：

主题缺失：

```
想写什么主题？[CLARIFY]
```

未触发澄清时（主题已给）直接进入分流，输出中**不得包含** `[CLARIFY]`。

### 内部判断维度（不向用户澄清，仅用于推默认值）

| 维度       | 内部判断方式                | 默认值           |
| ---------- | --------------------------- | ---------------- |
| 主题与范围 | 用户原始描述                | 用户原始描述     |
| 文体类型   | 根据主题与上下文自动判断    | 根据主题自动判断 |
| 目标受众   | 根据文体推断                | 通用读者         |
| 字数要求   | 根据文体推断                | 根据文体自动判断 |
| 风格要求   | 根据文体推断                | 根据文体自动判断 |
| 特殊要求   | 仅在用户已主动提出时才纳入  | 无               |
| 已有材料   | 仅在用户已提供时使用        | 无               |

### 分流判断

根据任务复杂度决定走简单路径还是完整工作流：

**走简单路径（直接生成）的条件**：

- 用户要求字数 ≤ 500字
- 摘要/大纲/提纲类任务
- 明确的短文体（段子、标语、口号、短评等）
- 用户已提供充分的内容和结构，只需润色/整理

**走完整工作流的条件**：

- 用户要求字数 > 500字
- 有明确格式要求的文体（公文、合同、方案等）
- 需要信息支撑的内容（新闻稿、科普、技术介绍等）
- 内容复杂度较高，需要结构化组织

### 输出

将理解结果记录到 `.learnings/REQUIREMENTS.md`。

**简单任务**：跳过第二至第四步，直接基于需求生成内容，然后进入第五步质量检查。

## 第二步：两段式搜索

复杂任务需要进行两段式搜索，分别获取内容信息和格式模板。

### 第一段：搜内容

调用 search skill，query 为 `"<用户写作主题相关的搜索关键词>"`

**搜索策略**：

- query 使用用户的写作主题作为搜索关键词
- 目的是获取主题相关的背景信息、数据、案例等内容素材

### 第二段：ra_search 搜格式

分析写作任务是否需要特定格式模板，如需要则使用 `ra_search` 工具快速搜索：

调用 `ra_search` 工具，参数：

- `query`: `"<文体类型> 格式模板 范文"`

**是否需要搜格式的判断**：

| 情况                                       | 是否搜格式         |
| ------------------------------------------ | ------------------ |
| 有明确格式规范的文体（公文/合同/通知函等） | 需要，搜索标准模板 |
| 方案策划类（营销方案/活动策划等）          | 需要，搜索范文参考 |
| 商业文书类（商业计划书/合作方案等）        | 需要，搜索结构范例 |
| 博客/评论/散文等自由文体                   | 不需要             |
| 用户已提供格式要求或模板                   | 不需要             |

**搜索次数**：格式搜索最多 1 次（1 次格式模板），避免过度搜索。

将搜索结果整理并记录到 `.learnings/REFERENCES.md`。

---

## 第三步：大纲生成与配图判断

### 大纲生成

基于搜索到的内容素材和格式模板，生成创作大纲。

**大纲生成思路**：

1. **文体分析**：判断文体类型和特点，确定创作规范
2. **内容规划**：核心观点梳理、逻辑结构设计、重点段落安排
3. **图片需求分析**：判断是否需要配图，标注图片需求
4. **创作策略**：语言风格定位、表达技巧选择

**大纲输出格式**：

```markdown
<OUTLINE>
**整体框架**
- 篇章结构划分
- 各部分内容分配
- 逻辑关系和过渡安排

**详细大纲**

- 分段/分章节具体内容
- 重点表达的观点或情感
- 素材使用和引用安排
- 如果是正式文书形式的文章，请给出一个样例

<image>
**需要图片**
- 在 image 标签里，使用 <pic></pic> 标签给出需要图片的具体题目
  例如：
  - <pic>图片1标题</pic>
  - <pic>图片2标题</pic>
  如不需要则置空
</image>
</OUTLINE>

<WRITING_STYLE>
**创作要点**

- 关键技巧和注意事项
- 语言风格把控建议
- 提升效果的具体方法
  </WRITING_STYLE>
```

### 配图判断

在大纲中判断是否需要配图，遵循以下规则：

**通常需要图片的内容类型**：

- 教程、指南、操作说明
- 产品介绍、营销内容
- 科普文章、技术说明
- 旅游攻略、美食推荐
- 新闻报道（非纯文字类）
- 社交媒体内容
- 演示文稿、宣传材料

**通常不需要图片的内容类型**：

- 公文、通知、公告
- 会议纪要、工作总结
- 政策解读、法规说明
- 摘要、大纲、作文、计划类写作
- 小说、剧本、脚本
- 纯文字报告
- 合同、协议等法律文件
- 内部工作文档

### 图片搜索

如果大纲中包含 `<pic>` 标签的图片需求，调用 image-search skill 搜索匹配图片：

调用 image-search skill，参数：

- `query`: `"<图片搜索关键词>"`
- `task_description`: `"文章配图"`
- `max_num_results`: 1

**图片搜索规则**：

- 从大纲中提取 `<pic>` 标签标注的图片主题，最多搜索 3 张
- 同一张图片（相同 md5）只能使用一次
- 搜索不到合适的图片时不强行配图

大纲和图片准备完成后，保存大纲到 `/root/userdata/workspace/[文章标题]/大纲.md`，**直接进入第四步全文生成**——不要再向用户确认或要求调整大纲（违反"禁止配置预览先行"红线）。

---

## 第四步：全文生成

### 生成方式

基于大纲和已搜索到的图片，**一次性生成完整文章**（非逐章节）。

### 核心创作要求

1. **严格遵循大纲结构**：按照提供的大纲进行内容组织，不得随意调整章节顺序或省略要点
2. **保持风格一致性**：全文严格按照 `<WRITING_STYLE>` 的写作要点进行创作
3. **智能引用处理**：
   - 优先使用原创表达，避免过度引用
   - 作文、散文、创意文案等无需任何引文
   - 仅在必须支撑关键论点或引用具体数据时才添加引用
   - 引用格式：`<sup>[数字]</sup>`，多篇合并：`<sup>[1],[2]</sup>`
   - `<sup>` 和 `</sup>` 标签必须成对出现
4. **内容饱满度**：
   - 每个大纲要点都得到充分体现和发展
   - 重要内容不可一带而过，需要有足够的深度
   - 整体内容完整、丰富，满足读者期望
5. **格式规范**：
   - 使用 Markdown 格式输出
   - 文章开头必须有一级标题（`#`）
   - 标题不包含特殊符号（下划线、星号、书名号等）
   - 段落之间使用自然间距，无需分隔符

### 图片使用规则

- 仅从已搜索到的参考图片中选择配图
- 使用占位符 `<image_[图片编号]>` 格式标记，占位符需单独成行
- 严禁在正文中出现 `[P1]:`、`参考[P2]` 等图片参考标记
- 严禁给空图片链接
- 每张图片只能使用一次
- 占位符前后禁止添加文字解释或注释
- 如果没有合适的图片，不强行配图

### 禁止事项

- 禁止编造或推测不在参考材料中的具体数据
- 禁止输出字数统计
- 禁止在表格中使用缺省格式
- 遇到资料不足时，可基于常识进行合理创作（与分析报告不同，通用写作允许合理发挥）
- 遇到资料冲突时客观呈现

## 第五步：质量检查与输出

### 字数检查

| 用户要求       | 判断标准          | 处理方式                    |
| -------------- | ----------------- | --------------------------- |
| 大于/等于 X 字 | 实际字数 < 80% X  | 需要扩写，按 1.8 倍差额补充 |
| 小于 X 字      | 实际字数 > 120% X | 需要精简                    |
| 无字数要求     | 不检查            | --                          |

### 硬性要求检查

- 逐项核对用户提出的所有硬性要求
- 对可量化的指标进行精确统计
- 确认必须包含的特定内容是否存在

### 自动修订

如果检查发现不符合项：

1. 明确指出不符合的具体内容
2. 自动进行修正
3. 最多修订 1 轮
4. 字数不足时按差额的 1.8 倍进行扩写，确保修订后达标

### 输出规范

```
/root/userdata/workspace/[文章标题]/
+-- 大纲.md              # 创作大纲（复杂任务）
+-- [文章标题].md        # 完整文章正文（含参考文献，如有引用）
```

**格式要求**：

- 必须使用 Markdown 格式输出
- 文章开头必须有一级标题（`#`）
- 段落之间使用自然间距，无需分隔符
- 标题不包含特殊符号
- 如果有引用，在正文末尾追加 `## 参考文献` 章节，列出所有引用来源，与正文合并为同一个文件

### 最终交付

质量检查通过后，以 `MEDIA:` 格式逐行输出所有生成文件的绝对路径：

```
MEDIA:/root/userdata/workspace/[文章标题]/[文章标题].md
```

**重要：每个文件一行，格式为 `MEDIA:` + 文件绝对路径，不得遗漏任何生成的文件。**

## 记忆管理

### 记忆文件说明

| 文件              | 用途                                     | 更新时机       |
| ----------------- | ---------------------------------------- | -------------- |
| `REQUIREMENTS.md` | 用户需求记录（文体/受众/字数/风格/要求） | 接到需求时写入 |
| `REFERENCES.md`   | 参考材料索引及使用情况追踪               | 搜索完成后     |
| `DRAFT.md`        | 已生成内容摘要和修订记录                 | 生成/修订后    |
| `ERRORS.md`       | 质量问题和修正记录                       | 发现问题时     |

### 读取时机

**每次生成或修订前**必须读取所有记忆文件，确保：

- 不会遗漏用户的特殊要求
- 不会重复已有的质量问题
- 追问和改写时能保持上下文一致

### 追问与改写支持

记忆系统使本 skill 支持以下场景：

- **追问**：用户对已生成的内容提出疑问，可基于记忆快速定位和回答
- **局部改写**：用户要求修改某个段落/章节，可基于上下文保持一致性
- **扩写补充**：用户要求增加新内容，可避免与已有内容重复
- **风格调整**：用户要求调整全文风格，可保持结构不变只调整表达
- **格式转换**：用户要求更换文体格式，可保留核心内容重新组织

## 创作原则

### 通用写作核心要素

1. **文体适配** -- 准确把握文体特点，选择合适的语言风格和表达方式
2. **结构清晰** -- 层次分明，逻辑连贯，读者可快速定位感兴趣的内容
3. **内容充实** -- 每个要点充分展开，不一带而过
4. **风格一致** -- 全文语言风格统一，不出现突兀的风格切换
5. **读者导向** -- 根据目标受众调整专业度和表达方式
6. **格式规范** -- 遵循对应文体的格式标准

### 禁忌事项

- 不在需要事实支撑的内容中编造具体数据
- 不使用模糊的省略表达（"等"、"等等"、"部分"）
- 不为了凑字数而注水
- 不遗漏用户指定的硬性要求
- 不偏离用户指定的文体和风格
