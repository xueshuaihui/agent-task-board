
# 思问导学备课与学生课堂课件

## 适用范围

本技能仅适用于 K-12（小学、初中、高中）课程。若用户需求明确属于大学、研究生、成人教育、职业继续教育或企业培训，直接说明“该需求超出本技能的 K-12 适用范围”，简要说明本技能服务于中小学课程，并建议用户改用适合高等教育或成人学习设计的工具。不得强行套用“思—问—导—学”中小学框架，也不得继续生成交付物。

## 交付规则

根据用户明确需要的格式交付：教师版 Word 教案、学生版 PPTX 课件、HTML 交互课件或 Markdown 内容稿。用户只要求一种格式时，只生成这一种，不附带其他文件；用户要求多种格式时，才生成相应组合。用户明确要求网页课件或 HTML 交互课件时，以单文件 HTML 替代 PPTX，不再额外生成 PPTX，且继续遵守学生端隐性四步和受众规则。用户未说明格式时，在资料核准后逐项询问所需交付物。

当用户已经提供所需文件，或已逐项回答完必要问题后，直接建立内部映射并生成最终交付物。不得展示课程蓝图、页面蓝图或制作计划让用户确认，也不得设置“确认，可以生成”之类的确认门槛。

## 不可变原则

1. “思—问—导—学”是每课时唯一的四个大步骤。检测、总结、迁移和作业归入“学”，不得增加并列第五步。
2. 教师端显性标注四步，学生端隐性落实四步。教学目标、教师话术、预设答案、评价量规和板书只进入教师材料。
3. 教师材料与学生课件必须来自同一份内部课程映射，但该映射不发送给用户确认。
4. 改造旧版教案或 PPT 时，原有内容不得删减。先建立内容保全清单，再在原内容基础上调整结构、重排顺序并补充“思—问—导—学”所需内容。
5. PPTX 或 HTML 课件所需情境配图在制作过程中由 AI 自动生成并直接用于成品，不另设图片确认环节。

## 中文交互规则

所有面向用户的提问、选项、进度说明、范围提示和交付消息必须使用准确、自然、无歧义的中文。开始交互前阅读 [references/chinese-interaction-and-blueprint.md](references/chinese-interaction-and-blueprint.md)。英语学科允许在成品中保留教材官方英文课题、词汇、句型和必要原文，但用户交互仍使用中文。

## 工作流

### 1. 判断范围并逐项补齐核心信息

先判断是否属于 K-12。超出范围时按“适用范围”直接回复并停止。

若用户只说“帮我备课”，且没有提供教材版本、年级、课题或材料，必须严格按以下顺序逐项追问，每轮只问当前缺失的一项，收到回答后再问下一项：

1. 教材版本与学科，例如“请先告诉我教材版本和学科，例如人教版小学语文。”
2. 年级，例如“请告诉我具体年级。”
3. 准确课题，例如“请告诉我这次要备的准确课题名称。”
4. 教材页或课程材料，例如“请上传教材页照片、课程文档或可参考的旧教案、旧 PPT。”

不得自行猜测教材版本、年级或课题，不得凭空编造教学内容。上下文已有的信息不得重复询问。

教材原文缺失时，先请用户上传材料；如果用户暂时无法提供，再询问是否授权根据已确认的版本、年级和课题检索教材内容。获得授权后方可检索，并在交付物中标注来源。

核心信息齐全后，再逐项补充真正缺失的课时数与单课时时长、班级特点、交付格式和视觉偏好。不要把所有问题一次性堆给用户。

### 2. 完整读取材料并建立内容保全清单

完整读取教材页、课程文档、旧教案和旧 PPT，核准教材版本、年级、单元、课题和课时边界。

若任务是改造旧版教案或 PPT，先在内部建立内容保全清单，逐项记录原材料中的标题、知识点、例题、练习、答案、活动、图表、图片、教师提示、板书和页序关系。新版必须保留清单中的全部内容；允许调整归属、顺序、版式和表达，允许补充分支追问、转场、学习证据和情境，但不得删除、压缩到失去原意或用新内容替代原内容。原内容存在矛盾或明显错误时，保留其信息并清楚标注问题与修订依据，不得静默删去。

### 3. 明确交付格式

用户已指定格式时直接采用，不额外建议或生成其他格式。用户未指定时，逐项询问最终需要教师版 Word、学生版 PPTX、HTML 交互课件或 Markdown 内容稿中的哪一种或哪些组合。

网页课件规则：用户明确要求 HTML 或网页交互课件时，以单文件 HTML 替代 PPTX；若用户只要 HTML，只交付 HTML。HTML 中学生可见内容必须隐性落实四步，不显示教学模型标签或教师后台语言。

### 4. 建立内部课程映射并直接制作

阅读 [references/mapping-and-verification.md](references/mapping-and-verification.md)，在内部建立“思—问—导—学”映射，记录学习目标、学生关键动作、教师关键引导、课件页面组和课堂达成证据。

映射完成后直接进入成品制作。不得向用户展示蓝图或页面骨架，不得要求用户确认蓝图；只有输入信息仍有实质缺口时才继续逐项询问。

### 5. 按需生成教师版材料

仅当用户要求 Word 或 Markdown 教师材料时，完整阅读 [references/teacher-word.md](references/teacher-word.md)。生成 Word 时调用 `docx` skill；生成 Markdown 时保持与教师版结构一致。

教师版必须显性使用“思—问—导—学”。每个关键任务写清学生任务、正确与错误反应、教师观察判断、分支追问、转场策略和达成证据，禁止只写“教师引导”或“学生讨论”。

### 6. 按需生成 PPTX 或 HTML 课件

仅当用户要求学生课件时，完整阅读 [references/student-ppt.md](references/student-ppt.md)。生成 PPTX 时调用 `pptx` skill；生成 HTML 时使用单文件 HTML，且不得同时生成 PPTX，除非用户明确要求两种格式。

制作过程中先形成内部页面与配图清单，再调用 AI 图像生成能力，为具体课题生成适合学生年龄、学科情境和页面任务的原创配图，并直接嵌入成品。不得使用空白占位图、无关装饰图或要求用户另行补图。AI 图片不得承载必须精确呈现的文字、公式、坐标、实验刻度或学科结论；这些内容使用可编辑文本、形状、图表或公式制作。若 AI 图像生成能力不可用，应明确说明阻塞原因，不得静默省略配图要求。

学生课件不得出现教学模型标签和教师后台语言。每页只驱动一个主要学生动作；先让学生尝试，再逐步提供线索，最后呈现规范结论或自查。四步必须能从任务链中还原，但不能被学生看见。

### 7. 验证并返工

按 [references/mapping-and-verification.md](references/mapping-and-verification.md) 完成范围、内容保全、双端映射、用户交互语言、文件结构和视觉检查，并执行“检查—修正—重新检查”循环，直到全部通过：

- 任务属于 K-12；
- 每课时完整且仅有四个大步骤；
- 每个课件问题在教案中有预期反应和教师追问；
- 每个答案或结论之前都有学生尝试；
- 学生课件无教师专属语言和模型标签；
- 旧材料改造任务的内容保全清单逐项有去向，无删减；
- PPTX 或 HTML 中的 AI 配图已实际生成、嵌入且符合年龄与学科情境；
- 只生成用户指定的文件格式；
- Word、PPTX 或 HTML 可正常打开，关键页面经过视觉抽查。

阻断性问题未解决时不得交付。

### 8. 直接交付

输入与格式要求齐全后直接交付最终文件，不再请求蓝图确认。将用户指定的文件放到用户可见目录并提供直接文件链接。交付消息使用中文，简要说明课题、教材版本、课时信息、已交付格式和必要的来源或版本差异提醒，不列出用户未要求的文件。
