
# Pic report（图文报告生成）

**功能定位：先进行图文搜索取数，再生成图文并茂的完整报告。** 本 skill 通过执行脚本调用远程搜索任务完成取数（得到文字信息汇总 `main_agent_input` + 图片信息 `addition_info`），再把它们组织成「搜索 → 大纲 → 正文 → HTML」的图文报告。

---

## 全局约束（每步执行前必须内化）

1. **数据忠实**：所有文字/数据必须来自 `main_agent_input`，严禁编造；所有图片必须来自 `addition_info`，相信两个文件内的内容有效性和可靠性不要试图额外搜索内容替换它们。
2. **图文并茂**：这是图文报告，正文必须恰当穿插图片形成良好视觉效果；但**图文必须相关、宁缺毋滥**。
3. **图片唯一**：每张图片（按 `@@IMG_<id>@@` 标记去重）**全文仅能使用一次**；配图必须与所在段落文本语义相关。
4. **禁用 emoji**。
5. **内容类型适配**：先判定交付物类型（内容型/工作汇报型/数据分析型/创意型），全文采用对应写作身份与口吻，正文**绝不暴露取数/搜索/工具过程**。
6. **结论先行**：遵循金字塔原理，首章即给出核心结论，后续章节展开；同一结论全文只完整表述一次。
7. **表格规范**：表头用属性/维度（对比型首列为维度），禁止表头全为实体或序号，标题独立于表格外，无空单元格。
8. **图片零解说**：正文用 `@@IMG_<id>@@` 标记落图（交付前由脚本替换为 `![图片标题](url)`），禁止在图片标记前后追加"图示：xxx""如下图所示"等文字。
9. **工具约束**：.md 必须用 Write/Edit 工具写入；.html 由 Agent write 骨架 + 脚本填充章节，禁止脚本一次性生成完整 HTML 正文文字。
10. **禁止调用 subagent**：整个流程由单一 agent 串行完成。
11. **绝不中断**：每完成一步（Step 0/1/2/3/4/5）后立即进入下一步，不停下来总结、确认或等待用户回复。若单步产出超出输出限制，拆分为多轮写入，轮次之间不插入任何用户交互。

---

## 执行流程

按以下六步**顺序执行**，每步的指令文件在执行到该步骤时才读取，不要提前读取。

### Step 0：创建输出目录

根据用户的报告主题，创建输出目录：

1. 生成 <目录名>：时间戳作为前缀，加 8 位随机 MD5 后缀。

- **后续所有步骤中的 `<输出目录>` 均指此目录路径**

### Step 1：搜索结果
1. 执行以下命令进行搜索：
```bash
python3 {baseDir}/scripts/script.py "<用户的图文收集主题或任务描述>" <输出目录>
```
参数：

- **第一个参数**：图文收集主题或任务描述，直接使用用户原始输入，不要修改或拆解

> ⚠️ **超时设置**：脚本内部搜索超时 1200 秒 + 报告生成超时 900 秒，总计可能需要 30+ 分钟。调用时 **必须设置 timeout ≥ 2100 秒**。

输出：

在 `<输出目录>` 下得到三个搜索结果文件：`main_agent_input`（子agent搜索内容）、`addition_info`（图片信息）和 `cited_urls.md`（溯源标记 → URL 映射，交付阶段回填用）。前两个文件为 **UTF-8 编码的 JSON**，内容与格式如下：

**`main_agent_input`（文字事实/数据的唯一来源）**：JSON 数组，元素为搜索子 agent 的对话消息对象 `{"role": "user"|"assistant", "content": "<文本>（包含`@@REF_<id>@@`格式的溯源标记）"}`：

- `role=assistant` 消息为 `<thinking>` 规划过程，属过程性内容，**不作为报告素材**。 -->

**`addition_info`（图片的唯一来源）**：JSON 数组，嵌套结构如下：
- 顶层元素：`{"sub_agent_query": "<子任务 query>", "sub_agent_result": […]}`。
- `sub_agent_result` 元素：`{"search_pic_query": "<图片搜索 query>", "imgs": […]}`。
- `imgs` 元素：`{"id": "@@IMG_n@@", "title": "<图片标题>", "url": "<图片直链>"}`。其中 `id` 为**全局唯一的字符串**（`@@IMG_1@@`、`@@IMG_2@@` ……跨所有 `sub_agent_query` / `search_pic_query` 连续递增，而非单个 query 内重新计数），作为图片在全文的唯一标识；正文写作时直接落 `@@IMG_<id>@@` 标记，交付前由回填脚本替换为 `![图片标题](url)`（标题取自该图的 title）。


> `addition_info` 中的图片（按 `@@IMG_<id>@@` 标识）是后续「选图」的唯一依据：大纲阶段规划每章用哪些 `@@IMG_<id>@@`，正文阶段直接写 `@@IMG_<id>@@` 标记，并保证每张图仅用一次；标记由 Step 3 末尾的回填脚本统一替换为真实图片链接。

**此步骤完成后，确认 `addition_info`、`main_agent_input` 和 `cited_urls.md` 已生成，再进入下一步。**

### Step 2：生成图文大纲（写大纲）

**此时才读取** `{baseDir}/reference/outline-rules.md`，严格按其要求执行。

- 数据源：`<输出目录>/main_agent_input` + `<输出目录>/addition_info`
- 产出：`<输出目录>/outline.md`（含章节结构 + 论点 + 表格需求 + **配图规划** + 写作指导）

**此步骤完成后，确认 `outline.md` 已生成，再进入下一步。**

### Step 3：撰写完整图文报告（写正文）

**此时才读取** `{baseDir}/reference/writing-spec.md`，严格按其要求执行。

- 数据源：`<输出目录>/outline.md` + `<输出目录>/main_agent_input` + `<输出目录>/addition_info`
- 产出：`<输出目录>/<相关标题>.md`（文件名取自文章标题，默认中文；含标题 + 摘要 + 全部正文章节，正文图文混排）
- 写作时溯源直接落 `@@REF_<id>@@` 标记、配图直接落 `@@IMG_<id>@@` 标记（同一处信息不堆叠多个溯源标记）；正文与摘要全部写完后执行回填脚本，把标记替换为 `[站点名](url)` 溯源链接与 `![图片标题](url)` 图片链接（命令与规则见 writing-spec.md，**禁止手工回填**）：

```bash
python3 {baseDir}/scripts/backfill_markers.py <输出目录>/<相关标题>.md <输出目录>/cited_urls.md <输出目录>/addition_info
```

**此步骤完成后，确认 `<相关标题>.md` 已生成且回填脚本已执行成功（正文无残留 `@@REF_`/`@@IMG_` 标记），再进入下一步。**

### Step 4：生成图文 HTML 报告（必须产出文件）

**此时才读取** `{baseDir}/reference/html-render.md`，严格按其要求执行。

- 底稿：`<输出目录>/<相关标题>.md`
- 骨架模板：`{baseDir}/template/template.html`
- 填充脚本：`{baseDir}/scripts/md_to_html.py`（第四个参数传 `<输出目录>/addition_info`）
- 图片展示：连续多图自动排为等大网格，单图尺寸固定；报告末尾自动生成「图片汇总」章节（支持搜索与标签筛选），罗列 `addition_info` 全部图片
- 产出：`<输出目录>/<相关标题>.html`（与 md 同名，仅扩展名不同）

**此步骤完成后，确认 `<相关标题>.html` 已生成，再进入下一步。**

### Step 5：按照以下要求输出内容给用户

**最终交付文件**
必须展示一个文件：`<相关标题>.html`
交付方式：以 MEDIA: 格式逐行输出所有生成文件的绝对路径，例如：MEDIA:<输出目录>/<标题>.html

## 注意事项

1. **数据只读**：`main_agent_input`、`addition_info` 为 Step 1 搜索产出的输入，生成阶段只读不改。
2. **图片来源唯一**：报告中所有图片必须来自 `addition_info`，禁止引入外部图片或占位图。
3. **图片不重复**：同一张图片（按 `@@IMG_<id>@@` 标记）全文仅出现一次。
4. **图文相关**：配图必须与文本语义相关，无相关图片时该段可不配图，宁缺毋滥。
5. **顺序依赖**：每步依赖前一步产出，必须按顺序执行。
6. **指令文件延迟读取**：reference 文件仅在对应步骤时才读取，不要提前加载。
7. **残留标签兜底**：若数据中存在无法解析的 `<sup>`、`\u003Csup\u003E` 等 HTML 标记，写作时直接忽略，不引入报告。
