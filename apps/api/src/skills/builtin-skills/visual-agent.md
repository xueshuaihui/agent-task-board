# Visual Agent —— 图片/视频内容交付入口

## 概述与调用方式


**脚本默认自动从 session jsonl 抽取用户原始 query（纯代码链路，不经过模型，零改写风险）**，无需手动传 query。

### 参数说明

| 参数          | 必填   | 说明                                                                                                                                                                           |
| ------------- | ------ |------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `--query`     | 否     | 任务描述（**可选**）。不传时自动从 session jsonl 抽取用户原文（推荐）。**以下场景必须手动传 `--query`**：1) 多轮重做/迭代，当前消息不足以描述完整需求时；2) 用户任务复杂（生图只是其中一步），需要把生图需求单独摘出来传入；3) 用户要求的视频时长超过 15 秒，需把时长收敛为「时长 15 秒」时。**传了 `--query` 后脚本直接使用该内容，不再从 session 抽取** |
| `--media-type`| 否     | 交付物媒体类型。可选值：`image`（图片）、`video`（视频）。不传时服务端根据 query 自动判断。**视频类需求必须传 `--media-type video`**，图片类需求推荐传 `--media-type image`。详见下方「`--media-type` 使用规则」 |
| `--duration`  | 否     | 视频时长，**只支持 3-15 秒的整数**。用户明确指定时长时必须传，**且必须同时把时长明文写进 query**（如「时长 5 秒」）；不传时脚本会在视频任务下从 query 解析时长并收敛到 3-15 秒后透传。详见下方「视频时长规则」 |
| `--context`   | 否     | 补充背景信息（如 search 收集到的资料）。支持传文本字符串或文件路径（推荐写文件再传路径，避免 shell 转义问题）。脚本自动拼接到 query 后面并标注为“仅供参考”，用户原文不受影响。**限制 1024 字符以内**，超出会被截断。**只传关键摘要信息**                                      |
| `--src-paths` | 否     | 本地文件绝对路径列表（空格分隔），用于传入本地图片和上一轮 MEDIA 输出路径，统一存放在 `/root/userdata/attachment/` 下，请严格传入本地绝对路径。图生视频场景传入图片作为首帧/参考帧                                                                                    |

### `--media-type` 使用规则

| 场景 | 传值 | 说明 |
| --- | --- | --- |
| 用户明确要图片（如“生图”、“做海报”、“画壁纸”） | `--media-type image` | 服务端只走图片生成工具 |
| 用户明确要视频（如“生视频”、“做一段动画”、“让图动起来”、“图生视频”） | `--media-type video` | 服务端只走视频生成工具 |
| 无法明确判断图片还是视频 | 不传 | 服务端根据 query 内容自行决策 |

> ⚠️ **视频需求必须显式传 `--media-type video`**，否则可能被服务端错误路由到图片生成。图片需求推荐传 `--media-type image`，不传也可工作但有误判风险。

### 视频时长规则

单个视频只支持 **3-15 秒**，15 秒是服务端能力上限。

| 用户时长要求 | 处理方式 |
| --- | --- |
| 未提时长 | 不传 `--duration`，也不要在 query 里编造时长，交服务端判断 |
| 3-15 秒 | 传 `--duration <秒数>`，**并保证时长明文在 query 里**（用户原话已含时长时自动抽取即可） |
| 超过 15 秒 | **不要拒绝任务**：传 `--duration 15`，并手动传 `--query` 把时长改写为「时长 15 秒」，其余需求原样保留 |
| 需要更长成片 | 交付后说明只能拆成多段分别生成、由用户自行拼接（本技能不支持视频二次编辑） |

> ⚠️ `--duration` 只接受 3-15 的整数，传 `--duration 30` 会直接报错退出。用户要 30 秒时传 `15`，不要传 `30`。
>
> 未显式传 `--duration` 时，脚本会在 `--media-type video` 下从 query 解析时长（支持「30 秒」「五秒」「10s」等写法）并收敛到 3-15 秒，因此即使忘传也不会超限；但交付说明里仍要告知用户实际时长。

超限时的交付说明话术示例：「单次视频最长 15 秒，已按 15 秒为你生成。需要更长的成片可以拆成几段分别生成。」

### ⚠️ 超时设置

visual task任务可能需要 30 分钟。调用时必须设置：

- exec 设置 yieldMs 为 1800000（30分钟）

## 禁止清单（违反任何一条都是严重错误）

1. **禁止绕过脚本**：禁止使用 curl/fetch/wget 等方式手动提交任务或查询状态，必须且只能使用 `run_visual_task.py`。
2. **禁止自行展示结果**：禁止用 Markdown 图片/视频语法 `![](url)`、Markdown 链接、HTML img/video 标签或裸路径展示交付物。**唯一合法格式**：`MEDIA:{本地文件路径}`，每行一个（图片和视频均适用）。
3. **禁止在 query 中添加用户没说过的细节**：query 直接传用户原话（加上需求确认阶段补充的信息）。远程 Agent 会自行设计配色/字体/构图/运镜，你添加的具体细节会覆盖其专业判断。把超过 15 秒的时长收敛为「时长 15 秒」不算添加细节。
4. **禁止在 query 中包含文件路径**：本地文件走 `--src-paths`。
5. **禁止重复提交同一任务**：任务已确认失败且用户明确要求重试时才可重新提交。
6. **输入限制**：`--src-paths` 最多 8 张图片（仅支持图片，不支持视频输入），超过必须拒绝。
7. **输出限制**：单次最多生成 15 个文件（图片或视频），超过必须拒绝。
8. **视频时长上限 15 秒**：单个视频只支持 **3-15 秒**。用户要求更长的视频时**不要拒绝任务**，传 `--duration 15` 按上限生成，并在交付说明里告知上限（见「视频时长规则」）。禁止传 `--duration 30` 等超出 3-15 的值，脚本会直接报错退出。
9. **MEDIA 路径一律是本地路径**：后续使用时必须通过 `--src-paths` 传入。
10. **不支持视频编辑/修改**：仅支持视频从零生成（文生视频、图生视频），不支持对已有视频进行编辑、修改、裁剪、加字幕等二次加工。若用户要求修改/编辑已生成的视频，必须拒绝并说明：「视频不支持二次编辑，只能重新生成。如需调整，请描述新的需求，我会重新为你生成。」

## 调用前：需求确认与追问

调用前确认用户是否已提供以下关键信息，缺失必填项时**合并为一次提问**：

| 维度         | 是否必填 | 说明                                                                                 |
| ------------ | -------- | ------------------------------------------------------------------------------------ |
| **用途**     | ✅ 必填  | 活动宣传、产品推广、节日庆典等                                                       |
| **目标受众** | 🔶 推荐  | 年龄层、兴趣偏好、消费群体（个人用途如壁纸、头像、贺卡等可默认为用户本人，无需追问） |
| **核心信息** | ✅ 必填  | 标题、关键文案、关键视觉信息                                                         |
| **风格偏好** | ⬜ 可选  | 赛博朋克、扁平化、国潮等                                                             |
| **尺寸规格** | ⬜ 可选  | 1920×1080、手机/桌面等                                                               |
| **时长**     | ⬜ 可选  | 仅视频任务需要，支持 3-15 秒；明确指定时通过 `--duration` 传入并把时长明文写进 query，未提时长不要自行编造。**上限 15 秒，超过则按 15 秒生成并在交付说明里告知，不要为此追问或拒绝** |
| **动态描述** | ⬜ 可选  | 仅视频任务可选，描述画面运动/运镜效果（如"镜头缓慢推进"、"花瓣飘落"）               |

**追问规则**：

1. **智能推理**：用户描述中已隐含的维度视为已提供（如"六一儿童节活动海报"隐含用途+受众+核心信息，直接调用）
2. **合并询问**：将所有缺失的必填项合并为一次提问，不要逐个追问
3. **素材缺失追问**：需求明显依赖图片输入（如"把这张照片转成动漫风格"、"把这张图做成动态视频"）但未提供素材时，必须追问
4. **信息充足即调用**：必填项全部确认后立即调用，不做多余确认
5. **信息补充**：以下情况应先收集素材再传给 visual-agent：
   - **用户当前轮次上传图片** → **必须**将用户上传的文件本地路径通过 `--src-paths` 传入（这是最高优先级，即使历史中有 MEDIA 路径也要以当前轮上传为准）
   - 需要搜**图片素材**时 → 调用 `image-search` skill，将结果图片下载到 `/root/userdata/attachment/` 后通过 `--src-paths` 传入（如"帮我把xx产品P到我家客厅"用户给了客厅照片但没给产品图、"用某明星的照片做一张电影海报"但没给明星照片）
   - 需要从**网盘**获取图片/资料时 → 调用网盘相关 skill 将文件下载到 `/root/userdata/attachment/` 后通过 `--src-paths` 传入（如"帮我把网盘里那张照片做成海报"、"修改我网盘里的那张设计图"）
   - 需要搜**文字资料**时 → 调用 `search` skill，将搜索结果通过 `--context` 传入（如用户说"帮我做XX公司的宣传海报"但没给公司资料、"根据最近的AI新闻做一张信息图"）
   - **素材下载统一规范**：所有搜索到的图片、网盘下载的文件统一存放到 `/root/userdata/attachment/` 目录下，做好文件命名避免重复。传入 `--src-paths` 前必须确认文件路径有效（文件存在且为支持的格式），无效路径不要传入
6. **澄清标记**：当模型需要向用户进行澄清追问时，必须在回复内容的**结尾**添加 `[CLARIFY]` token，用于标识当前回复为澄清类型。

## 脚本输出与结果展示

脚本自动提交任务并轮询，完成后输出 `MEDIA:{本地文件路径}` 格式的交付物（每行一个，图片为 `.png`，视频为 `.mp4`）。脚本会在以下情况自动报错退出（无需 LLM 提前校验）：`--src-paths` 超过 8 个、传入视频文件、路径不是绝对路径、路径不在 `/root/userdata` 下、文件不存在、`--duration` 不在 3-15 之间。

**成功时**：**你的回复必须包含 `MEDIA:` 行，这是唯一的交付方式。** 从脚本 stdout 中提取所有以 `MEDIA:` 开头的行，**逐行原样复制**到你的回复中。没有 `MEDIA:` 行 = 没有交付 = 任务失败。

**输出格式（必须严格遵守）**：

```
# 图片输出示例
MEDIA:/root/userdata/workspace/visual_agent/xxx.png
MEDIA:/root/userdata/workspace/visual_agent/yyy.png

图片已生成，共 2 张。还需要调整吗？

# 视频输出示例
MEDIA:/root/userdata/workspace/visual_agent/xxx.mp4

视频已生成。还需要调整吗？
```

> ⚠️ **`MEDIA:` 行必须放在回复最前面**，先输出所有 `MEDIA:` 行，再输出简短的文字说明。
>
> ⚠️ **严禁编造路径**：路径必须100%来自脚本 stdout 输出的 `MEDIA:` 行，逐字符复制，有几行就输出几行，不多不少。路径均以 `/root/userdata/workspace/visual_agent/` 开头，如果不是，说明抄错了。
>
> ⚠️ **禁止只输出文字描述而不输出 `MEDIA:` 行**：如"图片已生成！"但没有 `MEDIA:` 行，这是严重错误。

**失败时**：脚本可能仅输出错误信息而没有 summary 或交付物。此时**必须将错误信息如实总结后转述给用户**，不要忽略或吞掉 error 内容。常见错误类型及建议：

- **文件不存在/类型不支持** → 提示用户检查文件路径或格式
- **任务执行失败** → 建议用户稍后重试或调整需求描述
- **超时** → 说明任务可能仍在处理中，不要重复提交，建议稍后再查
- **配额/限额相关**（如每日生成次数已用完） → 如实输出：今日剩余额度不足，请明天再来。
- **其他未知错误** → 将 error 原文摘要展示给用户，不要隐藏细节

> **核心原则**：无论脚本返回了什么，只要没有成功的交付物（`MEDIA:` 路径），就必须从输出中提取错误信息并以用户可理解的方式总结反馈，严禁返回空内容或仅说"失败了"而不提供原因。

## 多轮对话：MEDIA 路径传递规则

当用户需求涉及对之前生成的图片进行操作（如“换背景”、“做成动态的”、“重新做”、“把这张图做成视频”），且未提供新素材时，需从对话历史中提取参考文件。**核心判断：区分“修改”和“重做”。**

> ⚠️ **视频不可编辑**：若用户要求修改/编辑已生成的视频（如“把视频换个背景”、“视频改成竖版”），必须拒绝并引导用户描述新需求重新生成，不要尝试将 `.mp4` 路径传入 `--src-paths`（脚本会拒绝）。

### 修改 vs 重做

| 意图                               | 关键词                                           | 传入的参考文件                                                                                  |
| ---------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **修改**（在上一轮结果基础上调整） | "换成"、"调整"、"改成"、"基于这个" | 上一轮助手回复中的 `MEDIA:` 本地路径 → `--src-paths`                                          |
| **重做**（对结果不满意，从头来过） | "重做"、"重新"、"再来"、"不行"、"不好"、"换一个" | 回溯到用户最初上传的原始文件（本地路径 → `--src-paths`），忽略中间 MEDIA 路径 |
| **图转视频**（将已生成图片做成视频） | "做成视频"、"动起来"、"做成动态的" | 上一轮助手回复中的图片 `MEDIA:` 本地路径 → `--src-paths`                                     |

**通用规则**：

- **当前轮上传文件优先**：若用户在本轮对话中上传了图片，**必须**将其本地路径通过 `--src-paths` 传入，且优先级高于历史 MEDIA 路径（即使用户说"基于上一张改"，只要本轮有新文件，就以新文件为准）
- **默认不传 `--query`**，让脚本自动从 session 抽取用户原文
- **以下场景必须手动传 `--query`**（传了后脚本直接使用，不再从 session 抽取）：
  - **多轮重做/迭代**：当前消息不足以独立描述完整需求时（如"不好，重新做"），从对话历史中合成完整需求描述传入，**不得遗漏用户的任何需求信息**
  - **复杂任务拆分**：用户的原始任务涉及多个步骤（如"帮我写一篇文章配一张封面图再做成PPT"），生图只是其中一步。此时**必须把生图需求从复杂任务中摘出来**，只将生图相关的描述通过 `--query` 传入，不要把整个复杂任务丢给 visual agent
  - **最新消息不完整**：用户最新一条消息无法独立表达完整生图意图（如只是补充了风格、确认了追问、回复了"好的"等），需要结合上下文才能理解。此时**必须从对话历史中合并出完整的生图需求描述**通过 `--query` 传入
  - **视频时长超过 15 秒**：用户原文里的时长超过上限（如"做个 30 秒的视频"）时，手动传 `--query` 把时长改写为「时长 15 秒」并传 `--duration 15`，其余需求原样保留（见「视频时长规则」）
  - ⚠️ **`--query` 准确性要求**：无论哪种场景，手动传入的 `--query` 必须**准确、完整地覆盖用户的生图需求**——包括风格、内容、文案、尺寸等用户提到的所有生图相关信息，不得遗漏、不得添加用户没说过的细节（把超限时长收敛为 15 秒是唯一例外）
- 单个文件操作只取一个 MEDIA 路径，多文件操作按需提取，合计不超过 8 个
- 用户明确提供了新文件时，优先使用新文件，忽略上述逻辑
- 重做场景下找不到原始文件时，通过 `--query` 传入合成的完整需求描述
