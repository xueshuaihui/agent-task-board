> 本技能由千问工作台技能降级迁移，原平台专属能力不可用。

# 舆情收集技能

在社交平台搜索并收集真实用户发布的讨论、评价、观点等内容。支持站点、登录要求均由配置文件 `sites.yaml` 控制。

## ⚠️ 功能限制

**本技能不支持以下功能：**

- ❌ **热搜/热榜/爆款收集** — 不支持获取微博热搜、抖音热搜、知乎热榜、B站热搜、小红书热搜等平台的热门话题榜单
- ❌ **热门话题爬取** — 不支持自动抓取平台热门话题排行
- ❌ **高赞/热帖收集** — 不支持筛选或收集某平台上的高赞内容、热帖、热门笔记等。舆情收集针对关键词搜索用户讨论，不按热度排序


## ⚠️ 调用限制

**本技能执行时必须遵守以下限制：**

- ⛔ **单站点单次调用** — 一次任务只能指定一个站点，多个站点需要分别调用多次
- ⛔ **禁止并行调用** — 多个站点任务必须串行执行，不能同时发起多个舆情收集任务

**示例：**

- ✅ 正确：先调用微博收集 → 等待完成 → 再调用小红书收集
- ❌ 错误：同时调用微博和小红书收集任务

## ⚠️ 站点/任务不支持时的处理

当站点不在支持列表中或任务类型不匹配时，**可使用 browser-skill 技能作为替代方案**，避免直接拒绝。

## 支持的功能

✅ 搜索特定关键词/话题的用户讨论  
✅ 收集产品/品牌的用户评价

## 站点配置

配置文件：`./sites.yaml`

读取配置判断：

1. **支持哪些站点** — `sites` 下的所有站点
2. **哪些需要登录** — `require_login: true` 的站点

当前支持：微博、小红书、B站、知乎、抖音。详见 sites.yaml。

## 工作流程

### 0. 判断搜索对象类型（关键规则）

**根据任务描述判断搜索目标，决定目标平台**：

| 任务类型                          | 示例                                     | 目标平台                   | 说明                                                               |
| --------------------------------- | ---------------------------------------- | -------------------------- | ------------------------------------------------------------------ |
| 搜索某平台上的话题/品牌           | "在B站搜索王者荣耀评价"                  | B站（用户指定）            | 在指定平台内搜索关键词                                             |
| 在某平台找发布过xx内容的博主/店铺 | "梳理小红书上发布过千问发布会新闻的博主" | **小红书（目标平台本身）** | 在博主所在平台内搜索其发布的内容，而非搜索外部评价                 |
| 搜索关于某平台博主/UP主的评价     | "找B站UP主epcdiy的评价"                  | **微博**（外部平台）       | 在其他社交平台搜索关于该博主的外部评价，而非在博主所在平台内部搜索 |
| 搜索关于某店铺的评价              | "找淘宝店铺xxx的口碑"                    | **微博**（外部平台）       | 在社交平台搜索用户对店铺的讨论                                     |

**核心原则**：

- 若任务为"找某平台博主/UP主/店铺的**外部评价**"，目标平台为微博等外部平台，**不是博主/店铺所在平台**
- 若任务为"在某平台找发布过xx内容的**博主/店铺**"，目标平台为博主/店铺**所在平台本身**

**示例对比**：

- ✅ "找B站UP主epcdiy的用户评价" → 目标平台：微博，搜索"epcdiy评价"（找外部评价）
- ✅ "梳理小红书上发布过千问发布会新闻的博主" → 目标平台：小红书（找发布内容的博主）
- ❌ 错误理解：在B站内部搜索epcdiy的评论区（这是找博主所在平台的内部内容，不是外部评价）

### 1. 确定目标平台并解析配置

**重要规则：若任务是在社交媒体或社交平台上收集舆情信息，且用户未明确指定平台，默认只使用微博进行收集。**

从用户任务描述中识别目标平台，从 `sites.yaml` 读取该站点配置，获取：

- `url`：站点主页地址
- `require_login`：是否需要登录

**示例（场景A：在某平台搜索话题）**：

- "帮我收集王者荣耀的负面评价" → 默认使用微博 → 读取微博配置
- "帮我在社交媒体上收集王者荣耀的负面评价" → 默认使用微博 → 读取微博配置
- "在微博搜索瑞幸咖啡的负面评价" → 明确指定微博 → 读取微博配置
- "在抖音搜索xxx" → 明确指定抖音 → 读取抖音配置

**示例（场景B：搜索关于某博主/店铺的评价）**：

- "找B站UP主epcdiy的用户评价" → 目标平台：微博 → 读取微博配置
- "找小红书博主xxx的舆论反馈" → 目标平台：微博 → 读取微博配置
- "找淘宝店铺xxx的口碑" → 目标平台：微博 → 读取微博配置

### 2. 判断登录需求

- **无需登录**（`require_login: false`）：直接执行舆情收集
- **需要登录**（`require_login: true`）：先调用 browser-skill 检查登录态

### 3. 检查登录态（需要登录的站点）


```bash
  --task "检查 {站点名} 是否登录，若未登录请进行登录" \
  --url "{站点URL}" \
  --max-iterations 10 \
  --output json
```

**示例（微博）：**

```bash
  --task "检查微博是否登录，若未登录请进行登录" \
  --url "https://www.weibo.com" \
  --max-iterations 10 \
  --output json
```

### 4. 处理登录结果

#### 已登录（login_required: false）

直接执行舆情收集。

#### 需要登录（login_required: true）

browser-skill 会根据 `login_type` 引导用户完成登录。**按照返回提示引导用户操作，具体流程见 browser-skill SKILL.md。**

用户确认登录完成后，**再次调用 browser-skill 确认登录态**：

```bash
  --task "检查 {站点名} 登录状态" \
  --url "{站点URL}" \
  --max-iterations 5 \
  --output json
```

确认 `login_required: false` 后继续。

### 5. 执行舆情收集


```bash
  "<任务描述>" \
  "<站点URL>"
```

**⚠️ 任务描述需完整传递用户原始要求**

包括搜索内容、时间要求、分类维度、分析方向等所有要求，不要简化或截断。完整传递才能让后端生成符合预期的报告结构。

**示例：**

```bash
  "在微博搜索王者荣耀的负面评价" \
  "https://www.weibo.com"
```

**⚠️ 注意：切勿误判为卡住而中断进程**


### 6. 呈现结果

返回 JSON 格式：

```json
{
  "success": true,
  "result": "收集到的信息汇总...",
  "reporter_html_path": "MEDIA:/path/to/report.html" // 可选，舆情收集HTML报告路径，以MEDIA:开头
}
```

失败时包含 `error` 和 `error_detail` 字段。

**结果呈现规则（区分场景）**：

**场景A：仅舆情收集（未触发search补充）**

- `result` 字段为报告的 markdown 内容
- `reporter_html_path` 为报告的 HTML 路径（格式：`MEDIA:/path/to/report.html`）
- **外层不需要额外总结**，直接将 `reporter_html_path` **单独一行原样输出**即可

**场景B：舆情收集 + search补充合并**

- `reporter_html_path` 为**中间产物**（仅舆情收集部分，非最终报告），同样是 `MEDIA:` 开头的路径
- **需合并两部分结果，生成最终markdown报告呈现给用户**
- 可选择性输出 `reporter_html_path` 供用户查看原始数据，但需注明"仅含舆情收集部分"

**⚠️ MEDIA: 路径输出规则**：

- `reporter_html_path` 返回以 `MEDIA:` 开头的路径时，**必须原样输出，不得修改或转换**
- 输出格式：单独一行，完整保留 `MEDIA:` 前缀

### 7. 结果不足时的补充策略

**触发条件**：舆情收集返回空结果或有效评价较少或不完全满足用户需求时，**必须调用 search 技能进行补充搜索**。

**补充方案**：

- 调用 search 技能进行搜索补充，将补充结果与舆情收集结果合并总结成一份完整markdown报告呈现

**强制补充场景**：

以下任务类型**必须使用 search 技能补充**：

- "找xx博主/UP主的评价"（**不包括小红书博主**）
- "找xx店铺的口碑"（**不包括小红书店铺**）
- "找xx商家的用户反馈"（**不包括小红书商家**）

这些场景用户期望全面了解外部评价，仅舆情收集可能覆盖不足，需 search 技能补充以确保结果全面性。

## 完整示例

### 微博负面舆情（需要登录）

```
用户：帮我收集微博上王者荣耀的负面评价

流程：
1. 识别站点：微博 → sites.yaml → require_login: true
2. 调用 browser-skill 检查登录
3. 若未登录：按 browser-skill 引导用户扫码
4. 用户确认完成 → 再次调用 browser-skill 确认登录态
6. 返回结果
```

### 抖音话题讨论（需要登录）

```
用户：在抖音搜索关于夸克眼镜的讨论

流程：
1. 识别站点：抖音 → sites.yaml → require_login: true
2. 调用 browser-skill 检查登录
3. 处理登录流程
5. 返回结果
```

## 任务示例

**场景A：在某平台搜索话题/品牌**

```
"在微博搜索瑞幸咖啡的负面评价"
"在抖音搜索夸克眼镜的讨论"
"在小红书收集iPhone 16的用户评价，按外观、性能、拍照、价格四个维度分类整理"
"在微博搜索瑞幸咖啡近7天的讨论"
```

**场景B：搜索关于某博主/店铺的评价（目标平台为微博）**

```
"找B站UP主epcdiy的用户评价" → 舆情收集(微博) + search补充
"找小红书博主xxx的舆论反馈" → 舆情收集(微博)（小红书不强制search补充）
"找淘宝店铺xxx的口碑" → 舆情收集(微博) + search补充
```

## 扩展站点

编辑 `sites.yaml` 添加新站点：

```yaml
sites:
  new_platform:
    name: 新平台名
    domain: example.com
    url: https://www.example.com
    require_login: true
```

## 注意事项

- **task 参数**：不要换行，使用英文引号包裹；若内容包含引号需转义，如：`"在微博搜索\"xxx\"的观点"`
- **超时时间**：执行时间较长，建议设置不少于25分钟
