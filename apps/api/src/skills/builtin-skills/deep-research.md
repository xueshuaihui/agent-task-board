# Deep Research（深度搜索 + 报告生成）

**功能定位：多源调研与研究报告生成。** 先执行搜索获取结构化数据，再基于搜索结果生成完整的 Markdown 报告（调研报告、行业/市场分析、资金走向、横向对比选型、信息收集整理成表格），并保留可点击溯源链接与核心参考文献；随后将 Markdown 终稿渲染为带主题样式与数据图表的 HTML 报告（必须产出），用户要求时可再导出 PDF。

> 与 pic-report 的区别：本 skill 面向纯文字深度调研；若用户明确要图（图文并茂、配图、收集图片），用 pic-report。
> 与 advanced-search 的区别：advanced-search 只返回搜索结果摘要，本 skill 生成完整的报告文件（Markdown + HTML，可选 PDF / Word / PPT），包含文字和表格。

**核心执行原则（本技能的编排优化都来自这四条）**：
1. **能进脚本的绝不占轮次**：目录创建、资料校验、结构检查、溯源回填、交付后检全部由打包脚本完成
2. **能并行的绝不串行**：参考文档读取、资料读取、补缺搜索，凡无依赖一律放在同一条消息并行发出。**但「并行」只适用于互不冲突的对象**：对同一文件的写入永远不属于可并行范畴（见全局约束第 7 条）
3. **写作批量落盘**：正文默认 2 批写完（1 次 Write + 1 次 Edit）；遇超时或输出超限失败时自动回退为按章节续写
4. **快速收尾**：脚本服务成功即交付，不做多余校验——收尾打包、HTML 渲染、Word 生成、PPT 生成、PDF 导出等脚本运行成功后直接进入下一环节，不回读产物全文、不逐条核对引用与数据、不重复跑校验命令、不追加人工事实核验轮次。脚本输出中的告警（如清单外标记被自动清除、格式被自动修复）视为已处理，不构成返工或额外核查的理由；仅当脚本明确报错（退出码非 0 / RESULT=FAIL）时才定位修复重跑

## 全局约束（每步执行前必须内化）

1. **数据忠实**：所有信息必须来自参考资料，严禁编造
2. **禁用 emoji**
3. **禁止调用 subagent**：整个流程由单一 agent 串行阶段完成（阶段内部可并行工具调用）
4. **绝不中断**：阶段之间不得停下来总结、确认或等待用户回复，整个流程是一次连续的自动执行；某步产出超出单次输出限制时用占位符机制分批写入，批次之间不插入任何用户交互
5. **溯源白名单纪律（防返工核心）**：阶段 0 输出「有效 REF id 清单」，阶段 2 **将该清单原样写入 outline.md 顶部注释块**，形成唯一取号依据。正文中的溯源标记**只允许逐字照抄资料原文中的 `@@REF_<id>@@`，且 id 必须在 outline.md 中固化的清单内**；清单外的一律不写，宁缺勿造。**严禁使用两类伪编号作为取号依据**：① `source_text.md` 的内部编号（搜索结果 JSON 键如 `{"44": ...}`、ITEM 序号等，均非引用编号）；② `cited_urls.md` 的 id 集合（全量映射表，可能包含有效清单之外的编号）。收尾脚本会对非法标记告警并在回填时自动清除
6. **轮次预算（自检用）**：通用模式全流程目标 ≤12 个工具轮次（含 HTML 渲染），行业模式 ≤15 个；每多一轮都要有明确理由（如资料过大需多批读取、补缺搜索、PDF 导出）
7. **同一文件的写入必须串行（硬性，最高优先级）**：对同一个文件的任何 Write / Edit 调用，必须逐条串行发起——等前一次调用返回成功后，才能发起下一次。**严禁在同一条消息中并行发出多个指向同一文件的 Write / Edit，即使它们改的是文件的不同段落、不同占位符。** 原因：每个写入调用都基于发起时刻的文件状态做匹配与落盘，并行写同一文件会产生竞态，导致 `old_string not found` 匹配失败、占位符替换丢失、内容互相覆盖。占位符续写（`<!--DR_ABS-->`、`<!--DR_NEXT-->`）的替换同样必须一个一个串行完成。此约束覆盖流程中的所有产物文件：`outline.md`、`<报告标题>.md`、HTML 报告、Word/PPT 母本。不同文件之间的写入可以并行
8. **工具约束**：`.md` 报告必须用 Write/Edit 工具写入；`.html` 由 Agent Write 骨架 + 脚本填充章节 + Agent Edit 微调，**禁止脚本一次性生成完整 HTML**，也禁止通过脚本生成报告文字内容

## 过程展示规范（面向用户的进度消息）

进度消息用「完成句 + 预告句」句式，让用户随时知道已完成什么、下一步做什么。一律使用产物语言，措辞精简、去术语。

1. **基本句式：完成句 + 预告句**
   - 模板：`{产物}完成，接下来{动作}（{起点/范围}）`
   - ❌ 大纲完成。现在撰写报告正文，先写市场与需求、供给格局。
   - ✔ 报告大纲完成，接下来撰写正文（先写市场与供给）

2. **禁止出现内部实现细节**：用户可见消息中不得出现脚本名/脚本动作、非交付产物的文件名、技能名、目录、协议、字号、驼峰标识、内部流程步骤编号。
   - ❌ 加载 pptx 技能制作幻灯片 → ✔ 开始制作汇报幻灯片
   - ❌ 执行引用回填脚本把溯源标记转链接 → 直接删除，并入下一条产物句

3. **质检消息必须带可核验数字**
   - 模板：`第 {N} 轮自检：修正 {数字}处{类别}、{数字}处{类别}` 或 `{数字}页校验通过`
   - ✔ 第二轮自检：修正 5 处重复引用、10 处模糊用词

4. **阶段切换用产物语言命名**，不用内部机制描述
   - ❌ Markdown 母本已完成两轮质检，现在生成 Word
   - ✔ 两轮质检通过，生成 Word 文档

5. **分批进度统一格式**：逐章/逐页推进时只输出 `{产物} {已完成}/{总数}`，不加"进度正常"之类的修饰
   - ❌ 正文进度正常，继续第七至十二章
   - ✔ 正文 6/12 章、幻灯片 8/12

## 执行流程（7 个阶段）

### 阶段 0：初始化 + 搜索 + 资料处理（1 轮）

**0.1 判断报告模式**：

| 模式       | 判断标准                                                                                                                                                                                                                                                                                                                |
| :--------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `industry` | 必须**同时满足**两个条件：① 用户请求包含以下关键词之一：行业分析、行业研究、赛道研究、竞争格局、行业尽调、产业分析、市场前景研判、行业深度报告；② 用户**明确要求以 Word 或 PPT 格式交付**（只认明确词汇：Word、docx、PPT、pptx、幻灯片、演示文稿；"给我一份文档""出个报告"等泛指不算，只要 PDF/Excel 等其他格式也不算） |
| `general`  | 不满足上述双条件的常规多源调研任务（包括：不含行业关键词的任务；以及命中行业关键词但未要求 Word/PPT 交付的任务，此类任务只产出 Markdown + HTML 报告）                                                                                                                                                                   |

对用户播报（硬性）：向用户告知模式结论时只说结论本身，不解释判断过程、依据或原因（如"命中行业关键词但未指定 Word/PPT 交付格式"之类的推理说明一律不输出）。通用模式只说"将按通用深度研究模式产出完整的 Markdown + HTML 调研报告"；行业模式只说"将按行业分析模式产出 Markdown + HTML 报告及 Word/PPT"。

**0.2 行业模式专属预处理**（仅 `industry` 时，在发起搜索前完成；通用模式跳过）：

直接从用户原始请求中提取研究任务要素，缺失项按下表自动取默认值并记入执行上下文（不单独生成文件）：

| 要素          | 提取与默认规则                                                                                         |
| :------------ | :----------------------------------------------------------------------------------------------------- |
| 行业/赛道边界 | 用户已说明则沿用；未说明默认：该行业通行的标准定义、覆盖全产业链上中下游                               |
| 市场范围      | 用户已说明则沿用（如用户请求含"全球"则范围为全球、含"中国"则范围为中国）；未说明默认中国市场           |
| 核心研究问题  | 从用户请求提炼一句话；无法提炼时默认："该行业的市场空间、竞争格局将如何演变，哪些环节存在结构性机会？" |
| 研究视角      | 用户已说明则沿用；未说明默认投资视角                                                                   |
| 研究时间窗口  | 用户已说明则沿用；未说明默认近 3 年                                                                    |

**默认设置明示（硬性）**：先逐项核对各要素是用户已指定还是采用了默认值；只有用户未指定、采用默认值的要素才需要说明。凡是采用了默认值的要素，必须：① 在面向用户的过程消息中用自然语言简要说明哪些要素未指定、采用了什么默认设置（不得提及步骤编号）；② 在报告「行业全景与边界界定」章节的研究范围说明中明确写明哪些要素采用了默认设置及其具体取值。严禁把用户已明确指定的要素说成默认设置。

**交付格式（无默认值，必由用户明确指定）**：进入行业分析模式的前提就是用户已明确要求 Word 或 PPT，因此交付格式直接从用户请求中提取，不存在默认格式。Markdown + HTML 报告（带可点击溯源链接）始终作为交付物，在用户指定格式之外附带交付。交付格式结果记为 `<交付格式清单>`，取值 `md+word` / `md+ppt` / `md+word+ppt` 之一。若用户中途改选格式，对已完成的母本补跑对应格式生成即可，无需重写报告。

**行业模式搜索查询构造**：读取 `{baseDir}/reference/industry-analysis-framework.md` 第一部分「研究任务与证据要求」，按其五维度搜索指令模板构造搜索查询（覆盖市场与需求/供给与竞争/驱动与趋势/企业案例/风险与前景），填入用户指定的行业、视角、范围、时间窗口，作为下面命令的第一个参数（而非用户原始描述）。

**0.3 一条链式命令完成全部阶段 0 工作**（本技能最关键的打包点，禁止拆成多条命令）：

```bash
OUT="$(python3 {baseDir}/scripts/prepare_run.py "<输出根目录>" "<general|industry>")" \
  && python3 {baseDir}/scripts/script.py "<搜索查询>" "$OUT/main_agent_context" \
  && python3 {baseDir}/scripts/replace_refs.py "$OUT/main_agent_context" "$OUT/id_to_doc" \
  && python3 {baseDir}/scripts/stage_a.py "$OUT"
```

- `<输出根目录>`：用户指定的目录；未指定则用当前工作目录。**不固定任何根路径**
- 搜索查询：通用模式用用户原始任务描述，不修改不拆解；行业模式用 0.2 构造的五维度查询
- **必须设置足够长的超时（脚本内部搜索超时 1800 秒，总计可能超过 30 分钟，即 ≥1800000 ms）**，避免长任务被提前中断或移交后台
- `prepare_run.py` 创建 时间戳+8位随机后缀 的输出目录并写入 `mode.txt`，stdout 仅输出目录绝对路径；`script.py` 产出 `id_to_doc` 与 `main_agent_context`；`replace_refs.py` 原地把 `<sup>[ID]</sup>` 替换为 `@@REF_<id>@@` 溯源标记（id 按引用次数倒序分配）并输出 `cited_urls.md`
- 命令完成后记住 `$OUT` 路径（后续所有阶段使用）
- 链尾的 `stage_a.py` 会输出：资料校验结果、`$OUT/source_text.md` 纯文本资料路径（清洗后的完整资料纯文本，含全部溯源标记）、**有效 REF id 清单**（写作白名单，必须记录）

失败处理：链式命令任一环失败，读其报错输出定位环节后重跑整条命令（`prepare_run.py` 每次生成新目录，不会污染旧目录）。

### 阶段 1：并行读取（1 轮，同一条消息发出全部 Read）

一条消息内并行读取：
- 通用模式：`reference/outline-rules.md` + `reference/writing-spec.md` + `$OUT/source_text.md`
- 行业模式：`reference/industry-analysis-framework.md`（此时读第二部分「报告结构与章节大纲」）+ `$OUT/source_text.md`（写作规范部分在行业框架第三部分，写作前再读）

`source_text.md` 较大时，在同一条消息里用多个带 offset/limit 的 Read 并行分块读完全文；**禁止**整体 Read JSON 格式的 `main_agent_context`，也**禁止**为它构建任何索引。

若读完资料发现用户要求的关键对象明显缺失，补缺搜索（ra-search）与后续大纲生成之间可并行：多个补缺搜索放在同一条消息发出，结果返回后补入写作素材。

### 阶段 2：大纲（1 轮）

- 通用模式：严格按 `outline-rules.md` 生成 `$OUT/outline.md`
- 行业模式：严格按行业框架第二部分的章节框架（按视角/时间窗口动态取舍）生成 `$OUT/outline.md`
- **白名单固化（两种模式均执行，硬性）**：将阶段 0 输出的「有效 REF id 清单」原样写入 `outline.md` 第一个 `<section>` 之前的注释块 `<!-- VALID_REF_IDS: ... -->`（格式见 `outline-rules.md`「溯源白名单固化」节）。清单照抄，不漏号、不加号；此后全程写作只从此注释块取号

### 阶段 3：正文写作（默认 2~3 轮，占位符续写机制）

**写作约束**：
- 严格遵守对应写作规范：通用模式按阶段 1 已读的 `reference/writing-spec.md`；行业模式读行业框架第三部分全文（含核心分析框架、写作质量要求与两轮自检），严格按其要求执行分析与写作
- 溯源标记逐字照抄 `source_text.md` 原文，id 必须在阶段 0 的白名单清单内
- 标题占位符约定（结构校验依赖）：全文唯一一级标题 `# `；摘要章节固定为 `## 摘要`；正文从 `## 1. ` 开始
- 数据源：`$OUT/outline.md` + `$OUT/source_text.md`；产出 `$OUT/<报告标题>.md`

**默认策略：正文分 2 批写完**

**批次 1（Write，新建报告文件，含前半部正文章节）**：

```
# <主标题>

**<副标题>**

**报告日期：YYYY年M月D日**

## 摘要

<!--DR_ABS-->

## 1. 第一章...
（前半部章节内容，覆盖约一半章节）
<!--DR_NEXT-->
```

- 文件名即报告标题，路径 `$OUT/<报告标题>.md`
- `<!--DR_ABS-->` 为摘要占位符，`<!--DR_NEXT-->` 为续写哨兵，两个占位符都要保留到对应批次替换
- 批次 1 按大纲章节数对半分（偶数章取前一半，奇数章取前一半向上取整），不硬设字数上限，但单批输出控制在单次输出能力的安全范围内

**批次 2（Edit，续写剩余全部章节）**：`old_string` 用批次 1 末尾的 `<!--DR_NEXT-->`，`new_string` 为剩余全部章节内容（不带哨兵）。

**失败回退（硬性）**：批次 1 或批次 2 因超时、输出超限（内容被截断）或其他写入失败时，自动回退为**按章节续写**：每次只写 1~2 章，用上一批末尾的 `<!--DR_NEXT-->` 作 `old_string` 续写，直到全部章节写完；回退后不再尝试大批量重写。已写入的批次内容一律保留，不重复重写已有章节。截断场景下：先用 Read 确认文件实际写到哪一章，从下一章节起续写，哨兵缺失则补在文件末尾后再续写。

**末批同步**：全部正文写完后，依次用两个 Edit 完成：① 把 `<!--DR_ABS-->` 替换为基于已写正文提炼的 200~400 字摘要；② 确认哨兵已清除。**两个 Edit 指向同一文件，必须串行发起（第一个返回成功后再发第二个），禁止放在同一条消息并行**（见全局约束第 7 条）。

**行业模式附加（硬性）**：写作完成后、进入阶段 4 前，必须执行行业框架第三部分的两轮质量自检（第一轮：证据与逻辑审查；第二轮：洞察深度审查），自检发现的问题在本阶段内修复，不另占轮次；自检通过后才执行阶段 4。

### 阶段 4：收尾打包 + Word/PPT（通用 1 轮 / 行业 2~3 轮）

**快速收尾（硬性，贯穿本阶段）**：各脚本服务（收尾打包、Word 生成、PPT 生成）一旦运行成功，立即进入下一环节，不追加任何脚本之外的校验——不回读产物全文、不逐条核对引用与数据、不重复跑校验命令、不安排额外的事实核验轮次；脚本输出中的告警（清单外标记被自动清除、格式被自动修复等）视为已处理。仅当脚本报错（退出码非 0 / RESULT=FAIL）时才定位修复重跑。

**4.1 收尾打包（1 轮，一条命令）**：

```bash
python3 {baseDir}/scripts/stage_e.py "$OUT" "$OUT/<报告标题>.md"
```

脚本一次完成：结构检查（一级标题唯一、摘要存在、占位符清除、无 section 标签）→ 溯源标记合法性告警 → 调用 `append_refs.py` 回填溯源链接（把 `@@REF_<id>@@` 替换为上标引用 `<sup>[站点名](url)</sup>`，相邻并列的多个引用合并为一组、以英文逗号分隔）并追加核心参考文献 → 回读后检 → 输出交付信息。
- 结构检查不通过会以退出码 1 报出具体问题，修复后用 Edit 改报告再重跑本命令（幂等，可安全重跑）
- 脚本输出"交付信息"即表示 Markdown 终稿完成（后续 HTML/Word/PPT 均以此终稿为底稿）

**4.2 Word/PPT 生成（仅行业模式，按 `<交付格式清单>`）**：

#### 生成 Word 文档

若 `<交付格式清单>` 含 `word`（即用户明确要求了 Word），执行本步；否则跳过。调用**固定脚本**将已回填为 `[站点名](url)` 内联链接的 Markdown 母本转换为 Word（.docx）：

```bash
python3 {baseDir}/scripts/md_to_docx.py "$OUT" "<报告标题（不含扩展名）>"
# 读取 $OUT/<报告标题>.md，输出 $OUT/<报告标题>.docx
```

- **数据忠实（硬性）**：Word 上的每一个数字、结论、案例必须取自 `<报告标题>.md`，不得改写数据或结论语义。
- **引用格式（硬性）**：正文中的 `<sup>[站点名](url)</sup>` 上标引用转为可点击的上标式引用，点击**直接打开该条参考文献的原文网页**（外部超链接），并列引用间的逗号同样上标；文末「核心参考文献」在 Markdown 中每条引用独立成行（标题完整、不显示条数统计），转 Word 时按一条引用一行渲染，每条标题为可点击的外部链接，不显示冗余网址文本。
- 保持金字塔结构：标题层级、结论先行、表格、溯源链接。
- 产出 `$OUT/<报告标题>.docx`。

#### 生成 PPT 演示文稿

若 `<交付格式清单>` 含 `ppt`（即用户明确要求了 PPT），执行本步；否则跳过。将**报告核心内容**（从 `$OUT/<报告标题>.md` 提炼，而非凭空重写）调用 **pptx 技能**制作成 PPT（.pptx）演示文稿：

- **数据忠实（硬性）**：PPT 上的每一个数字、结论、案例必须取自 `<报告标题>.md`，严禁在脚本里填入报告中没有的数据；提炼时可以删减、归纳措辞，但不得改写数据或结论语义。
- 面向高管/投资人汇报场景，结论先行（每页标题均为判断句式 action title）
- **页数约束（硬性）**：默认 **8~12 页**，超出需合并或精简。若内容庞杂超 12 页，优先删减重复论述而非堆页。
- **密度约束（硬性）**：单页要点 ≤5 条；单条要点尽量控制在一行或两行内；整页核心要点总字数 ≥120 字（避免空页）。
- **配图策略（硬性）**：行业分析是数据密集型报告，**默认不配 AI 装饰图**。视觉主体用数据图表、表格、规则线、大数字呈现；封面用深色底 + 规则线 + 文字构图即可，不依赖封面配图。仅当某页确需具象示意图时才配图，且全篇 ≤2 张。
- **讲者备注（硬性）**：每一页调用 `slide.addNotes()` 写入讲者备注，内容为该页汇报要点（取自报告对应章节），供主讲人使用。
- **默认风格（硬性）**：使用 pptx 技能风格库中的 **`McKinsey Academic Report`（风格 id 40）**——麦肯锡学术报告风：深蓝结构色 + 学术深红强调、发丝线分隔、判断式 action title、数据表格与来源脚注。除非用户明确指定其它风格，不得更换。封面用深蓝底 + 规则线 + 文字构图。
- 结构建议：封面 → 执行摘要（总判断+核心发现）→ 行业全景与边界 → 市场与需求 → 供给与竞争格局 → 驱动与趋势 → 代表企业案例 → 吸引力-竞争力矩阵 → 核心洞察 → 风险与反面证据 → 前景研判与情景分析 → 对不同参与者启示 → 结尾页
- 产出 `$OUT/<报告标题>.pptx`

word 与 ppt 都要时，docx 命令与 pptx 技能调用按顺序执行。

### 阶段 5：HTML 报告（必须产出文件）
