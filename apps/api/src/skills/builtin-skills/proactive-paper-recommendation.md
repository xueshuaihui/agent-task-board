# 论文推荐

确定 workflow 后按流程直接执行；已有候选满足交付要求时，优先整理并返回结果，不为追求极致完整或完美而反复规划和扩展检索。

## 输入

开始时综合可用信息：

- `query`：任务关注的主题、对象或问题；
- `task_settings`：定时任务提供的频率、数量、来源、时间范围、交付偏好，以及可能存在的任务类型；
- `memory`：用户背景、长期兴趣、已读/已推荐内容、反馈与稳定偏好。

存在任务设置时，将其作为本次执行的主约束；记忆用于补全与个性化，不覆盖明确设置或 Query。缺失信息只有在会实质改变候选集合或交付结果时才询问。

## 公共流程


1. 整理本次主题、适用的时间范围、硬性条件、数量和用户偏好；定时任务同时确定本次增量窗口。
2. 用户明确要求近期、最新、前沿或其他高时效内容时，直接按能力选择专业学术来源；其他任务先调用一次内部学术搜索。必要时使用 Web Search 补充。
5. 合并重复版本，排除明显不相关的候选。候选信息不足时，优先从已有结果中选择信息更完整的论文替代。
6. 按对应 workflow 和下方“输出与交付”约束组织内容并输出；不要展示内部检索、打分、路由、重试或调度过程。
7. 对定时任务，需要结合记忆中已推荐过的信息对本次推荐结果执行去重和调节。

## 输出与交付

- 报告中的范围说明和最终摘要只呈现时间范围、主题边界、纳入与排除条件，以及面向用户的覆盖结论。不得呈现检索来源组合、接口参数、查询轮次、失败与回退过程、候选数量漏斗、内部打分或调度信息。论文原文、DOI 和出版平台等证据链接可以展示；它们不等同于论文发现渠道。
- 普通论文推荐生成 UTF-8 编码的 Markdown 文件（`.md`），文件是完整正文载体。优先采用用户指定的文件名和保存位置；未指定时，在当前任务允许写入的输出目录中，以主题和日期生成清晰、可识别且不覆盖已有文件的文件名。
- 标准最终回答必须同时提供一段简短的内容摘要和可点击的 Markdown 文件链接。不得只返回文件路径，也不必在最终回答中重复展示 Markdown 文件的完整正文。
- 无论采用哪种交付形式，都不得把内部候选、检索日志或中间产物当作最终报告。

## 共同质量要求

- 每个核心结论应有入选论文或可靠来源支持。
- “最新”以首次公开时间和任务增量窗口为准。
- 不因标题吸引人而牺牲相关性与证据质量。
- 候选不足时缩小交付规模并用面向用户的结果表述说明覆盖边界，不展开内部检索或失败过程，不用弱相关内容凑数。
