# 新闻日报（Daily News Briefing）


为用户提供**个性化定制**的新闻日报服务，覆盖科技、财经、产业、国际等多个领域。本 Skill 是所有**定时/周期性新闻推送需求**以及**即时今日新闻速览需求**的统一入口，不应绕过本 Skill 直接用八爪鱼调度拼接其他新闻 skill。

## When to Use

### 强制触发场景（MUST USE）

满足以下**任一条件**即**必须**调用本 Skill：

**条件 A：定时/周期类** — query 同时包含「时间/周期」+「新闻/资讯」两类信号：

| 用户 query 示例 | 触发原因 |
|----------------|----------|
| "每天早上8点帮我搜索并总结今日AI和科技行业的重要新闻" | 定时 + 新闻搜索总结 |
| "帮我设置一个每日新闻早报" | 定时 + 早报/日报 |
| "我想每天看科技资讯" | 每天 + 资讯 |
| "定时推送财经新闻给我" | 定时推送 + 新闻 |
| "能不能每天帮我整理行业动态" | 每天 + 动态整理 |
| "帮我订阅AI领域的每日快讯" | 订阅 + 每日 + 快讯 |
| "设置一个早上的新闻推送" | 设置 + 新闻推送 |
| "每天定时给我搜一下最新的XX新闻" | 定时 + 搜索 + 新闻 |
| "帮我做一个科技日报" | 日报 |
| "有没有定期推送新闻的功能" | 定期推送 + 新闻 |

**条件 B：即时今日新闻类** — query 包含「今日/今天」+「新闻/早报/资讯」信号，表达想看当天新闻的意图：

| 用户 query 示例 | 触发原因 |
|----------------|----------|
| "帮我看看今天有什么新闻" | 今天 + 新闻 |
| "今日新闻早报" | 今日 + 早报/日报 |
| "收集下今天的科技新闻" | 今天 + 收集 + 新闻 |
| "帮我整理一下今日AI领域的动态" | 今日 + 动态整理 |
| "今天有什么值得关注的资讯" | 今天 + 资讯 |
| "看下今日热点新闻" | 今日 + 热点新闻 |
| "帮我汇总今天的财经新闻" | 今天 + 汇总 + 新闻 |

### 触发关键词清单

**时间/周期类**：每天、每日、定时、定期、早上X点、每周、周期性、早报、日报、持续关注、长期跟踪、订阅

**即时今日类**：今天、今日、当天、本日、今天的、今日的

**新闻/内容类**：新闻、资讯、快讯、动态、早报、简报、热点、行业报告、搜索并总结、新闻推送

> **规则**：
> - 当 query 出现「时间/周期类」+「新闻/内容类」组合时 → 触发（**定时模式**：新建定时任务，走八爪鱼注册；先拆「频率+时间+内容」三要素）
> - 当 query 出现「即时今日类」+「新闻/内容类」组合，或为**不含频率/时间的纯内容请求（含八爪鱼到点回调）** 时 → 触发（**即时模式**，跳过澄清直接执行）
>
> **判定要点**：带**频率+时间信号**的原句（如「每天 16:38 推送 A 股行情简报」）= 新建定时（八爪鱼注册）；**不含频率/时间的纯内容请求**（如「推送 A 股行情简报」「生成今日科技新闻日报」，也包括八爪鱼回调发来的消息）= 即时执行。这正是三要素拆分要「回调只发内容」的原因——防止回调消息里的频率/时间信号把即时执行误判成新建定时。

### 与八爪鱼调度的关系

**重要**：本 Skill 与八爪鱼定时调度是**协作关系**而非替代关系：
- **八爪鱼** 负责时间调度（何时触发、按什么频率触发）
- **daily-news-briefing** 负责执行逻辑（执行什么、怎么执行）

#### 三要素拆分（CRITICAL — 防重复注册的核心机制）

在把定时任务交给八爪鱼之前，**必须**先把用户的定时 query 拆成**三要素**，分别派往不同用途：

| 要素 | 示例 | 用途 |
|------|------|------|
| **频率** | 每天 / 每周 | 仅用于八爪鱼的定时调度设置（schedule），**不进入回调消息** |
| **时间** | 16:38 | 仅用于八爪鱼的定时调度设置（schedule），**不进入回调消息** |
| **内容** | 推送 A 股行情简报 | 仅作为八爪鱼到点回调时发送的**消息体**，**不含频率/时间** |

> 举例：query「每天 16:38 给我推送 A 股行情简报」拆为——频率=`每天`、时间=`16:38`、内容=`推送 A 股行情简报`。八爪鱼调度设置吃「每天 + 16:38」；到点回调只发「推送 A 股行情简报」（或「生成今日 A 股行情简报」），**绝不带「每天/16:38」**。

**为什么必须拆**：如果把完整定时 query（含「每天 + 16:38」这类频率/时间信号）整句交给八爪鱼，八爪鱼到点回调时会**原样带回整句**，其中的频率/时间信号会**再次命中**本 Skill 的「时间/周期信号 + 新闻信号」定时设置分支，导致**重复注册定时任务 / 重复触发**。只发「内容」部分，回调消息里就没有周期/时间信号，本 Skill 只会走「即时执行 / 生成日报」分支，不会被误判为「新建定时任务」。

正确的工作方式：
1. 用户说"每天早上8点帮我搜索AI新闻" → Agent 在**主会话中**调用本 Skill
2. 本 Skill 在主会话中以多轮对话完成澄清（不 yield、不 spawn subagent）
3. 澄清得到「领域 + 时间」后，将 query 拆为「频率 + 时间 + 内容」三要素
4. 「频率 + 时间」写入八爪鱼定时调度设置；「内容」（如「生成今日科技新闻日报」）登记为八爪鱼到点回调时要发送的消息体
5. 八爪鱼到点回调 → 回调消息**只含「内容」**（无频率/时间）→ 命中本 Skill 的「即时执行 / 生成日报」分支 → 直接读取 profile 执行采集与生成（**不澄清、不再注册新任务**）

**错误的工作方式**：
- 把含「每天/16:38」的整句 query 直接交给八爪鱼当回调消息（会导致重复注册，见上）。
- 直接用八爪鱼创建一个简单任务，绕过本 Skill，只调用 ra-search。这样会丧失：个性化配置、多源聚合、权威核验、格式化输出、历史追溯等能力。

> **防重复触发规则（CRITICAL）**：交给八爪鱼的**回调内容**中**禁止**出现「每天 / 每周 / 定时 / 定期 / HH:MM（如 16:38）」等任何频率/时间词。回调内容只描述「要生成/推送什么」，频率与时间只存在于八爪鱼的调度设置里。

> **字段说明**：上文「schedule / 回调消息体」为调度机制的抽象描述，八爪鱼具体 API 字段名以实际接入的八爪鱼调度接口为准（本文档不臆造字段细节）。核心不变量是：**频率+时间 → 调度设置；内容 → 回调消息，且回调消息不含频率/时间**。

### 与其他新闻类 Skill 的区分

| Skill | 适用场景 | 不适用场景 |
|-------|---------|------------|
| **daily-news-briefing**（本skill） | 定时/周期性新闻推送、即时今日新闻速览、个性化新闻日报 | - |
| news-summary | 即时获取国际新闻摘要 | 定时推送 |
| ra-search（系统工具） | 单次全面搜索 | 周期性需求 |
| cctv-news-fetcher | 获取某天新闻联播内容 | 定时推送 |
| 八爪鱼调度 | 负责「何时/按什么频率」触发（时间调度） | 执行逻辑（由本 Skill 负责） |

### 即时模式 vs 定时模式

| 模式 | 触发条件 | 是否澄清 | 行为 |
|------|---------|----------|------|
| **即时模式** | 用户说"看今日新闻""帮我收集今天的XX新闻"，或**八爪鱼到点回调**（回调消息仅含「内容」、不含频率/时间） | **不需要澄清**（或仅确认领域） | 已有 profile → 直接执行；无 profile → 根据 query/回调内容中的领域关键词直接执行，使用默认配置 |
| **定时模式** | 用户说"每天X点推送新闻"（原句含频率+时间信号） | **需确认领域；有钟点或早上/中午/晚上则不问时间** | 确认领域 + 解析推送时间 → 拆分「频率+时间+内容」→ 写入 profile → 用「频率+时间」注册八爪鱼调度、以「内容」为回调消息体，无需再确认配置 |
| **八爪鱼回调** | 定时任务到点自动回调（消息体仅为「内容」） | **不需要澄清** | 因回调消息不含频率/时间信号，命中即时执行分支 → 直接读取 profile 执行采集与生成，**不再注册新任务** |

> **即时模式关键规则**：用户只是想看今天的新闻，不要强制走完整澄清流程。如果 query 中已包含领域信息（如"今天的科技新闻"），直接用该领域 + 默认配置执行采集和生成。如果 query 未指定领域（如"帮我看看今天有什么新闻"），可快速问一句领域偏好，或直接使用综合热点模式生成。

### 主动推荐时机

当以下信号出现时，Agent 应主动推荐本 Skill：

- 用户使用过搜索或深度研究功能，且历史 query 中出现**相同领域词汇超过 2 次**
- 用户 query 暗含周期性需求（"每天"、"定期"、"持续关注"）
- 用户频繁搜索同一领域新闻

推荐话术示例：
> "你经常关注 XX 方向的内容，我可以帮你设置一个新闻日报，每天定时把最新动态整理好发给你，要试试吗？"

  ▼                                    ▼
跳过澄清                        确认领域 + 推送时间

  │                                    │
  ▼                ▼
  └──── 生成本次任务时间戳 /root/userdata/workspace/daily-news-briefing/tmp/{timestamp}/ ────┘
              │
              ▼
   Step 1 采集：ra-search 原样落盘 → 1_ra_search_raw.json
              │
              ▼
   Step 2 合并：按话题归类+去无关内容 → 2_ra_search_topic.json

              ▼

### 关键规则：三种触发模式

| 场景 | 是否澄清 | 行为 |
|------|-----------|------|
| 用户首次设置日报（定时模式） | **确认领域 + 推送时间** | query 中未指定领域时需问；推送时间按三档解析（明确钟点 / 粗粒度时段随机 / 完全未提才问），确认后拆「频率+时间+内容」三要素、写入 profile.md 并向八爪鱼注册定时任务（频率+时间→调度设置，内容→回调消息体），无需再次确认配置 |
| 用户修改配置 | **需要澄清** | 仅针对修改项澄清，更新 profile.md |
| 用户看今日新闻（即时模式） | **不需要澄清** | 有 profile → 直接执行；无 profile → 从 query 提取领域或用综合热点模式直接执行 |
| 八爪鱼定时回调 | **不需要澄清** | 回调消息仅含「内容」（无频率/时间），命中即时执行分支 → 直接读取 profile.md，执行采集与生成，不再注册新任务 |

## 第一阶段：需求澄清（仅定时模式时）

澄清只需**两项**——领域 + 推送时间。领域仅在 query 未点明时才问；推送时间仅在**未提钟点且无「早上 / 中午 / 晚上」**时才问。两项明确后直接写入 profile.md 并创建定时任务，**不要再展示配置摘要让用户确认**。

> **注意**：即时模式（用户只是想看今日新闻）**不进入此流程**，直接跳到第二阶段执行采集。
>
> 领域选择、推送时间询问、创建成功提示等**澄清话术模板见 `templates.md`**。

### 会话上下文约束（CRITICAL）

澄清阶段是**多轮对话**，必须在用户当前主会话中直接进行：

1. **禁止 yield**：澄清阶段绝对不能调用 `sessions_yield`。输出澄清问题后必须等待用户回复，不能结束 turn。
2. **禁止 spawn subagent（仅限澄清阶段）**：澄清过程不能委派给子 agent 执行，子 agent 无法与用户进行多轮对话。
3. **禁止在回调/isolated session 中澄清**：如果当前是八爪鱼定时回调触发的会话（回调消息仅含「内容」），不应进入澄清流程（应直接读取 profile 执行）。
4. **澄清 = 等待用户输入**：每输出一个澄清问题后，当前 turn 自然结束（返回文本给用户），等用户下一次输入时继续下一步。不要主动调用任何工具来"结束 turn"。

> **核心原则**：澄清是普通的文本对话，不是工具调用。输出问题文本 → 用户回复 → 继续下一步。不需要任何特殊的会话管理操作。

### 澄清红线规则（CRITICAL）

1. **禁止推断领域**：用户未点明领域时必须问（「帮我设置一个早报」不能猜领域）。把「早上 / 中午 / 晚上」映射成窗口内的 `HH:MM` **不是**推断预填，不得因此再问时间。
2. **完全没提时间才问**：未提钟点、也没有「早上 / 中午 / 晚上」时必须问，**禁止默认 08:00**。有钟点或上述时段词 → 按「推送时间确认」取值，不得再追问。
3. **不需要配置确认**：领域与推送时间都明确后直接创建定时任务，**不要**再展示"配置摘要"让用户确认。
4. **领域须原词，时间认时段词**：领域不能靠模糊描述跳过。时间只要原句有钟点或「早上 / 早晨 / 中午 / 午间 / 晚上 / 夜里」即可跳过询问。

### 跳过判断示例

| 用户 query | 可跳过 | 仍需澄清 |
|------------|--------|----------|
| "帮我设置一个早报" | 无 | 领域 + 推送时间（「早报」是品类，不触发早上映射） |
| "每天早上8点帮我搜索AI和科技行业新闻" | 领域（=科技与AI） + 推送时间（=08:00） | 无（直接创建任务） |
| "每天早上帮我推送科技新闻" | 领域（=科技与AI） + 推送时间（早上窗口随机） | 无（直接创建任务） |
| "帮我设置科技早报" | 领域 | 推送时间（仅有「早报」、没有「早上」） |
| "帮我关注财经新闻的每日报告" | 领域（=财经与市场） | 推送时间 |
| "每天下午推送财经新闻" | 领域（=财经与市场） | 推送时间（「下午」不在映射窗口） |
| "帮我设置科技早报，每天早上 9 点推送" | 领域 + 推送时间（=09:00） | 无（直接创建任务） |

### 确认感兴趣的领域

当用户 query 未明确指定领域时（如"帮我设置一个早报"），问领域选择：

```
你主要对哪个方向感兴趣？选一个或几个，我来帮你定制：

1. 科技与 AI
2. 财经与市场
3. 产业与政策
4. 国际时事
5. 娱乐与文化
6. 消费与生活
7. 其他（自定义描述）
```

如果用户已明确说了领域（如"科技新闻"、"AI行业动态"、"财经早报"），跳过此步，再按「推送时间确认」取值（有早上/中午/晚上则不问）。

### 推送时间确认（按三档解析，禁止模型口头「随便挑」）

按优先级取一个 `HH:MM`，取到即跳过询问、直接创建定时任务：

**档 1 — 明确钟点（原词，不随机）**  
query 已含可解析的钟点（如「每天早上8点」「每天 9:30」「晚上 8 点」「下午三点」）→ 按原词取值（下午三点 → `15:00`）。

**档 2 — 粗粒度时段（窗口内随机，不再追问）**  
无明确钟点，但原句含**恰好一个**可映射时段词时，用一次 shell 抽出 `HH:MM`（左闭右开、**15 分钟一档** `:00/:15/:30/:45`；**禁止** Agent 自己猜整点）：

| 原句信号 | 窗口 | 取值命令 |
|---------|------|----------|
| 早上 / 早晨 | `08:00`–`09:59` | `printf '%02d:%02d\n' $((8 + RANDOM % 2)) $((15 * (RANDOM % 4)))` |
| 中午 / 午间 | `12:00`–`13:59` | `printf '%02d:%02d\n' $((12 + RANDOM % 2)) $((15 * (RANDOM % 4)))` |
| 晚上 / 夜里 | `20:00`–`21:59` | `printf '%02d:%02d\n' $((20 + RANDOM % 2)) $((15 * (RANDOM % 4)))` |

边界（不走档 2，仍问）：
- **`早报` ≠ `早上`**：只有「早报」、没有「早上 / 早晨」→ 档 3
- **`下午` / `傍晚` / `凌晨` 不覆盖**：只说「每天下午推送」→ 档 3；「下午三点」已是档 1
- **多时段冲突**（「早上或晚上」「中午和晚上都推」）→ 档 3，不随机

**档 3 — 完全未提时间（必问）**  
query 未提及任何推送时间（如只说「帮我设置科技早报」），**必须问用户**，不允许默认到 08:00：

```
你希望每天几点推送新闻日报？比如早上 8 点、中午 12 点或晚上 8 点。
```

用户回复后：若给出钟点则按档 1；若只回「早上 / 中午 / 晚上」则按档 2 随机；然后进入下一阶段。

抽中或解析出的 `HH:MM` 写入 profile 与八爪鱼 schedule；成功提示须带上该时间（粗粒度映射时注明「按『早上/中午/晚上』自动选定」）。回调消息体仍不得包含该钟点或时段词。

### 领域与推送时间确认后直接创建定时任务

领域与推送时间都明确后，**不要**再向用户展示配置摘要请求确认。直接按以下默认值写入 `~/daily-news/profile.md`，并将 query 拆为「频率 + 时间 + 内容」三要素后向八爪鱼注册定时任务：

- **细分方向**：该领域下的全部热点（不限定细分）
- **新闻源**：系统根据领域默认选择（参见后文「推荐信息源」）
- **报告格式**：四模块结构（头部 + 分组正文 + 核心判断 + 附加板块）
- **推送时间**：按三档解析得到的 `HH:MM`（含粗粒度随机结果）

**注册八爪鱼定时任务时的三要素分派（CRITICAL）**：
- **频率 + 时间**（如「每天」+「16:38」）→ 写入八爪鱼的定时调度设置（schedule）
- **内容** → 作为八爪鱼到点回调时发送的消息体，只描述「要生成/推送什么」，如「生成今日{领域}新闻日报」——**绝不包含「每天 / 每周 / 定时 / HH:MM」等频率/时间词**，否则回调时会被误判为新建定时任务而重复注册

定时任务成功创建后，给用户一个简短的成功提示即可（粗粒度映射须注明来源），例如：

```
✅ 已为你创建{领域}新闻日报定时任务，每天 {HH:MM} 推送。
如需调整领域、推送时间或其他偏好，随时告诉我。
```

粗粒度时段映射时改为：

```
✅ 已为你创建{领域}新闻日报定时任务，每天 {HH:MM} 推送（按「早上」自动选定）。
想换时间随时告诉我。
```
