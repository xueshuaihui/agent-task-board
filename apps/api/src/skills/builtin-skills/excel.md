#### 主体、口径与读取

按需求和源样本确定主体、期间、单位、粒度及所需列；“申请人”“审批人”等角色不能混用，原字段程序读源保留。硬筛选逐项区分满足/不满足/未知，仅全部满足者计入合格结果；证据缺失、待确认不算通过，不为凑数量放宽门槛。要求多平台时区分已查无合格项、访问失败、未查询，说明实际覆盖与缺口。

批量取值用 `for row in ws.iter_rows(min_row=实际首行, max_row=实际末行, values_only=True)`，每行是tuple，C列取`row[2]`；零星定位、写值和样式操作用`ws.cell(行号, 列号)`，两个参数都是1-based整数。不要把值行当dict、Workbook或Worksheet。pandas默认读首Sheet；需要多Sheet时显式选择，标识列按源类型读取，前导零不能靠事后转str恢复。

```python
import pandas as pd
# 表名、表头行和类型按实际源映射；字符串NA也可能是有效编号，不能默认当缺失。
df = pd.read_excel(source, sheet_name='明细', dtype={'编号': 'string'}, keep_default_na=False)
# 确需全部Sheet时用sheet_name=None，返回Sheet名→DataFrame的dict。
```

##### 二、数据预处理

复用已取得的预检。只处理本次计算/匹配确需的字段；发现数据问题再选择处理，不默认全表清洗、拆字段或改写原文。

- **明细与汇总**：结合位置、公式和样本辨认合计/小计，不能仅凭关键词删行。明细聚合不重复计入汇总；任务要求的总计或保留行单独按原口径处理。
- **类型与单位**：参与运算的数字、日期先解析；单位换算保留原值和单位依据。标识符的前导零不是可丢弃数值。无法解析、单位冲突或缺失值不擅填0/均值，也不静默排除；按任务口径处理并计入对账。
- **比较键与显示值分开**：先确认哪些写法等价。确有格式差异且业务允许时，双方一致做 strip、NFKC；英文大小写或同义词仅在确认为同一标识时合并。精确编码、用户指定原文和有意义的空格/标点保持；不因两键相似就判同一主体，不把比较键覆盖回显示原文。

```python
# 仅用于已确认允许 strip/NFKC 的名称比较键；原列不改。
import pandas as pd
import unicodedata
def norm_key(v):
    if pd.isna(v): return None
    key = unicodedata.normalize('NFKC', str(v).strip()).strip()
    return key or None
df['_key'] = df['名称'].map(norm_key)
```

缺键记录不能自动互相匹配；pandas merge 会匹配两侧空键，连接前排除缺键并另行保留其源记录；检查清洗前后的键冲突、覆盖及源侧守恒，不能只看总数或“合并得更多”。公式比较路径采用同一已确认规则；TRIM 会改变部分内部空格，不与 Python strip 视为等价替代。

```python
# 已确定本列为纯数值金额；带单位的值先按已确认单位解析，不用正则随意删字符。
amount = pd.to_numeric(df['金额'], errors='coerce')
unparsed = df.loc[df['金额'].notna() & amount.isna(), ['编号', '金额']]
df['_amount'] = amount
```
unparsed及原始缺失保留源行映射，按口径处理并对账；只回显数量和必要样本。errors='coerce'只是定位失败值，不能随后填0、丢行或忽略它们求总量；不用宽泛except把失败列改成0。

##### 三、时间与日期处理

按任务明示或上下文确定基准时刻、时区和数据截至日期；仅实时任务未指定基准时用宿主当前时间。“24小时内发布”核发布时间，不以抓取/更新时间替代；T-3先定自然日/交易日及适用日历，不猜日期。求差、排序、比较先转日期对象，明确跨日/缺失/非法值；仅计算区间才拆起止。交付保留类型并设number_format；纯复制原文不强制转换。

```python
from openpyxl.utils.datetime import from_excel
# 仅对确认是Excel日期/时刻序列的原始数字使用；已是datetime/time的不重复转。
date_or_time = from_excel(serial, epoch=wb.epoch)
# 确认是累计时长时使用下面一行，可保留超过24小时的部分。
elapsed = from_excel(duration_serial, timedelta=True)
```
日期使用源工作簿的1900/1904纪元，不手写固定基日；小于1的时刻序列可返回time。时间段仅在计算需要时用`str.split('-', n=1, expand=True)`拆起止、`pd.to_datetime(..., format='%H:%M', errors='coerce')`解析，失败保留源定位。只有口径明确跨午夜时才给负差加一天；只有时刻不能推断跨多日，完整日期区间直接求差。

##### 四、单元格格式类型设置（货币 / 短日期 / 百分比 等）

用户明确要求以下中文 Excel 格式分类时采用对应写法；仅外观相似不代表分类相同。原模板约定优先。保留 raw string 的反斜杠转义；币种按任务替换。

|格式分类|Python `cell.number_format` 的值|
|---|---|
|数值（负数红色）|`r'0.00_);[Red]\(0.00\)'`|
|货币（人民币）|`r'"￥"#,##0.00_);[Red]\("￥"#,##0.00\)'`|
|会计专用|`r'_ "￥"* #,##0.00_ ;_ "￥"* \-#,##0.00_ ;_ "￥"* "-"??_ ;_ @_ '`|
|短日期|`'yyyy/m/d;@'`|
|长日期|`r'yyyy"年"m"月"d"日";@'`|
|时间|`'h:mm:ss;@'`|
|百分比|`'0.00%'`|
|分数|`r'#\ ?/?'`|
|科学记数|`'0.00E+00'`|

##### 五、公式设计与边界处理

公式/写值路线与最终检查见下文§2.6。

- 比率先明确分子、分母及主体集合；零分母、缺失与极值按业务口径处理，不把未知结果包装成0。可保留空值/明确标记并说明；用户必需的结果未核实就标未完成。
- 政策、金融等特殊公式缺少口径且无法从需求/数据确定时，向用户确认依据；本技能不自行搜索。
- 聚合的空值只有明确表示“无发生额”时才视为0；未知值不等于0。检查实际参与集合，避免忽略异常后得到自洽但不完整的总量。

建立真实列名→Excel整数列号、记录→源行号的映射；过滤/reset_index后的DataFrame索引不能直接加1当源行号。Excel列字母用`get_column_letter(64)`得到BL。已知少量引用的核对放进同次程序，确认范围后批量构造：
```python
from openpyxl.utils import quote_sheetname
# name、first、last来自实际源布局，first/last包含端点；先按口径处理空集合。
formula = f"=SUM({quote_sheetname(name)}!B{first}:B{last})"
```
quote_sheetname会处理Sheet名中的空格和单引号。范围覆盖全部实际明细，排除已计入的小计/合计及自身，避免循环引用；动态模板须随输入扩展。优先明确范围，不能声称SUM整列必因文本表头报错，也不将固定末行冒充动态扩展。

##### 六、排序与排名规则

仅任务要求排名时计算；排序不自动新增名次列。用户规则优先，否则标准竞赛排名：100/95/95/90 → 1/2/2/4；Excel `RANK(value, range)` 对应此默认。默认“前N名”按名次阈值，保留并列，可能多于N行；用户明确要N条时才按条数及其并列处理要求截取。

```python
df['rank'] = df['score'].rank(method='min', ascending=False)
top = df[df['rank'] <= N]
```

四人并列第一时，“前三名”保留四人；不能用 head(N)、默认 nlargest(N) 或行号替代。其他明确口径：dense 不跳号（1/2/2/3）；first 按先后不同名次；average 取平均名次（1/2.5/2.5/4）。排序方向和并列次序按任务确定，需稳定时显式指定次级键或保留源顺序，不猜业务优先级。

#### 实体关联

实体关联把源实体、属性或明细按业务关系对应；事件核销还要求一条事件消耗另一条记录，首轮整读ref-cross-table-match.md。

匹配依据来自用户指定字段、业务含义和原始样本；“看起来相同”或“匹配最多”不能证明对应正确。标识列和属性列要分清，但不是所有关系都要求每行唯一。

|关系|应检查的基数|
|---|---|
|1:1|两侧业务键均唯一；冲突需辨明来源|
|1:多|主侧唯一、明细侧允许重复|
|多:1|归属侧唯一、子项侧允许重复|
|多:多|保留合法关系，不将连接后的重复累计当原始数量|

按明确关系核验键、匹配覆盖和源侧集合/数量；聚合分母用实际参与记录。重复可能是合法明细或多源同一报告，不能任意加日期/其他字段直到唯一，也不能擅去重。用户显式键不因数据冲突自行更换；欠定部分保留来源与歧义。

比较键仅按已确认的等价规则清洗，显示原文和业务身份字段保留；空键不自动相互匹配；pandas merge 前排除缺键并另行保留，不将缺键记录丢弃。

生成前确认关系、字段对应与必要样本；生成后从原始源独立核对匹配/未匹配样本、关键字段和集合。换方向回源，不重用生成侧结果自证。已有证据充分的程序检查在同次执行中完成；真正歧义才返回模型裁决。

#### 文本抽取、分类与统计

复用主文预检，确定任务范围、目标列、记录粒度和实际行坐标。只生成用户需要的字段；内部保留源行映射，不默认新增原文、清洗、证据、备注列或汇总Sheet。

- 依据需求和少量完整样本确定字段、类别与分支优先级，已知冲突同批核实；样本用于选规则/展示，不限制已知分支检查。关键歧义才澄清，不追问源已说明的细节。
- 规则匹配、关键词替换和确定性统计一次脚本处理。标签需要语义判断时保留必要原文供判断，不将全文反复转抄。
- 用户指定原文、数字、日期、编号和非目标字段保持。去品牌/关键词只删命中片段，不把包含关键词的整条记录删除；可变实体只能在获准的主题归类键中归一化，不能覆盖身份字段。
- 模糊相似只适用于允许近似的主题/语义归类，不据此判定同一主体。词典/类别选一套符合目标的方案；无新证据不再设计，无法判断保留未知和源定位，不硬凑分类。
- 半结构化文本按上文非表格附件的方法切分、记录失败并对账。不要逐字段穷举所有变体。

按清单同次全量核字段、记录覆盖、保留内容及可程序判定的规则。核重复/只填一次的非空数量、对象和顺序，不以唯一值替代。
抽取与统计是不同结果：要求统计就从源记录数清对象和数量，不能仅录入明细后称统计完成。已核验条件不再另加“语义复审”。
交付所需结果，简述影响理解的类别/未知处理口径；没有要求就不做完整报告、方法附件、标签对照表或追溯Sheet。

### 2.6 同次生成、独立核验与发布

一次性汇总默认Python算后写值；联动/复算模板/财务模型的派生指标及需保留的原公式关系须动态计算，不用静态值/辅助区冒充。状态统计按任务定义的类别/权重计算；出勤/休假混填时，COUNTA非空数不等于实际出勤。动态模板同次在临时样本中改变任务相关状态/月期，按独立预期核公式结果；排班/调休用实际日历。普通.xlsx含公式须重算、零错误且缓存完整；无公式不启动LibreOffice。

按需求清单各R全部子条件定义独立只读谓词，从最终候选和独立源事实核结果、覆盖、保留及可读性，不能填True或用生成逻辑自证。计数/数值/覆盖全量核，语义抽查覆盖已知分支；展示限幅不限制核验。“只填一次”核非空次数。派生结果保留所需并集/单侧主体，排除或交集须需求或逐条证据。独立指验收依据来自源事实，不要求再写完整解析器或三套计数；可用源位置映射逐字段对照，并独立核记录覆盖。不要增加复核agent或额外审计阶段。


`task_checklist(work_dir, task_token, checks, *, requirements=None, parser_json=None, sheet=None, outputs=None)`返回可调用verify，不是dict；带`.required_ids`、`.checklist_path`。checks为实际R编号→函数。普通.xlsx声明`outputs=(全部最终绝对XLSX路径,)`；需求列表按§2.1传入，修复复用冻结清单；parser_json仅兼容旧脚本，新任务不用。

**新检查统一接收`(values_wb, formulas_wb)`两个Workbook，不传sheet=。** 在函数内用真实表名取Worksheet，再用`ws['B2'].value`取值；缓存值取values_wb，公式/样式/合并范围取formulas_wb。旧sheet='真实表名'调用收到两个Worksheet；不要在Worksheet上再次用表名索引或访问sheetnames。谓词返回bool/NumPy bool；False、非bool和普通异常同次汇总，不重试、不吞异常。

`save_verified(wb, filename, verify, timeout=30, *, after_verify=None)`：wb须为可写公式视图Workbook，filename只接受普通.xlsx；父目录自动创建。内部完成候选保存→必要重算→回读→全部R检查→原子发布，不另跑save/recalc/verify。发布前失败不覆盖目标；timeout须有限正数。返回键`output, checks, total_formulas, total_errors, after_verify_applied`，没有status/success/delivery_updated；工作程序无需为汇报再读成功文件。Claw骨架的after_verify=apply_aigc_watermark为核验后的最后写入，保留钩子，不重复加标。

#### 公式报错定位

按已返回位置检查源值和引用，共用同一次修复；不用IFERROR包住所有问题：

|错误|定位与处理|
|---|---|
|#REF!|引用失效或删除/移动后未更新，核真实坐标与范围|
|#DIV/0!|分母为0或空，按业务约定输出空值/标记等，不能把未知当0|
|#VALUE!|操作数类型或函数参数不合适，回源检查，勿吞掉解析失败|
|#NAME?|函数名、定义名称或引擎支持问题，核准确写法与兼容性|
|#N/A|查找未匹配等，先辨明源缺失、键或范围错误；仅预期未匹配才按口径处理|

#### 已有候选需单独重算

普通.xlsx用save_verified即可；已有CLI产物才同次调用`recalc_checked(path, timeout=30)`并独立回读。旧recalc/CLI同样须核status=success、total_errors=0、total_formulas为非负整数；有公式时还须delivery_updated=True。无公式不启动LibreOffice，Python计算不能替代必需公式缓存。
