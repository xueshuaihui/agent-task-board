
# Browser Agent

通过 LLM 驱动浏览器完成多步骤网页任务，支持登录引导、风险拦截处理。

## Quick Start

```bash
# 打开页面获取快照
python scripts/open_url.py --url <URL>

# 执行自动化任务
python scripts/new_run_task.py \
    --task "<任务描述>" \
    --url "<起始URL>" \
    --max-iterations <步数> \
    [--risk-confirmed blocking|notified]   # 风险确认时传入，详见「风险拦截」章节

# 批量抓取页面内容（转为 Markdown）
python scripts/page_content_retrieval.py \
    --urls <URL1> [URL2 ...] \
    [--batch-size 10] \
    [--max-browsers 5] \
    [--browser-timeout 20000]

# 释放浏览器资源（整条任务链结束后必须调用一次）
python scripts/release_browser.py
```

## 核心约束

**串行调用**：禁止并行调用。多站点任务必须依次执行，前一次完成后再启动下一次。

**单站点限制**：每次 `new_run_task` 只能操作一个站点。

**登录平台数据**：淘宝、京东、小红书、微博、抖音等平台，必须用浏览器直接获取，禁止以搜索结果替代。

**下载场景限制**：
- **可支持**：用户指定站点的下载链接查找，本 skill 可导航到下载页面并返回资源下载链接
- **不支持**：
  - 执行实际的文件下载动作（无法将文件保存到本地）
  - 用户未指定站点的下载链接查找，此时必须优先使用 `search` 技能（不是 `ra_search` 技能）搜索下载链接

**资源释放**：整条任务链最末尾必须调用 `release_browser.py`，中间切换站点不需要提前释放。

**风险确认后重发**：用户点击「我已确认风险，继续执行」后，必须携带 `--risk-confirmed blocking` 参数重新发起，**禁止**在 `--task` 中手动拼接任何风险前缀。

**URL 获取前置**：若模型不知道起始目标站点 URL，应先调用 `search` 技能获取。此场景下 search 的任务描述必须精简为「获取 xxx 站点网址」，禁止附带用户原始任务的完整需求。

**时间确认**：用户任务中有明确时间相关要求的在执行浏览器任务前必须用命令行工具确认当前时间。

**登录偏好仅源于任务**：登录方式偏好（扫码/短信/手工）必须来自用户在任务描述中的明确表述，禁止根据历史对话推断,，禁止沿用历史的偏好。

**定时任务禁止登录类操作**：当 system message 中包含 `cron` 标识时，判定为定时任务场景。此场景下**禁止**使用 `new_run_task` 执行需要用户登录态的任务（包括但不限于：互动类操作如点赞/评论/收藏、交易类操作如购物/下单、内容发布类操作如发帖/发文）。定时任务仅允许执行无需登录的读取类操作（如 `page_content_retrieval` 抓取公开页面）。

## 步数规划（调用前必须评估）

### 规则一：超过 10 个操作对象必须拆批

单次调用操作对象不超过 10 个。超过时拆分为多次串行调用，每批 ≤ 10 个。

### 规则二：按复杂度选步数

| 复杂度 | 典型场景 | 操作对象数 | `--max-iterations` |
|---|---|---|---|
| 简单 | 单页查询、填写 1 个表单、操作 1–3 个对象 | 1–3 | `20` |
| 中等 | 搜索提取列表、操作 4–6 个对象 | 4–6 | `40` |
| 复杂 | 批量点赞/评论/收藏、操作 7–10 个对象 | 7–10 | `50` |

**宁多勿少**：步数耗尽导致任务截断，代价远高于多给几步。不确定时取上一档。

### 规则三：单对象步数参考

| 操作类型 | 步数估算 |
|---|---|
| 点赞 / 收藏 / 关注 | 3–5 步 |
| 评论 | 5–8 步 |
| 进入详情页 + 返回列表 | 4–6 步 |
| 提取单条数据 | 2–3 步 |
| 表单填写（每字段） | 2–3 步 |

估算公式：`总步数 ≈ 前序导航（5–8步）+ 对象数 × 单对象步数`

**示例**：给 10 个视频点赞 = 8（导航）+ 10 × 7（进详情3+点赞2+返回2）= 78步 → 超过 50 步上限，但对象数恰好 10 个，取 `--max-iterations 50` 并在 task 说明"尽量完成更多"。

## 步数耗尽时的续跑规则

### 识别步数耗尽

`success: false` 且 result 出现以下任一特征，判定为**步数耗尽**而非真正失败：

- 提到"达到最大迭代次数"
- 描述了部分完成进度（如"已完成 6/10 个"）
- 完成量少于任务要求量

**步数耗尽 ≠ 任务失败**，不要向用户报告失败，直接续跑剩余工作。

### 续跑方法

1. 从 result 中确认已完成哪些对象、剩余哪些
2. `--max-iterations` 在原值基础上**至少增加 50%**，推荐直接取 `50`
3. task 明确说明"从第 X 个继续"，只要求完成剩余部分
4. 若上次调用携带了 `--risk-confirmed` 参数，续跑时**必须原样保留**
5. 若本任务链发起时用户指定了登录方式偏好，续跑时**必须在 task 最前面保留该偏好句**

```bash
# 原调用步数不足，只完成了前 6 个视频点赞
# 续跑：
python scripts/new_run_task.py \
    --task "前6个视频已完成点赞，请继续对[视频7]、[视频8]、[视频9]、[视频10]依次点赞，返回每个视频点赞结果" \
    --url "https://www.bilibili.com" \
    --max-iterations 50
```

## 结果处理

### 成功
`success: true`：直接向用户呈现 result 内容，不添加额外解释。

### 失败
`success: false`（非步数耗尽、非登录中断、非风险拦截）：向用户说明失败原因，询问是否重试。

### 人工验证中断
`takeover_type: captcha`：任务执行过程中遇到人机验证（滑块/图片点选/reCAPTCHA），
验证卡片已自动发送。

优先遵照输出中 `# AGENT_HINT` 的强制话术。兜底话术：
「任务执行过程中遇到人机验证，已为您暂停。请完成验证后告知我继续。」

### 登录中断
`takeover_type: login`（或旧字段 `login_required: true`）：登录引导卡片已自动发送。

优先遵照输出中 `# AGENT_HINT` 的强制话术。兜底话术：
- `qrcode` / `manual`：「请按提示完成登录，完成后告诉我」
- `sms`：「请按提示操作，需要输入验证码时告诉我。」

### 风险拦截
`risk_required: true` 且 `risk_blocking: true`：风险卡片已自动发送。

优先遵照 `# AGENT_HINT`。兜底话术：「检测到该操作存在风险，已为您暂停执行。请确认后点击「确认风险，继续执行」，或点击「换种方式执行」。」

### 风险提示（非阻断）
`risk_required: true` 且 `risk_blocking: false`：风险提示卡片已自动发送，任务继续执行并返回结果。**后续在同一站点发起任何新任务时，必须携带 `--risk-confirmed notified` 参数**，避免重复发送提示。

## 中断后重新发起规则

### 登录完成后继续

无登录方式偏好：

```bash
python scripts/new_run_task.py \
    --task "已完成登录，继续：<原始任务描述>" \
    --url "<原始起始URL>"
```

本任务链发起时用户指定了登录方式偏好（偏好句必须保留在 task 最前面）：

```bash
python scripts/new_run_task.py \
    --task "如果需要登录，必须采用<偏好方式>；已完成登录，继续：<原始任务描述>" \
    --url "<原始起始URL>"
```

**二次登录**（本次会话已有手机号）：直接注入手机号，禁止重复询问。

```bash
python scripts/new_run_task.py \
    --task "当前在登录页，手机号为<已知手机号>，发送验证码后等待用户输入，登录后继续：<原始任务描述>" \
    --url "<原始起始URL>"
```

### 风险确认后继续（操作类，blocking=true）

用户点击「我已确认风险，继续执行」后：

```bash
python scripts/new_run_task.py \
    --task "<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed blocking
```

**关键规则**：
- `--task` 填写**原始任务描述**，无需手动拼接任何风险前缀
- 风险前缀由 `--risk-confirmed blocking` 参数自动注入
- 禁止同时在 `--task` 中手动拼接「用户已授权确认风险」，否则会导致前缀重复
- 若本任务链发起时用户指定了登录方式偏好，`--task` 中仍需在最前面保留该偏好句

### 风险已提示后继续（读取类，blocking=false）

本次会话中已对某站点发送过非阻断风险提示，后续在该站点发起新任务时：

```bash
python scripts/new_run_task.py \
    --task "<新任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed notified
```

**关键规则**：
- `--task` 填写**新任务描述**，无需手动拼接任何风险前缀
- 风险前缀由 `--risk-confirmed notified` 参数自动注入
- 只要本次会话对某站点触发过非阻断风险提示，后续所有针对该站点的续跑或新任务都必须携带此参数
- `blocking` 与 `notified` 互斥，不可混用
- 若本任务链发起时用户指定了登录方式偏好，`--task` 中仍需在最前面保留该偏好句

### 人工验证完成后继续

```bash
python scripts/new_run_task.py \
    --task "已完成人工验证，继续：<原始任务描述>" \
    --url "<原始起始URL>"
    # 若携带了 --risk-confirmed 参数，原样保留
    # 若本任务链发起时用户指定了登录方式偏好，task 最前面保留该偏好句
```

**注意**：
- 用户点击「跳过验证」时，询问用户是否稍后重试或换种方式，不重新发起任务
- captcha 与风险确认可同时存在，`--risk-confirmed` 参数按原有规则保留

### captcha + 风险确认复合场景

```bash
# 操作类风险已确认 + 验证完成后续跑
python scripts/new_run_task.py \
    --task "已完成人工验证，继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed blocking

# 读取类风险已提示 + 验证完成后续跑
python scripts/new_run_task.py \
    --task "已完成人工验证，继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed notified
```

### 复合中断（风险确认 + 登录）

`--risk-confirmed` 参数与登录信息同时使用，格式：

```bash
# 操作类风险确认 + 扫码登录完成
python scripts/new_run_task.py \
    --task "已完成登录，继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed blocking

# 操作类风险确认 + 短信登录（用户提供手机号）
python scripts/new_run_task.py \
    --task "当前在登录页，手机号输入框填入<手机号>，点击发送验证码，等待用户输入验证码后继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed blocking

# 操作类风险确认 + 短信登录（用户提供验证码）
python scripts/new_run_task.py \
    --task "当前在登录页，手机号为<手机号>，验证码输入框填入<验证码>，点击登录，登录成功后继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed blocking
```

### 复合中断（风险已提示 + 登录，读取类）

```bash
# 读取类风险已提示 + 扫码登录完成
python scripts/new_run_task.py \
    --task "已完成登录，继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed notified

# 读取类风险已提示 + 短信登录（用户提供验证码）
python scripts/new_run_task.py \
    --task "当前在登录页，手机号为<手机号>，验证码输入框填入<验证码>，点击登录，登录成功后继续：<原始任务描述>" \
    --url "<原始起始URL>" \
    --risk-confirmed notified
```

**规则**：
- 只要本次会话用户点击过「确认风险」（操作类），后续所有续跑必须携带 `--risk-confirmed blocking`，直到任务链结束
- 非阻断风险提示（读取类）携带 `--risk-confirmed notified` 即可
- 两者不可混用
- 若本任务链发起时用户指定了登录方式偏好，以上所有示例的 `--task` 中均需在最前面保留该偏好句

## --risk-confirmed 参数速查

| 场景 | 参数值 | 说明 |
|---|---|---|
| 首次发起任务，无风险历史 | 不传 | 默认行为 |
| 用户点击「确认风险，继续执行」后 | `blocking` | 操作类风险已授权 |
| 本会话已发送过非阻断风险提示后 | `notified` | 读取类风险已提示 |
| 步数耗尽续跑，上次已传 `blocking` | `blocking` | 原样保留 |
| 步数耗尽续跑，上次已传 `notified` | `notified` | 原样保留 |

**注意**：
- 参数由框架自动将对应前缀注入 task，**禁止**在 `--task` 中手动拼接任何风险相关前缀
- 两个值互斥，同一次调用只能传其中一个

## task 描述规范

### 核心原则：只写目标，不写路径

task 是**任务目标**，不是**执行计划**。

- ✅ 任务目标：用户想要什么结果
- ❌ 执行计划：agent 如何达成结果

浏览器 agent 会根据目标自动规划步骤、处理异常、选择最优路径。

---

**格式**：`task = [可选登录方式偏好，] [可选登录状态说明，] 操作指令 + 结果要求`

风险相关前缀**不再出现在 task 中**，统一通过 `--risk-confirmed` 参数传递。

---

**禁止写入 task 的内容**：

task 只描述「做什么」和「返回什么」，具体「怎么做」由浏览器 agent 自行规划。

以下内容禁止出现在 task 中：
- ❌ 具体执行步骤（"第一步打开xx"、"第二步点击yy"）
- ❌ 文件保存路径（"保存到 /tmp/xxx"、"保存到本地"）
- ❌ 技术实现细节（"用 XPath 找到按钮"、"等待 3 秒后点击"）

❌ 错误示例：
```
task = "第一步打开淘宝，第二步搜索'蓝牙耳机'，第三步点击销量排序，把结果保存到 /tmp/taobao.json，返回前10条"
```

✅ 正确示例：
```
task = "在淘宝搜索'蓝牙耳机'，按销量排序，返回前10条的名称、价格和链接"
```

---

**登录方式偏好**（仅当用户在当前任务描述中明确指定登录方式时才写入 task）：

| 用户明确说了什么 | task 写法（放在 task 最前面） | 示例触发语 |
|---|---|---|
| 要用手工/手动登录，不要扫码或短信 | `如果需要登录，必须采用手工登录方式，不要使用二维码或短信验证码；` | "用手动方式登录微博" / "不要扫码不要短信" |
| 要用手机短信验证码登录 | `如果需要登录，必须采用手机短信验证码登录，不要使用二维码；` | "用短信验证码登录淘宝" / "不要扫码" |
| 要用扫码登录 | `如果需要登录，必须采用二维码扫码方式，不要使用短信验证码；` | "用扫码方式登录" / "扫二维码登录" |
| 未提及任何登录方式 | 不写任何登录偏好句，由 skill 自动选择 | "帮我查淘宝订单" / "登录微博看热搜" |

**关键规则**：
- **仅基于当前任务分析**：只有用户在任务描述中明确提到登录方式要求，才写入偏好句。不要根据历史对话记录或偏好推测本次偏好。
- **同一任务链内保留**：一旦在某次调用中写入了偏好句，该任务链的所有续跑（步数耗尽续跑、登录后继续、验证后继续）都必须在 task 最前面保留该偏好句，直到该任务链结束。
- **新任务重新判断**：每次启动新的任务链时，重新根据用户的当前任务描述判断是否有登录方式偏好，不沿用上一个任务链的偏好。
- 登录方式偏好与登录状态说明可同时出现，顺序固定：`登录方式偏好；登录状态说明；操作指令`
- 登录方式偏好与 `--risk-confirmed` 参数相互独立，两者同时存在时各自保留，不得互相覆盖

✅ 组合示例：

```bash
# 场景：用户本次任务中明确说"用手工方式登录" + 首次发起
python scripts/new_run_task.py \
    --task "如果需要登录，必须采用手工登录方式，不要使用二维码或短信验证码；在抖音搜索'三角洲肯德基联名活动'，找到相关视频，对第一个视频进行点赞并评论'联名活动太酷了🔥'" \
    --url "https://www.douyin.com" \
    --max-iterations 50

# 场景：同一任务链，风险已确认 + 登录完成后续跑（保留本任务链中用户指定的偏好）
python scripts/new_run_task.py \
    --task "如果需要登录，必须采用手工登录方式，不要使用二维码或短信验证码；已完成登录，继续：在抖音搜索'三角洲肯德基联名活动'，找到相关视频，对第一个视频进行点赞并评论'联名活动太酷了🔥'" \
    --url "https://www.douyin.com" \
    --risk-confirmed blocking
```

| 场景 | task 写法 |

## 工具选择决策（调用前必须判断）

**判断顺序**：依次检查以下条件，命中即停止。

| 优先级 | 条件 | 选择工具 |
|---|---|---|
| 1 | 需要登录才能访问 | `new_run_task` |
| 2 | 需要点击、搜索、填表、滚动等页面交互 | `new_run_task` |
| 3 | 已有 URL，只需获取页面内容（含结构化数据提取） | `page_content_retrieval`（并发，效率高） |

**关键规则**：只要页面可直接访问且无需交互操作，**一律**使用 `page_content_retrieval`，即使需要从页面中提取特定结构化字段（如日期、号码、价格、列表等）。

### 从指定页面提取结构化信息的 SOP

当用户要求从已知 URL 页面提取特定字段时，按以下两步执行：

**第一步：调用 `page_content_retrieval` 获取页面原始内容**

```bash
python scripts/page_content_retrieval.py \
    --urls <目标URL> \
    [--browser-timeout 20000]
```

**第二步：从返回的 `key_info`（Markdown）中解析并结构化输出用户所需字段**

`page_content_retrieval` 输出为 JSON 数组：
```json
[{"url": "https://...", "key_info": "# 标题\n\n正文 Markdown..."}]
```

从 `key_info` 的 Markdown 内容中提取用户要求的字段，整理为结构化格式后呈现给用户。

**示例**：

用户任务："从中彩网双色球开奖详情页抓取最新一期开奖信息"

```bash
# 第一步：获取页面内容
python scripts/page_content_retrieval.py \
    --urls https://www.zhcw.com/kjxx/ssq/
```

```
# 第二步：从 key_info 中提取并整理
开奖日期：2026-06-08
红球号码：03 08 15 22 26 33
蓝球号码：12
一等奖：5注，单注奖金 8,000,000元
二等奖：120注，单注奖金 150,000元
...
兑奖截止日期：2026-08-07
```

### 禁止反模式

| ❌ 错误做法 | ✅ 正确做法 |
|---|---|
| 用 `new_run_task` 打开页面后提取文本 | 用 `page_content_retrieval` 获取 Markdown |
| 在 `new_run_task` 的 task 中写"提取页面上的xx字段" | 先 `page_content_retrieval`，再由模型从 Markdown 中解析字段 |
| 认为"结构化数据提取"需要浏览器交互 | 结构化提取 ≠ 页面交互，`page_content_retrieval` 返回的 Markdown 足以支撑字段提取 |

## 输出字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `takeover_type` | str | 接管类型：`login`/`captcha`/`""` |
| `takeover_category` | str | 登录子类：`qrcode`/`sms`/`manual`/`""` |
| `takeover_subtype` | str | 细节：`need_phone`/`need_code`/`slider`/`image_select`/`recaptcha`/`unknown`/`""` |
| `takeover_hint` | str | 服务端生成文案，空时客户端走兜底 |
| `login_required` | bool | 兼容旧字段，等价于 `takeover_type == "login"` |
| `login_type` | str | 兼容旧字段，等价于 `takeover_category` |
| `sms_stage` | str | 兼容旧字段，等价于 `takeover_subtype`（sms时）|
| `risk_required` | bool | 是否触发了非阻断风险提示 |
| `risk_blocking` | bool | 是否触发了阻断型风险拦截 |

## 注意事项

- `new_run_task` 耗时可能超过 10 分钟，建议调用方设置 30 分钟超时
- `page_content_retrieval` 不支持需要登录的页面
- 禁止引导用户提供账号密码，登录只用 qrcode / manual / sms 方式
- `result` 内容保持原文输出，不添加套话；链接用 Markdown 格式 `[文字](url)`
- **禁止**在 `--task` 中手动拼接风险前缀（`用户已授权确认风险` / `已提示风险`），统一使用 `--risk-confirmed` 参数
