# 全方位论文深度阅读

**路由前置**：环境中存在 `academic-router`（学术检索路由） 时，学术类请求应优先经 `academic-router` 分流；本 skill 是其"论文深度解读型（类型 D）"下游，仅当 router 判定为深度解读意图、或用户明确指名 paper-deep-reading （论文深度解读）时才执行本流程。**已由 router 路由而来、或用户直接指名本 skill 时，直接进入下面的流程，不再回指 router（防止路由循环）。**

把一篇论文整理成专业读者愿意读、容易读懂、能够据此判断和继续研究的 HTML 阅读报告。报告的价值不在于缩短论文，而在于完成论文本身不会做的工作：概念定位、证据边界分析、跨领域联系和综合判断。

**质量优先级**：可读性 > 事实准确性（交付门槛）> 解读深度（价值来源）> 内容完整性（服从主线）。三层（快速导读 / 正文 / 折叠精读）用同一事实口径，不把同一结论换词重复。默认读者未读过本文，且分层：首屏（一句话速读＋四项导读）要让没有该领域背景的人也能读懂，术语必须换成通俗语言或就地点明；正文与精读折叠面向有大领域基础的读者，语言专业自然、不科普也不省略本文自造概念。

质量对齐四指标（内部标准，不写成报告栏目）：

- **忠实性**：数字追溯原文确切位置，验证单位/条件/比较对象；内部不一致或结论强于证据时明确指出。
- **解读深度**：讲「为什么以这种方式出现」——直觉联系、起源动机、假设边界、范式定位，不是摘要改写。
- **阅读效率**：表格替代散文枚举，多维比较一律表格，宁短密不长疏；避免过渡套话，直接给判断和证据。
- **科研价值**：复现条件、迁移启发、后续研究入口；后续问题从概念张力涌现，不是 limitation 改写。


默认交付 `<paper_slug>_reading/<paper_slug>_论文深度解读报告.html`；系统主动下载 PDF 时额外交付该 PDF，用户提供本地 PDF 不复制。报告的背景与上下文部分（若存在）不是百科式领域介绍，而是为理解本文贡献所必需的*概念铺垫*：问题为什么难、之前尝试为何不够、本文切入点的根本不同；长度和存在与否完全由"读者是否需要这些信息才能理解后文"决定。

### 1. 识别论文 → 分流 → 问模式（先问再动手）

1. **识别论文**：用户提供标题/ID/DOI/URL/引用/PDF 时确认论文身份；提供关键词时返回 Top 5 请选择；同名或版本歧义先消歧。

### 3. 收集元信息（分两波，与解析交叠）

**3.1. 与后台解析/图片提取并行做（不需要解析内容，只用论文身份信息 + abstract）**：后台任务运行期间并发完成以下五件事，不等它们返回：

(a) 核对完整元信息（标题/作者/机构/venue/年份/标识/链接）按可核实来源取值，**禁止凭记忆或"看起来对"补全**：① 有 arXiv ID / 官方 landing 页先直接读；② 读不干净或非 arXiv，用 academic-search（学术论文检索） skill 取权威结构化字段（arXiv→arxiv、有 DOI→Crossref/OpenAlex、跨领域→OpenAlex/Semantic Scholar），作者/venue/年份以 API 返回为准；③ 最终兜底裸 curl Crossref：`curl "https://api.crossref.org/works/<DOI>"`，取 `title` / `author[].given+family` / `container-title` / `issued` / `volume` / `page`；④ 仍拿不到就诚实留空、或只写可核实的缩写（只确定 "NeurIPS" 就写 "NeurIPS"），**绝不编造全称、人名、机构**。机构单列：Crossref 常返回空 `affiliation`，机构优先用 OpenAlex 的 institutions，取不到就留空 `AFFILIATIONS`（脚本允许空）；
(b) 搜索官方 Project Page 和代码仓库；
(c) 抓 arXiv abstract 建立问题/方法初步轮廓；
(e) **起草 LEAD 骨架**（六节各自的认识边界 + 覆盖地图初步三元组，详见步骤 4），解析回来后只需用正文细节校对/补齐。

留给 3.2/步骤 5 的只有需要完整 reference 列表才能定位的搜索（次要基线、消融对比、笔误交叉核对）。

**调度纪律**：3.1 起手一次并发发起所有已知搜索（元信息核对 / Project Page / 代码仓库 / 直接前作 / 主要 baseline / 关键后续 / abstract 点名的次要引用），禁止"搜一个 → 读 → 决定再搜"的串行迭代。需要基于中间结果二次调度的（前作具体版本、疑似笔误交叉核对）留到 3.2。后台解析/图片提取的 join 时机按步骤 2 **调度**段执行（3.1 期间不查状态、不轮询）。

**3.2. 解析完成之后做（需要解析内容）**：粗定位 Figure/Table/Appendix 索引（仅导航用，不作数字依据）；从参考文献列表和引言的引用模式中识别论文的智识谱系——哪些前人工作被视为直接基础、哪些被视为对比对象，为后续深度分析的概念定位提供线索；补做 3.1 无法从 abstract 判断的定向搜索（次要基线、疑似笔误交叉核对等）。

### 4. 深度分析（浓缩为 LEAD + 覆盖地图两个动作，不产出独立文档）


**深度分析的核心目标是解释性综合（interpretive synthesis）**：构建一个连贯的智识叙事——论文解决的根本困难是什么、为什么是这条路径、这条路径的概念代价和收益是什么、它在更大图景中的位置如何。技术细节服务于这个叙事，不是叙事本身。报告的组织逻辑是*论文的思想结构*而非*论文的排版结构*——例如论文在第 3 节定义模型、第 5 节给出理论保证、附录 A 提供证明细节，报告可以把三者合在一个解释流里讲通，而非按章节序列分别概括。

**覆盖地图的粒度**：让每份 CONTENT 作者写作前立刻知道本节要放几个 deep-dive、每个覆盖哪个中心；笼统的"心里过了"、写完发现说不出对应清单，等于规划没做。LEAD 契约只承担 6 节整体骨架，装不下一篇论文的全部独立技术单元（如 Transformer 的多头注意力、位置编码、LayerNorm、Warmup 各自都是独立单元）。一个组件若在方法中单列且移除后明显改变主要结果，就必须进入机制解释。凡含非冗余技术内容的章节都应进入分析视野，不能挑一个容易展开的组件充当精读、其余中心贡献停留在名称和概括。

**深度判据（功能性）**：读者读完报告能否自行复述每一项中心贡献的核心过程、并解释关键选择改变后会发生什么——不能则报告未完成深读。折叠精读块把对象、操作、设计原因、下游影响、证据和成立条件连起来；只有类比、公式转述或总体评价不算完成。**精读块数量由这个功能判据决定**，不预设配额、不为凑数补写。经验区间参考：常规实证/方法论文通常落在 3-6 个精读块，多机制配合的架构/系统工作往往更多（Transformer、GW150914 这类都在 4-6 个）——经验分布，不是硬约束。写出的数量明显低于此区间（1-2 个）时必须复审：是否有中心贡献被压回默认正文一两句概括、或被合并到其他精读块导致该贡献未独立走通对象/操作/设计原因/下游影响/证据/成立条件。深度在不同类型论文中有不同表现：理论论文走通证明的关键步骤和直觉来源；方法论文解释设计选择背后的归纳偏置（inductive bias）及何时失败；实证论文分析测量方法的效度和结论外推边界；系统论文揭示资源瓶颈的转移和工程取舍。

**结论必须是综合判断，不是摘要改写**：论文的核心贡献可信到什么程度、适用于什么条件、读者应如何定位它在自己研究中的角色。如果删掉报告只看论文摘要就能得到相同结论，说明分析深度不足。

#### 思想定位（深度的核心来源）

对论文的主要贡献建立在更大认知框架中的位置。三个维度按论文实际价值选取，不要求全部展开：

- **起源动机**：这个关键概念/方法从哪里来？回应什么更深层的困难或不满？与相邻领域的什么思想同构或对偶？
- **范式意义**：改变了什么理解框架或默认假设？引入了什么新的思考方式？
- **跨领域联系**：核心机制在其他领域是否有类比？必须是**结构性的**（底层数学结构/约束形式/优化目标同构）而非表面的——"注意力类似信息检索"是表面的，"注意力的 softmax 归一化等价于指数族的充分统计量选择"是结构性的。没有真正结构性联系时不勉强制造，承认贡献是领域内部的进步同样有深度。

好的思想定位表现为：读者能用自己的话向同事解释"这篇论文在想什么"，说出作者面对的核心张力、解决路径背后的直觉、以及这个选择排除了什么替代方案。这不是"相关工作"的重复——它回答"为什么世界需要这篇论文"而非"谁做过类似的事"。

#### 结构化批判与辅助工具（信息压缩工具，替代散文，非追加）

- **显式批判**：3-5 条编号的具体批判，指出问题本质、影响范围和检验路径。每条必须可从原文直接验证，涉及公式的批判先确认原文定义。质量在于是否触及论文真正的概念张力——"选择 X 意味着放弃 Y，这在 Z 条件下会成为瓶颈"而非仅指出表面缺陷。
- **证据完备表**：证明密集型论文，用紧凑表格呈现各核心定理的证明状态（完整/关键步骤/草图/缺失）。
- **多维度对比表**：多方法/系统比较时，表格跨正交维度对比，替代分散段落。
- **后续问题**：2-4 个，每个标注类型（机制验证/方法改进/场景外推/基础假设检验）+ 实验设计要素（控制变量、预期观察、判定准则、资源量级）。源自分析中识别的概念张力，不是论文 limitation 的改写。

### 5. 扩展外部信息（获取在 3.1 完成，整合内嵌在写作阶段）

外部搜索的**获取**在步骤 3.1 的解析窗口已完成，本步只做"哪些外部工作真正写进报告、写进哪一节"的整合决定，发生在每份 CONTENT 作者写自己那节时。外部信息的首要目的是**智识定位**，不是罗列相关文献。整个阅读周期外部搜索 ≤ 10 次（含 3.1 前置的部分），每次服务于当前无法从原文回答的具体问题，信息够即停。选入报告的相关工作至少说明它处理的问题、关键路线、与本文差异和它如何改变判断（内部用"已有起点/本文增量/识别证据/当前位置"四问题选材）。优先一手来源，"首次""直接前驱""全面 SOTA"需要高证据门槛。外部材料写进相关段落，不只堆在文末。

对经典论文可增加历史回看，揭示思想演化的内在逻辑——哪些洞察被保留是因为捕捉了真实结构，哪些被替代是因为假设条件改变。不按发表年份自动触发，不把高引用量当技术正确性证据。

### 6. 生成自包含 HTML 报告


正文按 spec §三 走，三步：

1. **先定稿 LEAD**：在 `fragments/fields.html` 写六个 `*_LEAD`，作为各章节写作契约与边界。
2. **并行写 8 个 `*_CONTENT` 片段**（`BACKGROUND` / `METHOD` / `EVIDENCE` / `ASSESSMENT` / `APPLICATION` / `CONCLUSION` / `OPTIONAL_SECTIONS` / `FOLLOWUP_SECTION`）：8 个片段只依赖已定稿的 LEAD 与 `parsed.md`、**彼此之间没有任何依赖**，因此没有任何理由串行。**并发宽度硬要求：在同一条消息里一次发起至少 4 个，推荐 8 个一次发全**——宿主有 subagent/Task 工具时一次并发派出对应数量的子任务，没有时也要把多个写文件调用放进同一条消息。**一次只发 1-2 个、或"写一个→看结果→写下一个"的串行迭代是 CONTENT 超时的首因**，明确禁止。每个作者以自己的 `*_LEAD` 为 scope、其余五句为边界，不重述或改写导语。写作规则：
   1. **片段是 HTML 源码不是 Markdown**：用 `<strong>` 而非 `**`、`<table>` 而非 `|…|`、`<ol>/<ul><li>` 而非 `1.`/`- `、每段包 `<p>`。
   2. **表格**：原论文用表格呈现的信息（实验结果、消融、方法对比、超参、复杂度分析等）用 `<table>` 保持表格形式，禁止口述成段落；多方法/多条件/多指标的横向比较也用表格。
   3. **关键图嵌入**：`extract_figures.py` 提取到 `images/` 的关键图（架构图、主结果图、机制示意等），在讲到它的那节 `*_CONTENT` 按 spec §三 第 4 条的形式写成 `<figure class="figure"><img data-image-src="images/xxx.png" alt="…"><figcaption>中文图注</figcaption></figure>`（文件名对齐 `images/` 实际文件），装配阶段展开为 base64。**不要在 `<figure>` 之外另写孤立的 `<img>`**：stdout 给的 caption 是写 `<figcaption>` 的原料，不是让你先照抄一个 `<img>` 出来；同一张图在整份报告里只出现一次。深读至少嵌入关键图；纯数学/无图论文才可无图。
   4. **精读块**：若步骤 4 覆盖地图把某个中心技术单元分配给本节精读，该 `*_CONTENT` 必须包含对应的 `<details class="deep-dive">` 精读块（连贯写完对象/操作/设计原因/下游影响/证据/成立条件），而不是压回默认正文一两句概括。**这六项是覆盖清单不是句子模板**：槽位名不得用作句子主语，也不必按此顺序逐段展开，否则会写成“设计对象是……理想目标是……难点在于……”的填槽式翻译腔。
   5. **两个自带 `section` 的可选片段**：`OPTIONAL_SECTIONS`（相关研究）与 `FOLLOWUP_SECTION`（后续问题）不像六个固定节由模板提供外壳，非空时各自必须是**闭合完整**的 `<section class="report-section" id="related"><h2>…</h2>…</section>` / `id="followup"`，以 `<h2>` 开头、`id` 唯一。目录由脚本运行时扫 `.report-section[id]` 里的 `<h2>` 自动生成：缺 `class`/`id`/`<h2>` 会让这一节漏出目录，多写 `</section>`/`</div>` 会吞掉紧随其后的固定节。没内容就留空文件。
