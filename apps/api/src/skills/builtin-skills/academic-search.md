# 学术搜索

本 skill 提供两条互补的检索通道：

| 通道 | 检索源 | 擅长 | 参考文件 |
|------|--------|------|----------|

## 调用方式

### 何时调用本 Skill

**仅当用户有明确的论文检索需求时**才调用本 skill（满足任一判据即可）：

1. **明确的检索动作词**：出现"找/搜/检索/调研/查 + 论文/文献/paper/相关工作/学术研究"类表述
2. **提供了论文标识**：给出标题、作者、DOI、PMID、arXiv ID、机构、发表时间等元信息，意图是定位该论文或其引用、全文、PDF
3. **明确的查论文意图**：问题虽以知识问答形式提出，但已明确表达查论文/文献的诉求（如"XX相关的论文""有没有相关研究""帮我查查文献"）

**以下情况不应调用：**

- 一般性知识问答（即使带学术色彩），只要未明确要求查论文/文献
- 仅提及论文或学术概念，但核心诉求是编码、写作、计算等其他任务
- 意图模糊无法判断时，应先向用户澄清，而不是直接调用
- 凡围绕研究主题/方向、希望推荐或汇总一批论文的需求应优先调用proactive-paper-recommendation skill

### 查询类型识别

确认属于论文检索需求后调用本 skill，由本 skill 自行完成查询意图判断，识别以下三种查询类型并据此决定检索策略：

- **知识问答型**（`knowledge_qa`）：自然语言描述具体知识性问题，指向知识点或因果机制，不包含具体论文标识（如"搜索相关论文，CRISPR 的脱靶效应如何降低？"）
- **研究主题型**（`research_topic`）：围绕研究主题/方向的探索性、调研性、综述性需求，期望综合性论文覆盖（如"帮我调研一下多模态大模型的学术研究现状"）
- **元信息检索型**（`meta_info`）：提供了标题、作者、机构、关键词、时间、DOI/PMID/arXiv ID 等任一论文标识，期望精确定位特定论文或论文集合

类型判定边界：

- **知识问答型与研究主题型难以区分时**，默认按研究主题型处理，以获得更全面覆盖


## Query-CoT：查询拆解分析（强制前置步骤）

在执行任何检索之前，**必须先完成 Query-CoT 拆解分析并显式产出拆解结果**，然后才允许发起检索。跳过本步骤直接检索属于违规。

### Step 1：识别知识点数量

逐一扫描 query 中的询问点，将其拆解为独立的**知识点**（可独立检索的最小语义单元），重点识别以下多知识点信号（命中任一即视为多知识点 query）：

- 并列枚举：顿号/"和"/"以及"/"与"连接多个名词短语（如"收敛性证明、泛化误差上界和最小上下文长度"）
- 显式声明多个关注点："重点关注……这几个方向""尤其是 A、B 和 C""分别看看……"
- 多个疑问点："方法是什么、效果如何、有哪些局限"

### Step 2：产出拆解结果（必须先写出来再检索）

在发起检索前，先显式列出（作为内部自检记录，不展示给用户）：

```
知识点清单：[知识点 1] / [知识点 2] / [知识点 3] ...
知识点 1：
  中文子查询：<语义自足的自然语言短句：核心主题语境 + 单个知识点>
  英文子查询：<同义的英文自然表达>
知识点 2：...
```

子查询写法要求（自检不通过则重写）：

- **语义自足**：每条子查询脱离原 query 也能独立表达一个完整的检索意图。读者（和检索系统）不需要回看原 query 就知道在找什么；写成"XX 的 YY 方法/研究"这类完整短语或短句，而非无语法关系的词串
- **术语标准化**：将口语化表述转换为领域标准术语后再写入子查询（如"老电影修复"→ film restoration / 视频修复，"上色"→ colorization / 彩色化）
- **一条 query 只讲一件事**：同一条子查询中不得同时出现同义词（如"老电影"与"历史影像"）、上下位词（如"修复"与"去噪""划痕去除"）或多个并列侧面；近义表达留给二次补充检索的"换表达重检"，不得在单条 query 内堆叠

- **单一知识点**：query 指向单一主题或单一锚点时，仍须生成中、英文两条子查询后进入「通道路由」（无需拆分知识点）
- **多个知识点**：**必须按知识点清单拆分为多个独立子查询，每个子查询分别走「通道路由」并独立发起检索**

### 中英文双语检索（硬性要求）

每个知识点**必须同时生成中文与英文两条子查询，且两条都要实际发起检索**：

- 中英文献分属不同的索引体系，单语检索会系统性漏检另一语种的相关文献；双语召回结果在「检索结果处理与输出」阶段统一去重归并
- **英文子查询**：使用领域标准术语与惯用表达（国际平台与多数预印本以英文索引为主，英文表达直接决定通道 B 的召回质量）
- **中文子查询**：使用自然的中文检索表达，专有名词（模型名、数据集名、方法名等，如 Transformer、ImageNet、RLHF）保留英文原文，不强行翻译
- 两条子查询语义必须对等，不得借双语之名塞入不同的知识点
- **例外**：元信息定位类查询（标题、DOI、作者名等锚点检索）不受双语要求限制，按锚点原文检索即可

### 拆分硬性规则

- **禁止合并检索**：严禁将多个知识点的关键词拼接成一条长 query 一次性检索（如把"收敛性证明""泛化误差上界""最小上下文长度"全部塞进同一条 query）——关键词过多会导致检索系统无法有效响应、召回质量严重下降
- **禁止关键词堆叠**：子查询写成语义自足的自然语言短句，而非 3 个以上关键词的松散拼接（如 `老电影修复 深度学习 视频去噪 划痕去除 历史影像`——同义与上下位概念混排、无句法结构，语义检索系统无法有效响应）；仅通道 B 的关键词匹配平台（arXiv、OpenAlex 等）例外，允许短语组合，但限 2–4 个标准术语
- 每条子查询须保留原 query 的核心主题语境，只聚焦其中一个知识点
- 拆分数量以知识点数为限，**单次请求最多拆为 4 个知识点**（每个知识点含中、英文两个版本的子查询）；知识点过多时合并相近知识点
- 各知识点之间语义耦合紧密、拆开后反而丢失上下文时（如"X 如何影响 Y"这类关系型问题），不拆分，按单一知识点处理（仍出中英两条子查询）
- 各子查询的检索结果在「检索结果处理与输出」阶段按知识点归并展示；拆解与检索经过属于内部过程，**不得在回复中叙述**

### 正反示例

用户 query："找一下 2023 年以来关于大语言模型 In-Context Learning 理论分析的论文，我重点关注收敛性证明、泛化误差上界和最小上下文长度这几个方向。"

❌ **错误做法**（多知识点关键词堆进一条 query，且只用单语，检索系统无法有效响应）：

> `In-Context Learning theoretical analysis convergence proof generalization error bound minimum context length large language models`

✅ **正确做法**（拆为 3 个知识点，每个知识点中英双语分别独立检索）：

> 1. 知识点：收敛性证明
>    - 英文：`convergence proofs of in-context learning in large language models`
>    - 中文：`大语言模型上下文学习的收敛性证明`
> 2. 知识点：泛化误差上界
>    - 英文：`generalization error bounds for in-context learning`
>    - 中文：`上下文学习的泛化误差上界分析`
> 3. 知识点：最小上下文长度
>    - 英文：`minimum context length requirements for in-context learning`
>    - 中文：`上下文学习所需的最小上下文长度`

时间范围（2023 年以来）等约束条件通过检索参数（而非 query 关键词）附加到每个子查询上。

用户 query："搜一下 2020 年以后用深度学习做老电影、历史影像修复和彩色化的论文"

拆为 2 个知识点（修复、彩色化），时间范围（2020 年以后）走 `start_time` 参数，不写进 query：

> 1. 知识点：老电影/历史影像修复
>    - 中文：`基于深度学习的老旧影像修复方法`
>    - 英文：`deep learning based old film restoration`
> 2. 知识点：黑白影像彩色化
>    - 中文：`基于深度学习的黑白视频彩色化`
>    - 英文：`deep learning video colorization`

❌ 反例：`老电影修复 深度学习 视频去噪 划痕去除 历史影像`——"老电影"与"历史影像"同义重复，"去噪""划痕去除"是"修复"的下位细节，五段关键词无句法结构，无法表达单一明确的检索意图。去噪、划痕去除等细分方向若首轮覆盖不足，在二次补充检索中以独立子查询展开。

## 通道路由

收到查询（或 Query-CoT 拆分后的每个子查询）后，按以下规则决定走哪条通道（可以是单通道，也可以双通道并行）：

### 路由到通道 A（语义检索）

- 自然语言知识问答（"XX 是什么机制"、"XX 如何影响 YY"）
- 研究主题探索、文献调研、综述类需求
- 需要按权威性等级、时间范围、相关性等参数控制召回的场景
- 本 skill 判定查询类型为 `knowledge_qa` / `research_topic` / `meta_info` 之一时


### 路由到通道 B（开放平台检索）

- 通过论文标识符精确定位（DOI、PMID、PMCID、arXiv ID）
- 引文关系查询（谁引用了这篇）、作者出版物列表
- 机构/团队的论文清单枚举（如"某机构 2022 年以来某方向的全部论文"），优先 OpenAlex institutions 过滤或机构官网
- 开放获取 PDF / 全文获取
- 预印本按日期或 DOI 浏览
- 需要特定平台（PubMed、arXiv 等）权威数据源的场景


### 双通道并行

- 主题调研、综述等需要广度覆盖的需求：通道 A 提供语义维度召回，通道 B 在 OpenAlex、PubMed 等平台补充关键词维度检索。**各通道首轮检索应在同一批次并行发起**（利用并行工具调用），让失败被并行发现，禁止串行逐个通道试错换路
- 通道 A 三次放宽重试仍无结果时，降级到通道 B 继续检索

### WebSearch 全网补充（通用能力）

WebSearch 是贯穿整个检索过程的通用补充手段，首轮、二次补充检索乃至全面性评估阶段均可调用。与通道 A/B 并行执行、互为补充。适用情形：

- **高全面性需求查询的首轮默认调用**：调研、综述、多子主题覆盖等查询，首轮即同时发起 WebSearch，尽早扩大材料覆盖面，而非等到二轮才补充
- **所有需要校验或补充特征的操作一律用 WebSearch 完成**：通道 B 存在限流与时延高的问题，对已召回结果做增量特征补充（如背景介绍、术语释义、应用场景、相关动态等）或信息校验（如机构/团队背景、项目归属、发表 venue、成果报道等事实确认）时，一律通过 WebSearch 完成，不得回到通道 B 逐篇查询；且仅校验或补充与用户需求高度相关的特征，无关紧要的特征允许缺失
- 学术平台结果明显不足，或主题非常新、尚未被学术数据库收录
- 查询涉及产业进展、技术博客、机构报告、新闻等非学术来源
- 需要确认术语的标准表达或主题背景，以便构造更好的学术检索词
- 学术检索多轮无结果时，作为降级手段提供背景信息

WebSearch 结果仅作为补充材料，展示时可在条目层面标注来源性质（如链接、出处），不得替代学术检索结果的主体地位；**不得在回复中叙述"已通过 WebSearch 补充……"之类的检索经过**。

## 多轮检索策略

完成通道路由后，对全面性要求高的查询执行多轮检索：先判断全面性需求，首轮结果返回后**主动分析可能遗漏的知识点，默认发起二次补充检索**。全面性是检索质量的首要目标，存在疑义时宁可多检一轮，不可带着明显缺口直接输出。

### Step 1：全面性需求判断

收到查询后（Query-CoT 已拆分出多个子查询的，对整体需求判断一次即可），先判断用户对结果全面性的要求：

**高全面性需求（适用多轮检索）：**
- 研究主题调研、文献综述、某方向的综合性覆盖（查询类型判定为 `research_topic`）
- 需要多篇论文证据支撑的知识问答（查询类型判定为 `knowledge_qa`）
- 查询包含多个子主题/侧面，单次检索难以全覆盖
- 用户明确要求"尽量全面""多搜集一些资料""覆盖全面一点"
- 判定为高全面性需求后，**首轮即默认同时调用 WebSearch**（见「WebSearch 全网补充」），再根据首轮结果决定是否发起二次补充检索

**低全面性需求（单轮检索即可）：**
- 元信息精确定位单篇论文
- 单个 DOI/PMID/arXiv ID 查询、引文关系、作者出版物列表、获取 OA PDF
- 查询指向明确单一锚点，结果是唯一或封闭集合

### Step 2：首轮结果全面性评估

对高全面性查询，首轮结果返回后先做**知识点拆解**，再逐项评估覆盖情况：

1. **知识点拆解**：基于查询语义，将主题拆解为应覆盖的知识点清单——典型维度包括：核心概念与定义、主流方法/技术分支、典型应用场景、代表性数据集与评测基准、已知局限与挑战、最新进展等；按查询类型选取适用维度，清单需显式列出作为逐项核对依据
2. **逐项核对**：对照知识点清单与首轮结果，从四个维度评估：

   - **数量**：结果数量是否足以支撑综合性回答
   - **知识点覆盖**：清单中每个知识点是否都有对应结果，**哪怕单个知识点完全空缺或仅有弱相关结果，均视为明显缺口**
   - **多样性**：结果是否过度集中于单一平台、时间段或研究团队
   - **相关性**：是否大量结果偏离主题，说明检索词与主题的常用表达不匹配

**判定规则**：覆盖充分（所有知识点均有足够且相关的结果）→ 直接进入「检索结果处理与输出」；存在任何空缺或弱覆盖的疑点 → 进入 Step 3，**倾向于发起二次检索而非带缺口输出**。

### Step 3：二次补充检索

针对评估发现的知识点缺口，发起有针对性的补充检索，按缺口性质选择策略（可组合使用）：

- **改写查询补侧面**：将缺失知识点拆解为新的子查询（同义词替换、补充学科术语、缩小/扩大主题范围），作为新的检索任务执行
- **换表达重检**：某知识点首轮零召回但逻辑上应当存在时，更换同义词、上下位词、中英文表达重新检索，避免因检索词与领域常用表达不匹配而漏检
- 若缺口属于非学术来源或学术库覆盖盲区，可同时配合上文「WebSearch 全网补充」搜集相关资料

发起每一轮补充检索前，向用户简要说明上一轮发现的缺口与补充检索的目的。

### 多轮约束

- **每次用户请求最多 3 轮**（首轮 + 最多 2 次补充检索）；三轮后仍有缺口时，如实展示已有结果并明确说明未覆盖的方面，交由用户决定是否继续
- 每一轮是独立的检索任务：轮与轮之间允许改写 query、换通道换平台；但每轮内部的调用数量仍受通道 A / 通道 B 各自的调用约束限制
- 补充检索必须针对明确的知识点缺口，禁止对已充分覆盖的侧面改写重检凑轮次

## 通道 A：语义检索


### Query 数量限制（硬性约束）

为防止无限衍生查询，对每一轮检索的脚本调用数量进行严格限制：

- 所有重试只能通过放宽检索参数（时间范围、召回量）来调整，不得变更 query 语义；改写 query 只能通过发起新一轮检索实现（见「多轮检索策略」，每次用户请求最多 3 轮）
- 达到调用上限后必须停止当前轮检索，进入全面性评估决定是否发起下一轮，或向用户报告当前状态并交由用户决定下一步
