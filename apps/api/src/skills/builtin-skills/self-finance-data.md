通过 `finance_data` API 查询股票**行情与基本面数据**，输入自然语言 query 即可。

1. **构造查询** - 按下方规则构建 query 字符串
3. **获取内容** - 读取返回的数据文件，取回内容。文件可能较大，若单次读取被截断，**必须分段读取直至文件末尾，禁止遗漏任何数据**

## Query 构造规则

### ⛔ 第 0 步：主体类型硬门禁（构造 query 前必须先做，优先级高于本节其他所有规则）

本 skill 底层只有**股票库**。**以下类型的标的一律不在库，命中即直接如实告知用户不支持，严禁拼进 query「试一下」**——传下去 100% 空结果，只会白耗一次调用并让用户等满 10 分钟超时。

⚠️ 这是**主体级**判断，与「字段/维度是否支持」完全无关：即使查询维度（最新价、涨跌幅、历史行情、走势）本身是支持的，只要**主体**命中下表，也必须整条拒答。

| 禁止类型 | 命中特征（中文名 + 英文/代码 token，见到任一即命中） |
| --- | --- |
| **贵金属 / 商品现货**<br>（指商品本身的价格，不是矿业公司股票） | 现货黄金、现货白银、国际金价/银价、伦敦金、黄金T+D、上海黄金交易所/上海金交所、布伦特原油、WTI原油、天然气、铁矿石、螺纹钢、焦煤、焦炭、纯碱、豆粕、棕榈油、碳酸锂；`XAU` `XAG` `Au99.99` `Au9999` `T+D` `COMEX` `LME` `CBOT`；或**裸金属/商品名单独出现**（就叫「黄金」「白银」「铜」「原油」） |

| **非美非港海外个股**（韩股/台股/日股/欧股/新加坡股） | SK海力士、三星电子、台积电、阿斯麦、德西尼布；`SKHY` `Samsung` `ASML` `PulteGroup` `Berjaya` `First Resources` `SGX` |

**执行方式：**

- **多主体 query 中只有部分命中** → 把命中的主体**剔除后再发起**，并在回答里说明该主体不支持；不要整条放弃，也不要带着它一起发（会影响同批其他主体的召回）。
- ⚠️ **不得换个说法绕过**：`XAUUSD`／`XAU/USD`／`现货黄金`／`伦敦金`／`上海黄金交易所 Au99.99`／`国际金价` 指的是同一类东西，全部不支持。
- ✅ **反向豁免（务必看清，否则会错误拒答大量合法股票）**：金属/能源类**上市公司**是正常 A 股，**必须照常查询**。
  判据是「问的是商品价格，还是公司股价」——公司名通常是「地名/字号 + 金属」或带 `股份`/`有色`/`矿业`/`集团` 后缀。
  ✅ 支持：山东黄金、中金黄金、赤峰黄金、湖南黄金、招金黄金、白银有色、湖南白银、江西铜业、云南铜业、
  铜陵有色、北方铜业、铜冠铜箔、中国铝业、云铝股份、南山铝业、天山铝业、锡业股份、锌业股份、驰宏锌锗、
  兴业银锡、华锡有色、华友钴业、北方稀土、中国稀土、豫光金铅 等（这些都是股票，不是商品）。
  ❌ 不支持：现货黄金、国际金价、伦敦金、黄金T+D、`XAU/USD`、`上海黄金交易所 Au99.99`（这些是商品报价）。
- ⚠️ **不得用近似标的"代答"**：不支持时如实告知即可，严禁改查某只黄金股、黄金 ETF、或相关概念股来做"近似回答"。

### 其余构造规则

- 支持**单只或多只股票批量查询**。当用户要求查询多只股票的同类数据时，**必须一次性提交所有查询**，禁止多次单独调用。
- 每个 query 必须包含：**明确的股票名称** + **查询内容**（行情类还需包含明确时间或时间范围）。
- ⚠️ 若 query 中混合了支持与不支持的字段，必须先剔除不支持字段再发起查询，否则整条返空。
- 历史行情查询时，**单次 query 时间跨度不得超过1年**（接口返回数据条数有限）。若用户查询范围超过1年，须在调用前手动拆分为多个子查询：
  - 拆分后的子查询合集须**完全包含**用户查询范围，允许适当超出，不得有遗漏
  - **按自然年拆分**为优先策略：起止年份的边界年按实际月份切，中间完整的年份用整年。例如当前为2026年4月，"近3年"对应2023年4月~2026年4月，拆分为 `2023年4月至12月`、`2024年`、`2025年`、`2026年` 四个子查询；"近20个月"对应2024年8月~2026年4月，拆分为 `2024年8月至12月`、`2025年`、`2026年` 三个子查询
  - 每个子查询**仅替换时间范围部分**，原始 query 中其他所有修饰信息必须完整保留，包括但不限于：数据粒度（每日/每周/每月）、展示形式（K线/涨跌幅）等，不得增删其他语义

## 脚本调用

> ⛔ **唯一入口，严禁绕过脚本内部实现**：本 skill 与 finance_data API 交互的**唯一合法方式**，是通过命令行运行下面的 `script.py` 并把 query 作为参数传入。**严格禁止**以下任何"抄近道"写法：
>
> - ❌ `import script` 或 `from script import _submit_async_task, _poll_task_status, _build_headers` —— 直接引用脚本内部模块，或任何以 `_` 开头的私有函数
> - ❌ 自行用 `aiohttp`/`requests` 拼接 `/api/v1/finance/data/async`、`/data/task/{id}` 等 URL 去提交或轮询任务
> - ❌ 复刻或改写脚本内部的"提交 → 轮询 → 取结果"循环、并发控制、超时/重试逻辑
>
> **为什么**：以 `_` 开头的函数是**内部实现、没有对外契约**，签名与返回值会随版本变动 —— 例如 `_submit_async_task` 的返回值已从单个字符串 `task_id` 变更为 `(task_id, task_type)` 二元组。在脚本外调用又忘记解包，就会把 Python 元组的字符串形式塞进 URL 路径，导致下游持续 404、并污染网关整体监控。
>
> **批量/大规模怎么办**：`script.py` 内部已封装并行、重试、状态判定与任务取消。需要一次查很多标的时，**把多个 query 作为命令行参数一次性传入**（见下方"批量查询"），由脚本自行并行；标的数量过多受命令行长度限制时，拆成多次批量调用即可 —— **任何时候都不要改成 import 私有函数自建并发**。

## 脚本返回格式

脚本默认返回JSON

**单个查询：**
result.result.result.final_deliverable_json: 完整查询结果的 JSON文件 路径，**以此为准**，读取文件内容作为展示数据来源。

**批量查询：**
返回 JSON 顶层含 `all_success` / `partial_success` / `all_failed` 标志、`successful_queries` / `failed_queries` 列表，以及 `results` 数组。`results` 每个元素是以下三种之一：
- 成功：`{query, final_deliverable_json}` — 读 `final_deliverable_json` 路径获取数据
- 调用失败：`{query, status: "failed", error}` — 网络/进程异常
- 空结果：`{query, status: "empty_result"}` — 调用成功但业务无数据
仅对成功项读取 `final_deliverable_json`；失败/空结果项跳过即可，详细原因见 `failed_queries[*].reason`。

> ⚠️ 返回的 JSON 文件可能较大（如多地上市股票包含不同市场数据，长时间跨度查询数据量更大），若单次读取被截断，**必须分段读取直至文件末尾，禁止遗漏任何数据**。例如查询「紫金矿业2025年股价」，文件中会包含 A 股和港股两个市场的数据，若读取被截断，可能只获取到 A 股数据或港股数据不完整，必须继续读取直至所有市场数据均完整获取。

## 输出规范

### 通用规则

- 优先使用 **Markdown 表格**展示数据
- **仅展示用户要求的信息**，不将返回结果中的所有字段全部展示
- 成交量(volume)单位根据 sql 字段中的表名判断：表名含 `kline`（如 stock_index_kline_1m/1h）→ 单位为**手**；表名含 `ifind`（如 ifind_stock_data_1day）→ 单位为**股**。输出时必须标注正确单位
- 若用户询问的是**具体指标或衍生结论**（如某时间段最高价/最低价、某日涨跌幅），从数据中提取后直接作答，根据信息量决定是否使用表格
- **禁止输出原始字段名**，包括但不限于：`table_info`、`sql`、`thscode`、`market`、`vwap`、`pre_close` 等内部字段
- 多个子查询的结果需**按时间顺序合并**后统一呈现，不分段展示。可先对每个子查询数据按最终展示要求进行总结，再合并输出。
- 如果结果中包含**非目标标的**的数据，直接忽略，不展示
- 如果存在多地上市的情况，需分章节对每个标的进行展示

### 日内走势展示规则

使用 **Markdown 表格**展示，**第一列为时间**，后续列为行情字段。价格、涨跌幅为必选列，其他字段仅用户有明确需求时展示。按时间顺序排列。

### 历史行情展示规则

**展示粒度：**

- 用户**已指定粒度**（如"每日"、"每周"、"每月"）→ 按用户指定粒度展示
- 用户**未指定粒度**，根据查询范围自动决定：
  - 查询范围 不超过 3 个月 → 默认展示**日粒度**
  - 查询范围 超过 3 个月 → 默认展示**月粒度**
  - **注意**：这里的查询范围指用户原始任务查询范围，而不是拆分后的子查询；当查询需要拆分时，说明范围超过一年，同时若用户未指定粒度，统一按照**月粒度**展示

**展示列（不同粒度不混用）：**

| 粒度 | 必选列       | 可选列（按用户需求展示）       |
| ---- | ------------ | ------------------------------ |
| 日线 | 日期、收盘价 | 开盘价、最高价、最低价、涨跌幅 |
| 周线 | 周期、收盘价 | 开盘价、最高价、最低价、涨跌幅 |
| 月线 | 月份、收盘价 | 开盘价、最高价、最低价、涨跌幅 |

用户只问收盘价则只展示必选列；用户问"股价"等通用表达，默认展示全部列。

## 各类数据 Query 构造要点

### 资金流向与主力资金
- 问**主力资金净流入、散户净流入、沪深股通净买入**等，query 直接写自然语言即可，如`"XX今日主力资金净流入"`
- 问**超大单/大单/中单/小单**的买入额、卖出额、净买入额时，query 中**必须明确出现「超大单/大单/中单/小单」**等单型关键词，如`"XX今日超大单净流入"`
- 支持全市场筛选，如`"今日主力资金净流入最多的股票"`、`"今日超大单净买入前10"`

### 龙虎榜
- query 中**必须带有龙虎榜意图词**（龙虎榜/上榜/游资/席位/营业部/机构专用/榜单），否则会被误路由到行情表
- 问个股汇总：`"XX今日龙虎榜买入额"`、`"XX上榜原因"`
- 问席位明细：query 中必须含**席位/营业部/机构专用/买入榜/卖出榜**，如`"XX龙虎榜买入前五席位"`、`"今日机构专用席位净买入的股票"`
- ⚠️ 严禁用不带榜单语境的纯行情问法（如`"换手率最高的股票"`），即使龙虎榜表有该字段

### 板块/行业成分
- 股票→行业：`"XX属于哪个行业"`、`"XX所属板块"`
- 行业→成分股：`"软件开发行业有哪些成分股"`、`"光伏设备板块的股票"`
- 支持多行业并列查询：`"计算机应用和软件开发行业的成分股"`

### 分红
- 直接写年份或时间范围：`"XX 2025年分红方案"`、`"XX近3年分红情况"`
- 支持查具体字段：每股派息、除权除息日、送转比例等

### 财务数据
- 按报告期查询：`"XX 2025年Q3净利润"`、`"XX 2025年年报营收"`
- 查最新财务指标：`"XX最新ROE和资产负债率"`
- 支持多季度对比：`"XX近4个季度净利润"`
- 支持财务指标筛选：`"ROE超过20%的A股有哪些"`
